# Changelog

История изменений TerrariaXDK. Формат — по смыслу, не по датам: важнее «что теперь
работает», чем порядок коммитов. Полный список коммитов — в `git log`.

Автор всех коммитов: `Terraria Agent`.

---

## Основа порта

- **Переименование `TerrariaOGC` → `TerrariaXDK`**: csproj, exe, config, версии в UI и логе.
- **Клавиатура и мышь.** `Terraria/Input/KeyboardMouseInput.cs` собирает синтетический
  `GamePadState` и подмешивает его к физическому, поэтому `Player` и `UI` не пришлось
  переписывать: WASD, Space, Shift, ЛКМ/ПКМ, граппл на средней кнопке, абсолютный
  курсор. Отключается целиком через `[Input] KeyboardMouse=False`.
- **Читы — только в сингле.** `Terraria/Cheats/`, гейт `CheatState.IsAvailable` →
  `Main.NetMode == 0`. Отдельный экран, `F1`, консольные команды `!god/!give/!tp/!time`.
- **Встроенный мультиплеер.** `Terraria/Net/TcpPeer.cs`: хост живёт в процессе игры,
  отдельного серверного EXE не нужно. Handshake с версией протокола и подписью модов,
  пароль с внятной причиной отказа, roster, relay, LAN-дискавери, пинг.
- **Моды.** Обычные .NET-сборки в `Storage/Mods/<Mod>/`, хуки жизненного цикла, свой
  контент, изоляция падений, подпись набора в handshake.
- **Портативный `Storage/`.** Сохранения, логи, моды, конфиги и кэш — рядом с exe,
  ничего в профиль пользователя. Единственный источник путей — `AppPaths`.
- **Headless self-test.** `TerrariaXDK.exe --selftest` не требует GPU и гоняется везде.

## Моды: вылет на рецептах, вылет при подборе, и конвертация без рывков

### Вылет на вкладке крафта

Загрузил моды, открыл «Крафт» — игра упала с `ArgumentOutOfRangeException` из
`BitArray.Get`. Причина: **три таблицы были размечены под ванильную сборку**, а мод-предметы
начинаются с id 20000.

- `Player.itemsFound` — 632 бита. `DiscoveredRecipe` спрашивает «видел ли игрок ингредиент», а
  у мод-рецепта ингредиент — мод-предмет. Теперь таблица размерена от `ModItems.IdLimit` и
  читается через `HasSeenItem` с проверкой границ.
- `Player.recipesNew` — 342 бита, а `UpdateRecipes` пишет флаг для каждого найденного рецепта.
  Второй вылет на том же экране, нашёлся тестом. Размерен как `RecipesFound`.
- `craftingStationsFound` — 135 бит, а таблица станций знала `Blend-O-Matic = 217`. Это не
  только вылет: `AdjTiles` не смотрит на тайлы с id ≥ 135, поэтому такой рецепт **не мог** быть
  скрафчен никогда. `StationId` теперь отказывает всему выше таблицы тайлов, и рецепт остаётся
  добываемым (стандартная ветка «станция — мод-тайл, которого здесь нет»).

Проверено на 11 паках с этой машины: 509 рецептов, `UpdateRecipes()` проходит.

### Вылет при подборе мод-предмета

`ItemTextPool.NewText` → `AffixName()` → `Lang.ItemName(NetID)` → **null** для id вне таблицы
имён → `SpriteFont.MeasureString(null)` → падение. Теперь `ItemAffixName` не возвращает null, а
`UI.MeasureString` на null отдаёт нулевой размер: рисование подписи не должно уметь ронять игру.

### Конвертация: рывок 138 мс в одном кадре

Измерено, а не угадано: в лог добавлены `time: N ms total, slowest file M ms ('файл')`.

- **Таблица имён строится на экране загрузки** (`Main.LoadContent`), а не на первом файле пака.
  Она строится вызовом `Item.SetDefaults` для каждого id — 138 мс, и они приходились ровно
  посреди прогресс-бара.
- **`Job.Step` ограничен временем, а не числом файлов:** копит файлы, пока не истратит 4 мс
  кадра. «4 файла за кадр» было много для больших файлов и мало для маленьких.

После: `267 ms total, slowest file 17 ms` (17 мс — JIT первого файла, один кадр).

### Что ещё терялось, по логу конвертации

| Поле | Сколько | Было | Стало |
|---|---|---|---|
| `stack` | 119 | выброшено как «не число» | это `MaxStack`, применяется |
| `color` | 54 | выброшено как «не число» | `R,G,B,A` → `Item.Colour` |
| `consumable` | 46 | выброшено как «не число» | булево, применяется |
| `noUseGraphic` | 14 | «нет эквивалента» | есть в API (`NoUseGraphic`) |
| `useAmmoName`/`ammoName` | 5 | «нет таблицы» | резолвятся через `ItemLookup` |

Причины отказов перестали врать: `createTileName` — «нужны мод-тайлы», `light` — «предметы
здесь не светятся», `projectile` — «имя снаряда, а таблицы для него нет», `setName` — «это
сет-бонус, то есть код мода» (проверено по исходникам tConfig: `setName` группирует три куска
брони, чтобы вызвать `SetBonus`, и **не** переименовывает предмет). Одна функция `ValueProblem`
решает это для обоих выходов, поэтому Raw-мод и проект не могут разойтись.

Проверено на живых паках: `Omnirs Weapons` +54 поля `color`, `Omnir's Creatures` +119 `stack`;
сгенерированный проект с `.Set("color", ...)` собирается `dotnet build`.

### 5. Что ещё теряется, по логу конвертации

Разобрал остаток по частоте отказов и **проверил каждое поле по исходникам tConfig**, а не по
догадке:

| Поле | Сколько | Почему не переносится |
|---|---|---|
| `createTileName` | 139 | нужны мод-тайлы: предмет ставит свой блок |
| `setName` | 63 | **имя сета брони**, а не предмета: tConfig сравнивает три надетых куска и вызывает `SetBonus` — метод мода |
| `headSlot`/`bodySlot`/`legSlot`, `hasArms` | 21 × 4 | нужен нарисованный спрайт брони на игроке |
| `projectile` | 17 | имя снаряда, а таблицы имён снарядов нет; в этих паках снаряды модовые |
| `light` | 13 | у `Item` нет поля свечения (правка рендера, не конвертера) |
| `pretendType` | 9 | «веди себя как другой предмет» — поведение |

**Важная поправка.** В первой версии этого разбора было написано, что `setName` — это
переименование предмета, и что его надо реализовать реестром имён. Это **неверно**, и проверка
по `refs/T111M/Terraria/Config.cs` это показала:

```csharp
if (armorSets[player.armor[0].name] == armorSets[player.armor[1].name] && ...)
{
    RunMethod(player.armor[1].subclass, "SetBonus", player);
}
```

`setName` нужен ровно для группировки трёх кусков брони, чтобы вызвать код мода. В паках это
видно: `Demon Helmet`, `Demon Greaves`, `Demon Scalemail` все имеют `setName=Demon Armor`.
Без мод-кода сет-бонуса не существует, поэтому честный ответ — отказ с причиной «сет-бонус —
это код». Формулировка «переименовывает предмет» увела бы следующего в сторону реестра имён,
который тут не нужен.

**Сделано:** `useAmmoName`/`ammoName` резолвятся через `ItemLookup` в `UseAmmo`/`Ammo`
(+5 полей у `Omnir's Creatures`).

**Служебные файлы.** `'DropTables': no such item in this build` — это не предмет, а таблица
дропа NPC, лежащая в `Item/`. Теперь узнаётся по имени и объясняется: «это таблица дропа пака,
а не предмет — ей нужны мод-NPC, которых здесь нет».

## Колесо в меню: списки прокручиваются, хотбар не прыгает

Колесо в меню **никто не потреблял**. Счётчик шагов общий с хотбаром, поэтому прокрутка списка
персонажей копилась и затем дёргала хотбар на столько слотов, сколько накрутили, — ровно в момент
входа в мир. А списки длиннее окна мышью вообще нельзя было листать: строки за окном не
нарисованы, кликать не по чему.

Теперь `UI.UpdateMenu` забирает колесо один раз за кадр и раздаёт его тому экрану, который
прокручивается:

| Экран | Что делает колесо |
|---|---|
| выбор персонажа | двигает курсор на строку (список следует за ним) |
| выбор мира / список серверов | `WorldSelect.UpdateCursor(0, -steps)` — тот же путь, что у стика |
| меню модов | `ModMenu.Scroll` — без переноса через край, с ограничением |
| остальные меню | просто гасится, чтобы не утёк в игру |

Два экрана читают колесо **сами** и не должны быть перехвачены: карта (зум) и меню читов
(своя прокрутка). Они исключены явно, с комментарием — иначе одно исправление молча выключило бы
два работающих.

Перенос через край: у стика он остался (стик двигают понемногу), у колеса его нет — прокрутка,
которая с последней строки прыгает на первую, это список, в который нельзя прицелиться.
Покрыто проверкой в `mod menu kinds`.

## Моды: видно, чего сборка не умеет

У реальных паков есть не только предметы: у `Omnir's Creatures` — 146 файлов в `NPC/`, у
`SonnyMod` — 88 в `Tiles/`, плюс `Walls/`, `Buffs/`, `Projectiles/`. Загрузчик читал только
`Item/` и **молча** пропускал остальное. Игрок видел «мод загружен, 111 предметов» и решал, что
146 NPC тоже где-то там.

Теперь неподдерживаемые папки **считаются и называются**:

- в логе: `[Raw] <мод>: 146 file(s) in 'NPC' - this build cannot load that kind of content`;
- в меню модов: у строки `[Raw]` появляется `111 item(s), 242 file(s) unusable, v1.0.0`;
- в `README.md` проекта, который пишет конвертер, — отдельный раздел «What the pack has and this
  build cannot load», с объяснением, что это граница сборки, а не ошибка пака.

Это не «мы научились загружать NPC» — это честность: молча выброшенное выглядит как удачная
конвертация, а названное — как ограничение, которое можно понять.

## Туториал говорит клавишами, подсказки переведены

Две вещи, обе про «игра учит тому, чего у игрока нет».

### Туториал: глифы кнопок заменены на клавиши — во всех пяти языках

Текст туториала — из консольной сборки, и в нём значки кнопок (`\u0081` — триггер, `\u008c` —
A, …). С мышью они читаются как «нажми кнопку, которой у тебя нет». Теперь
`Terraria/TutorialHints.cs` переписывает их.

**Ключ таблицы — шаг + значок, а не фраза.** Два очевидных варианта не работают:

- **по значку** нельзя: одна кнопка делает разное. `[A]` в одном шаге «прыгни», в другом
  «создай это»; стик — «иди» и «между слотами». Подстановка по значку права наполовину;
- **по фразе** работает, но только для одного языка: тот же шаг в пяти переводах сформулирован
  по-разному, и правило, совпавшее с половиной немецкой фразы, её испортит.

Номер шага и значок **одинаковы во всех языках** (переводы построчные — проверено: 46 глифов на
тех же шагах в каждом). Поэтому одна таблица покрывает все пять языков.

| Было | Стало |
|---|---|
| `Press [B] to continue.` | `Press RMB to continue.` |
| `Use [stick] to move around.` | `Use WASD to move around.` |
| `Press [A] to jump.` | `Press Space to jump.` |
| `switch between items with [LB] & [RB]` | `with the mouse wheel` |
| `Press [Y] to open the Inventory Menu.` | `Press I to …` |
| `press [B] to enter or exit the Ingredients area` | `press Q to …` |
| `Press [RT] to switch your Cursor Mode.` | `Press C to …` |
| `press [LB] or [RB] until you switch to Crafting` | `Click the Crafting tab.` |

Пять шагов говорят о кнопке как о кнопке («нажимай A или B, пока не переключишься») — они
заменяются целиком, отдельной строкой на язык. Названия клавиш (`LMB`, `RMB`, `Space`, `WASD`,
`I`, `Q`, `R`, `C`) не переводятся: так пишет строка подсказок внизу экрана, а переведённое
существительное требует правильного падежа в пяти языках («mit der linken Maustaste» против
«mit die linke…»). Слова «мышь», «курсор», «колесо» переведены.

Замена включается по `[Input] KeyboardMouse`: игрок с геймпадом видит прежний текст.
Проверка `tutorial hints` проходит **все 80 шагов × 5 языков** и падает, если остался хоть один
значок или шаг стал пустым.

### Шаг «переключите категорию крафта» засчитывался без переключения
Шаг `CRAFT_CATEGORIES` ждал `IsButtonTriggered(LeftTrigger/RightTrigger)`, а не смены категории.
На клавиатуре левый триггер — это клавиша граппла, поэтому нажатие граппла закрывало шаг, ничего
не переключив; а клик по вкладке мышью, наоборот, ничего не закрывал, потому что клик в инвентаре
не синтезирует триггер.

Теперь шаг смотрит на `UI.TotalCategorySwitches`, который растёт **только** при реальной смене
категории (`UI.IsCategorySwitch`: в диапазоне и не та же самая). Вкладки идут через тот же
`SelectCraftingCategory`, поэтому клик по вкладке считается, а повторный клик по активной — нет.
Правило вынесено в чистую функцию, чтобы его можно было проверить без живого экрана.

### Подсказки управления: один источник и перевод

Подсказки были **английскими литералами в `UI.cs`** — на немецком клиенте инвентарь писал
`LMB - pick / place` по-английски, когда всё остальное было переведено. Теперь это ключи
`ui.hint.*` в `Texts`, и их читает и `AppendPointerHints` (меню), и инвентарь.

Заодно нашлись два экрана, где подсказки **не переключались на мышь вообще** — крафт и жильё
показывали глифы геймпада игроку с мышью. Это тот же баг, что был в инвентаре, в местах, куда
никто не смотрел. Им добавлены свои строки:

- крафт: `LMB - craft    Wheel - scroll    Q - ingredients    R - show all    Esc or Tab - close`
- жильё: `LMB - assign to room    Q - show residents    R - check housing    Esc or Tab - close`

### Q = Y в инвентаре

`Y` — «второе действие на этом экране» — не имел клавиатурной привязки вообще: скрыть/показать
жителей и переключить ингредиенты в крафте были доступны только геймпаду, хотя оба экрана
открываются с клавиатуры. `Q` теперь даёт `Buttons.Y` **только внутри инвентаря** (в создании
персонажа он по-прежнему «категория»), поэтому одна играбельная функция перестала быть
геймпадной.

## Debug-консоль на хосте, спавн по имени

Отладочный шаг из `IDEAS.md` («меню Debug вместо меню Cheats», пункт 1: сначала консольные
команды на сервере). Всё это — только в Debug-сборке.

- **Консоль работает на хосте.** `CheatConsole.CanRunHere` = `CheatState.IsAvailable ||
  DebugHostConsole`, где `DebugHostConsole` — `NetMode == 2` под `#if DEBUG`.
  `CheatState.IsAvailable` **не тронут** (по-прежнему `NetMode == 0`), поэтому правило
  «гейт один» соблюдено, а Release не содержит ни команд, ни флага — проверено поиском строк
  в Release-`exe`.
- **`!spawnnpc <id|имя> [count]`** — спавн по имени или id. Имена ищутся через новый
  `Terraria/NpcLookup.cs` (обратная таблица от `Lang.NpcName`, строится на английском, как
  `ItemLookup`). Имя, существующее только как legacy-отрицательный id, не резолвится: такие
  id не спавнятся.
- **`!invasion <goblins|snow>`** — инвейзия по имени. Пиратов в 0.7.8 нет, и команда говорит
  об этом списком, а не молчит.
- **`!god`, `!noclip`, `!infmana`, `!infbuff` на хосте отказывают с причиной**
  (`SinglePlayerOnly`): их эффект гейтится на одиночную игру, и «включено, но ничего не
  делает» было бы хуже отказа. Мировые команды (время, спавн, инвейзия, метеор, killall)
  работают.
- **`Main.NewText` больше не падает без шрифта.** Он измерял строку через
  `UI.BoldSmallFont`, а это null до загрузки контента — то есть сетевое событие или сообщение
  мода во время старта роняло игру из строки, которая должна была предупредить. Теперь строка
  записывается, а ширина остаётся нулевой.

Проверки: `npc names` (обратная таблица, round-trip каждого имени, числовой id, отказ
legacy-имени, регистронезависимость) и `debug host console` (Debug-only: гейт в трёх режимах,
классификация команд).

## Моды: скачивание с сервера

Сетевая игра требует одинаковый набор модов. Раньше это значило «найди те же моды сам»;
теперь хост может их отдать.

```ini
[Mods]
AllowDownload = False      ; хост: раздавать свои моды
DownloadFromHost = False   ; клиент: принимать моды от хоста
```

Обе выключены по умолчанию: мод — исполняемый код, и отдавать его всем подряд или принимать
от любого сервера — решение, которое принимают осознанно.

- **Список в handshake несёт размер и хеш** (`имя|версия|размер|хеш`). Две последние части
  необязательны, поэтому пир постарше просто не может предложить скачивание. Хеш считается по
  содержимому папки, без `disabled.txt` и без `obj/`/`bin/` — у двух людей, собравших один
  исходник, разные отметки времени, и сравнивать их незачем.
- **Отказ становится предложением:** `ModMismatch` получает два дополнительных поля — «этот
  хост раздаёт» и имена модов, которые можно скачать. Текст отказа не изменился.
- **Скачивание идёт по второму соединению.** Отказанное хост закрывает намеренно, оставлять
  его открытым «чтобы докачать» нельзя. Второе соединение приходит с флагом «я за файлами»;
  хост отвечает на него до проверки совместимости (иначе при `RequireMatchingMods=False` оно
  бы просто присоединилось), но после бана, пароля и вайтлиста. Оно никогда не становится
  игроком: не регистрируется, не видит roster, не получает мир.
- **Новый opcode `OpModFile`** с подкодами: клиент просит мод по имени, хост отвечает
  `Begin` (список файлов, размер, хеш), `Chunk` (путь, смещение, до 32 КиБ), `End` (хеш ещё
  раз). Отдельный opcode, а не `OpMod`: пакеты модов ретранслируются всем и ограничены 64 КиБ,
  а это приватный поток целых файлов.
- **Хост отдаёт только имена из своего загруженного набора** — попросить путь невозможно.
- **Клиент проверяет путь, манифест и хеш на диске.** Файл, которого не было в `Begin`, не
  пишется; `..`, абсолютные пути и двоеточия отвергаются; после приёма содержимое
  пересчитывается по тому, что реально легло в папку.
- **Сборка в `Storage/Mods/.incoming/<Имя>/`**, переезд в `Storage/Mods/<Имя>/` только после
  проверки. Старая папка отодвигается и возвращается при неудаче — игрок остаётся либо со
  старой версией, либо с новой, но не без мода.
- **Перезапуск, а не горячая загрузка:** сборки и id предметов фиксируются при загрузке.
- **Ограничения:** 8 МБ и 512 файлов на мод, 32 КиБ на кадр, отказ при нехватке места.

Проверки: `mod download` (кадры и враждебные кадры, безопасность путей, реальная передача по
сокету, подмена содержимого, установка, отказ) и `mod set requirement` (живой хост:
соединение для скачивания не получает Welcome; отказ предлагает скачивание только когда хост
правда раздаёт).

## Моды: Raw Mod — папка вместо сборки

Просьба игрока: «загрузка модов даже без компиляции — компиляция нужна, но не обязательна».
Теперь так и есть: папка в `Storage/Mods/` с `Item/*.ini` и PNG — это мод.

- **Формат — tConfig-пак.** Ничего переписывать не нужно: пак кладётся в `Storage/Mods/` как
  есть. `RawMod` читает те же секции (`type=-1` для нового предмета, `[Items]`/`[Tiles]`/
  `[Amount]`/`[needWater]` для рецепта) и регистрирует всё в тех же реестрах, что и
  скомпилированный мод, — `ModItems`, `ItemOverrides`, `ModRecipes`.
- **Оба написания рецепта.** Кроме по-секционного (`[Items] Copper Bar=6`), понимается и
  строчный (`[Recipe] Items=6 Copper Bar, 2 Wood`), который пишут `SonnyMod` и `Suggestions`.
  Раньше второе молча пропускалось, и 5 предметов из этих паков существовали без рецепта.
- **Игра их не различает.** Те же id (из общего диапазона, в том же детерминированном
  порядке), та же упакованная текстура на мод, та же подпись набора.
- **Подпись по содержимому.** `имя|версия|raw:<хеш папки>`, где хеш считается по путям и
  байтам. Два игрока с папкой одного имени и разными числами внутри не соединятся. Хеш
  скомпилированных модов не изменился — существующие наборы работают как раньше.
  `disabled.txt` в хеш не входит: включение мода не меняет того, что в нём.
- **Меню:** `[Raw]` рядом с именем, справа — сколько предметов и версия; включается и
  выключается как обычный мод и участвует в порядке загрузки.
- **Отказоустойчивость:** один битый файл не отменяет пак (причина в лог, `[Raw]`), файл без
  спрайта пропускается с причиной, неизвестная станция рецепт не отменяет.
- **Конвертация пака в Raw-мод.** `C` в меню модов (или `--tconfig-raw <пак>`) пишет
  `Storage/Mods/<Имя>/` — `mod.ini`, `Item/*.ini` только с поддерживаемыми полями и спрайты.
  `P` (или `--tconfig-convert`) по-прежнему пишет проект с C#. Переписывание, а не
  копирование: отчёт конвертации описывает мод, а не файл, а повторная конвертация чистит
  `Item/` от исчезнувших предметов (только в папке со строкой-маркером в `mod.ini`).
- **Граница честная:** поведения нет. `OnUse`, свой AI и свой рисунок — это код, для него
  нужна сборка. Пак, который в tConfig использовал код, станет набором данных.

Проверено вживую: `--tconfig-raw SonnyMod` даёт 111 предметов и 84 рецепта, и этот же
результат загружается как мод без правок. Проверка — `--selftest`, `raw mod` (новый предмет с
полями и id, правка существующего через живой `SetDefaults`, оба написания рецепта, отказ файлу
без спрайта, хеш содержимого, выбор папки загрузчиком), `mod menu kinds` (меню пишет Raw-мод,
чистит исчезнувшие предметы, показывает папку как мод) и `tconfig convert`.

## Меню читов: свой экран вместо чужого рендерера

Игрок: «шрифт должен быть как в меню настроек, и список залезает за край». Причина была не в
шрифте и не в высоте строк, а в том, что экран рисовал **общий** рендерер меню: колонка
центрированных слов, фиксированный шаг, четырнадцать строк.

- **Список больше не уезжает за край.** Четырнадцать строк по 38 px от `menuTop = 200` — это
  762 px в кадре 720 px, то есть панель и подпись уходили вниз при любом пресете. Теперь
  высота строки вычисляется из свободного места (`CheatMenu.FitRows`): при 720/960/1440 все
  18 действий видны, а если кадр короче — список прокручивается, сохраняя читаемую высоту.
- **Страниц больше нет.** Четырнадцатая строка была переключателем страниц, поэтому два
  действия из восемнадцати требовали листания при свободном месте.
- **Один визуальный язык с соседними экранами.** Панель, заголовок `BigFont`, строки
  `BoldSmallFont` с подсветкой выбранной, подсказка `SmallFont` — как у `Display`, `HUD`,
  `Network` и `Mods`, которые рисуют себя сами.
- **Мышь, клавиатура и геймпад сразу.** Раньше экран жил на общем навигаторе меню; теперь
  у него свой ввод: стрелки/стик/колесо двигают выбор, клик и `A` выполняют, `Esc` и `B`
  закрывают. Колесо прокручивает список и не копится в хотбар.
- **Закрытие возвращает туда, откуда пришли.** Из паузы — в паузу, после `F1` — в игру.
  Раньше `F1` → `Esc` оставлял игру «на паузе» без единого экрана, а возврат через
  `SetMenu(PAUSE)` дописывал `CHEATS` в историю, и Back в паузе снова открывал читы.
- **Клик не срабатывает дважды.** Экран объявлен обрабатывающим мышь
  (`KeyboardMouseInput.RefreshContext`), иначе клик приходил ещё и как синтетический `A` и
  выполнял подсвеченное действие вместо нажатого.

Проверка — `--selftest`, `cheat menu layout`: раскладка всех трёх пресетов, короткий кадр,
пустая область.

## Мышь в сундуке, крафте и диалоге NPC

Три экрана, которые игрок назвал «всё ещё не работают», и у каждого причина оказалась не там,
где симптом. Подробности — `BUGS.md`; здесь то, что изменилось в поведении.

### Сундук и магазин

- Ячейки сундука, банка и сейфа, а также витрины магазина принимают мышь **всегда**, а не только
  если игрок до этого открывал вкладку «предметы». Раньше вся ветка отсекалась проверкой
  `invMouseLayoutValid`, которая выставляется отрисовкой сетки 10×4 — а на вкладке сундука эта
  сетка не рисуется вовсе.
- **Loot All / Deposit / Quick Stack** стали кликабельными: их прямоугольники пишутся в
  `DrawStorage`, действие идёт через `ActivatePressed()`.
- Клик по пустому месту панели больше не действует на слот, где курсор стоял до этого:
  на кадре клика путь стика отключается через `FrameGate`.

### Крафт

- **Сетка рецептов больше не уезжает под лежащим указателем.** Окно строки
  (`CraftingRecipeWindowX`) отделено от курсора (`CraftingRecipeX`); стик и колесо двигают окно,
  указатель — только курсор внутри него. Раньше это было одно число, и наведение на ячейку 3
  сдвигало строку на 3, из-за чего следующий кадр выбирал уже другой рецепт: сетка крутилась
  сама, несколько ячеек за кадр.
- **Указатель отключает анимацию прокрутки.** Ячейки записываются только при неподвижной сетке,
  поэтому после каждого щелчка колеса крафт был недоступен ~20 кадров.
- **Колесо двигает ровно одну ячейку за кадр** (свободное колесо присылает несколько щелчков в
  одном кадре) и больше не требует, чтобы раздел был переключён на «рецепты».
- **Ячейки ингредиентов** наводятся и показывают количество; раздел «рецепты/ингредиенты»
  выбирается сам по тому, на что показывает указатель.
- Клик по пустому месту панели крафта больше не создаёт выбранный рецепт через синтетический
  `Buttons.A`.

### Диалог NPC и надгробия

- Диалог считается экраном (`UI.ChatOpen`), поэтому левая кнопка в нём больше не превращается в
  `RightTrigger`: клик по слову не взмахивает киркой, а выбирает слово. Правая кнопка закрывает
  разговор.
- Слова-варианты получили запас по краям: прямоугольник был ровно по высоте строчных букв.

## Моды: рецепты и поиск предметов по имени

Сконвертированный предмет без рецепта существует, но добыть его негде — поэтому рецепты были
следующим шагом, и по дороге нашлась вещь хуже.

### Поиск по имени был сломан почти для всех предметов

`Item.SetDefaults(string)` — это не поиск, а `switch` на **две дюжины** старых консольных
предметов (gold/silver/copper инструменты). Любое другое имя молча давало пустой предмет.

Через него шли **все** пути по имени: `Context.Item`, импортёр tConfig, ингредиенты рецептов и
конвертер. То есть они работали только для тех двух дюжин — и тесты этого не видели, потому что
использовали «Copper Shortsword», который как раз в списке.

Теперь есть `Terraria/ItemLookup.cs`: обратная таблица от `Lang.ItemName`, построенная один раз.
Две тонкости, обе найденные прогоном:

- **Отрицательные id тоже нужны.** «Copper Shortsword» — это legacy-предмет: имя есть только у
  отрицательного enum-значения, а `SetDefaults` его не заполняет (это делает `NetDefaults`).
  Таблица обходит и их.
- **Строится на английском.** `Lang.ItemName` отвечает на языке игрока, а файлы модов и паков
  написаны по-английски; немецкий клиент иначе не нашёл бы «Copper Bar» в своих же файлах.
- **Мод-предметы спрашиваются первыми:** их имена живут в реестре, а ванильная таблица
  построена до загрузки модов.

### Рецепты

- `Context.AddRecipe` + `AddIngredient`/`AddStation` по имени; разрешение — после загрузки всех
  модов, чтобы ингредиентом мог быть предмет другого мода.
- Массив рецептов был **фиксированным** (`new Recipe[342]`) и все циклы говорили `342` — мод-рецепт
  не мог попасть в игру вообще. Теперь `Recipe.Capacity` и циклы до `Recipe.NumRecipes`.
- «Открытые рецепты» (`RecipesFound`) — тоже расширены; сейв хранит число байт, поэтому старые
  сохранения читаются и дополняются.
- **Станции — фиксированная английская таблица**, а не `Main.TileNames`: тот перезаполняется
  `Lang.SetLang` на языке игрока, и немецкий клиент искал бы «Anvil», а находил «Amboss».
- Рецепт с неизвестным ингредиентом или станцией **отклоняется с причиной**: рецепт, который
  ничего не производит, хуже отсутствующего.
- Конвертер разбирает секции `[Items]`, `[Tiles]`, `[Amount]`, `[needWater]` — раньше секция
  отбрасывалась при разборе, и **каждый ингредиент** попадал в отчёт как «поле без эквивалента».
  На одном паке это давало 450 предупреждений и прятало настоящие.

Проверено вживую на `Omnirs Weapons`: **114 предметов и 114 рецептов**, проект собирается.

## Моды: новые предметы

Раньше мод мог только **менять** существующий предмет: новый id ломал бы сохранения и сетевой
протокол, поэтому `Context.Item(name)` был единственным способом. Теперь есть
`Context.DefineItem(name, sprite)` — предмет, которого в игре не было.

- **Id — число выше ванильных** (с 20000), потому что `Item.Type` уже ездит по сети и лежит в
  сохранениях. Цена — у обеих сторон должен быть мод, и это ровно то, что теперь требует
  совпадение набора.
- **Id выделяются после загрузки всех модов**, в порядке `(мод, предмет)`. Не в порядке
  регистрации: два игрока с одинаковыми модами, загруженными в разном порядке, иначе
  разъехались бы — и это выглядело бы как «предмет превратился в другой».
- **Спрайты — одна упакованная текстура на мод, с кэшем на диске.** Одна, потому что
  `SpriteBatch` сбрасывает пачку при смене текстуры: отдельные PNG на предмет стоили бы по
  сбросу на каждый предмет в сундуке. Кэш, потому что распаковка сотни PNG на каждом запуске
  заметна. Ключ — имена, размеры и время правки, поэтому правка одного спрайта пересобирает
  только этот мод.
- **Потерянный мод — пустой слот**, а не исключение: сохранение с мод-предметом открывается
  без мода, слот пустой, причина в логе.
- **Конвертер** теперь переносит паки с `type=-1` (новые предметы), копируя PNG рядом с
  проектом. Проверено на живом паке: 114 предметов, проект собирается, игра регистрирует все
  114.
- Заодно исправлен настоящий баг конвертера: float-поля писались без суффикса `f`
  (`Knockback = 4.5;` — это double, проект не собирался), а `--tconfig-convert` терял всё
  после первого пробела в имени пака — то есть у **всех** реальных паков.

## Моды в сети: набор обязан совпадать

Правило было асимметричным и потому неверным: клиент **без модов** принимался любым хостом —
«у меня ничего нет» читалось как «мне всё равно». Это ровно тот случай, который ломается
первым: чистая установка заходила на модифицированный сервер, видела другие характеристики
предметов, и никто ничего не говорил.

- **Сравнение симметричное.** `vanilla` — такая же подпись, как любая другая. Решает **хост**:
  его мир — то, с чем остальные обязаны согласиться. `RequireMatchingMods=False` остаётся
  осознанным выходом.
- **Отказ называет моды.** В handshake поехал список (имя + версия), поэтому сообщение говорит,
  чего не хватает, что лишнее и где версии разошлись — вместо «наборы различаются, ищите сами».
- **Три формы отказа, а не одна общая**: «missing: ; extra: X» с пустым слотом выглядит
  сломанным.
- Список — необязательное поле в конце handshake: хост, который его не знает, просто читает
  меньше и отвечает общей фразой.

## Моды: конвертер не падает на плохом паке

Пак — это чужие данные: обрезанный INI, файл, залоченный редактором, значение «abc» вместо
числа, имя предмета, которого в этой сборке нет. Раньше любое из этого либо валило всю
конвертацию, либо (хуже) давало проект, который не собирается, — и причину приходилось
искать в сообщении компилятора.

- **Отказоустойчивость по файлам.** Один залоченный файл не отменяет остальные: конвертация
  продолжается, а в отчёт попадает `'Copper Axe': cannot read the file (IOException: …)`.
- **Плохое значение отбрасывается с причиной**, а не превращается в код, который не
  компилируется: `field 'pick' has the value 'abc', which is not a number - dropped`.
  Генератор, который пишет `= "abc";`, технически «честен», но проект после него бесполезен.
- **Отчёт в трёх местах**: строка статуса в меню (одно предложение), сгенерированный
  `README.md` (раздел «What failed» и «Why a field was dropped») и
  `Storage/Logs/tconfig-convert.log` (всё, с ротацией по мегабайту).
- **`--tconfig-convert` различает «чисто» и «с потерями»**: ошибки идут в stderr, код возврата
  `3` вместо `0`. Скрипт, который собирает мод, теперь замечает, что половина предметов не
  попала в проект.
- **Ошибка чтения отличается от пустого файла.** `ParseIni` (для игры) намеренно терпит
  нечитаемый файл — иначе один битый пак не давал бы игре загрузиться. Конвертеру нужен
  строгий вариант `ReadIni`, потому что там нечитаемый файл — это ровно то, о чём надо
  сказать.

## Интерфейс: мышь в крафте, жилье и диалогах

Три экрана принимали только геймпад. Причина у всех одна и та же, и она не в отрисовке: **клик
внутри инвентаря не превращается в `Buttons.A`** (инвентарь — не меню, поэтому синтетическая
кнопка не появляется), а обработчики этих экранов проверяли именно кнопку.

- **Крафт.** Сетка рецептов — не сетка: строки это подкатегории, каждая прокручивается
  горизонтально сама, и список анимируется при движении курсора. Поэтому «координата → рецепт»
  не деление на размер ячейки: ячейки записываются **там, где нарисованы**, и только когда
  анимация не идёт. Наведение выбирает рецепт, клик создаёт.
- **Жильё.** Указатель выбирал жителя (прямоугольники из отрисовки), но действие ждало `A`.
- **Диалоги NPC.** Слова-варианты («Shop», «Heal», «Close») теперь кликаются: наведение
  выбирает, клик подтверждает, **правая кнопка закрывает** разговор — в этом экране правой
  кнопке больше нечего значить, а тянуться к Escape хуже.
- **Экипировка** работала и раньше (её подключили в прошлый раз) — проверено по коду: обе ветки
  идут через `ActivatePressed()`.

## Моды: описания предметов и поля, которые терялись

Конвертер отбрасывал 66 полей на одном паке, и самые частые были **описания предметов**
(`toolTip` — 62, `toolTip2` — 55). Предмет без описания — это картинка без объяснения, а паки
пишут описание почти каждому.

- **`ItemToolTips`** — таблица «id → описание», которую `Lang.ToolTip`/`ToolTip2` спрашивают
  первой. Одна таблица на оба пути: импортёр tConfig пишет туда для существующих предметов,
  реестр модов копирует свои определения, когда id уже выделены.
- **`consumable` теперь применяется** (`IsConsumable` в этой сборке есть — раньше поле
  помечалось как неподдерживаемое).
- **`useTurn` → `CanUseTurn`**, **`material`** как синоним `isMaterial`.
- **`createTileName` и `light`** остаются неподдерживаемыми **с причиной**: первый требует
  мод-тайлов, которых нет; второго поля в этой сборке нет вовсе. Молчаливое сопоставление с
  ванильным тайлом поставило бы не тот блок.
- **`ItemOverride` и `ModItem` получили одинаковый набор свойств.** Раньше `width`/`height`
  были только у нового предмета, а `PropertyName` общий — значит правка *существующего*
  предмета с `width` в паке выдавала `ItemOverride.Width = ...` и проект не собирался.
  Тест сверяет **оба** типа, а не один: именно так нашлось `CanUseTurn`.

## Моды: конвертация показывает прогресс

- **`TConfigConverter.Job`** — конвертация разбита на шаги: `Begin`, `Step(maxFiles)`,
  `Finish`. Меню делает по четыре файла за кадр и рисует полосу прогресса с именем пака и
  текущего файла. Не фоновый поток: конвертер зовёт `Item.SetDefaults` и читает общие таблицы
  языка, и «просто, пока не столкнётся с игровым циклом» — не просто.
- **Keep/Delete теперь и с клавиатуры, и с геймпада.** Раньше были только `Y`/`N` и две
  кнопки мышью; на геймпаде вопрос не имел ответа вообще. Теперь ←/→ выбирают, `A` нажимает,
  `B`/`Esc` — «оставить»; выбранная кнопка подсвечена, и наведение мыши двигает тот же выбор.
- **`--tconfig-convert`** использует тот же `Job` целиком, без шагов.

## Исправленные баги, из-за которых что-то не работало вовсе

### Инвентарь: клик не брал предмет

Две причины, обе мои.

**1. Обработчик слота вызывался дважды за кадр.** Он достижим из двух мест — путь мыши и
`PositionInventoryCursor` — и оба выполняются каждый кадр, пока инвентарь открыт. А
`IsButtonTriggered` — это чистая проверка фронта, которая **не потребляется**: значит оба
вызова видели один и тот же клик. Предмет брался и сразу кладывался обратно. На экране это
выглядит как «мышь вообще ничего не делает», а слот, у которого второй вызов был пустым,
казался единственным работающим — ровно то, что и было замечено (работала одна ячейка монет).

Лечится `Terraria/FrameGate.cs`: первое действие в кадре проходит, второе — нет. Проверка
`inventory once per frame`.

**2. Подключён был только раздел ITEMS.** У экипировки, жилья, сундука и магазина свои
переменные курсора и свои обработчики, но `UpdateInventoryMouseHover` выходил сразу, если
активен не ITEMS — указатель туда просто не заходил. Теперь у каждого раздела есть
прямоугольники, записанные **при отрисовке** (тот же урок, что с дробной ячейкой: рисовать и
попадать надо одними числами), и указатель вызывает обработчик того раздела, на который
показывает.

Побочно выяснилось, что `Buttons.A` в инвентаре вообще не синтезируется: `MouseHandledByScreen`
для инвентаря ложен, но клик всё равно не превращается в `A`, потому что инвентарь — не меню.
Поэтому действия теперь идут через `ActivatePressed()` (указатель **или** кнопка), а не через
одну только кнопку.


### Вылет при подборе предмета: `LangOption = 6`

Это мой собственный баг из Custom-языка, и он стоил игроку сессии. Каждая таблица в
`Lang.cs` заканчивается цепочкой `if (LangOption <= 1) … else if (LangOption == 2) …` и
голым `return null` для всего остального. Custom ставил `LangOption = 6`, чтобы «помнить»
выбор — и `ItemName` начал возвращать `null` для **каждого** предмета. Подбор предмета строит
подпись через `AffixName()`, `null` доходил до `SpriteFont.MeasureString`, и игра падала.

Правильная модель: Custom — это не шестой язык, а **английский плюс файл**. `LangOption`
остаётся настоящим (1), файл ложится сверху. Выбор при этом по-прежнему помнится как
`Custom` — это свойство выбора, а не таблиц.

Проверка читает `Language=6` **из файла настроек**, как это делает игрок, и требует, чтобы
встроенный язык остался настоящим, а названия предметов — непустыми.

### Инвентарь выбирал соседний предмет

Отрисовка считала левый край колонки как `(int)(i * cell)`, а хит-тест — как
`(int)(offset / cell)`. Это не обратные операции, когда ячейка дробная, а она дробная всегда:
при 1080p ячейка 104.3 px, колонка 4 начинается на 417, и `417 / 104.3` даёт 3.998 → 3.
**Каждая** граница колонки выбирала слот слева, а клик по первому пикселю слота — соседний.

Теперь обе стороны идут через `Terraria/InventoryGrid.cs`, где `CellIndex` — точная обратная
функция к `CellStart`, а не приблизительная. Проверка исчерпывающая: каждый пиксель сетки на
всех трёх разрешениях.

Заодно мышью стали доступны слоты, которые раньше были недоступны **вообще**: монеты, аммо и
корзина. Хит-тест знал только про сетку 10×4, поэтому клик по ним не делал ничего.

### Три предмета падали в `SetDefaults`

`Familiar Shirt`, `Familiar Pants` и `Familiar Wig` берут цвет из активного игрока:
`UI.CurrentUI.ActivePlayer`. Пока `UI.CurrentUI` не создан (а он создаётся позже, чем
загружаются предметы), это `NullReferenceException` — то есть создание такого предмета
любым путём (конвертер, `!give`, отладочный набор) валило игру. Проверка `item names`
теперь создаёт **каждый** предмет по id, и это ловит.

Это не мелочи: каждый пункт означал, что заявленная функция не работала.

- **Настройки не сохранялись.** `Settings.Set` создаёт только отсутствующие ключи, а им
  же сохранялись изменения, поэтому запись существующего ключа была тихим no-op, и
  `Close()` возвращал старое значение. Не работали: перепривязка клавиш, переключатель
  читов, экран Display. Добавлен `Settings.Update` (перезапись).
- **Настройки экрана были декорацией.** `[Display] ScreenHeight` читался и никуда не
  попадал: `ScreenHeightPtr`/`ScreenMultiplier` никогда не присваивались, разрешение было
  зашито в 960×720, backbuffer — в 640×480.
- **LAN-дискавери не могла работать.** Хост слушал произвольный UDP-порт, а клиенты
  слали на `DiscoveryPort` — хосты в локальной сети были невидимы всегда.
- **Любой реальный сервер в списке убивал процесс.** У `AvailableNetworkSession` каждое
  свойство читало само себя (`get { return CurrentGamerCount; }`) → `StackOverflowException`.
- **В списке серверов вместо числа игроков показывался порт** (`7777/8` у всех).
- **Клиент не подключался вообще**: `EndJoin` не создавал транспорт.
- **Имя игрока терялось**: `NetworkGamer` жёстко ставил `"Stub Gamer"`, и хост объявлял
  его вместо реального gamertag'а.
- **Зум камеры не работал**: значение из файла нигде не применялось, а переход в
  полноэкранный вид сбрасывал его в 1.0; вдобавок `Convert.ToSingle` ронял игру на
  нечисловом значении в файле.
- **Виджеты HUD нельзя было включить**: часы, глубина и компас читались игроком, но
  изменить их было нечем.
- **Имена персонажа и мира нельзя было выбрать**: нажатие Start в создании персонажа
  сразу сохраняло персонажа со сгенерированным именем вида `A3F19C07251015`.
- **Репозиторий не содержал `Terraria/Mods/`.** Правило `.gitignore` было записано как
  `Mods/` без ведущего слэша, а такое правило матчит папку с этим именем на **любой** глубине —
  и вычеркнуло весь Mod API (8 файлов): `Mod`, `ModLoader`, `ModMenu`, `ModEvents`,
  `ModContext`, `ItemOverrides`, `TConfigImporter`, `ModInfoAttribute`. Собиралось только на
  машине, где файлы ещё лежали; в CI падало с `namespace Terraria.Mods does not exist`.
  Теперь runtime-правила привязаны к корню (`/Mods/`, `/Worlds/`, `/Settings.ini` и т. д.),
  файлы добавлены, а `tools/build.ps1` и отдельный шаг CI проверяют, что **ни один** исходник
  не игнорируется, и называют виновника.
- **`skip` в self-test превращался в `FAIL`.** Проверка `world file inspector` сама ловит
  `Exception`, и это же ловило `SkipCheckException`: в чистом клоне без `Content/` не было
  `tutorial.wld`, и CI краснел на ровном месте. Теперь `-skip` доходит до раннера, а
  раннер считает его пропуском, даже если он пришёл завёрнутым.
- **Все экраны, добавленные после Cheats, падали при входе.** `UI.uiPos` был `new Location[40]`,
  а `MenuMode` дорос до 47 значений, и массив индексируется **значением** режима. Поэтому
  Cheats, Keyboard bindings, Mods, Display, Network, HUD и Backups вылетали с
  `IndexOutOfRangeException` в `SetMenu` — и стек не говорил, что причина в размере массива.
  Размер теперь берётся из `MenuMode.NUM_MENUS` (`UI.MenuSlots`), то же для стека
  `prevMenuMode` (было 16), плюс защита от переполнения. Покрыто тестом `menu tables`.
- **Клик в меню срабатывал по прошлому выделению.** `UpdateMenu` обрабатывал нажатие до того,
  как `UpdateMouse` переставлял курсор на пункт под ним, поэтому «Start Game» нажимался не
  мышью, а тем, что было подсвечено кадром раньше. Теперь указатель применяется в начале
  `UpdateMenu`; это же убрало ощущение «меню прилипает к прошлой строке».
- **Виртуальную клавиатуру нельзя было набрать с клавиатуры.** Открытие ставит
  `TextInputActive`, что глушит синтетический геймпад, а больше клавиши никто не читал — поле
  было недоступно именно тем, у кого есть клавиатура. Теперь символы идут через
  `TextInputEXT` (как в чате), Enter подтверждает, Esc отменяет, а по клавишам можно кликать.
  Заодно `space` больше не налезает на `del`: широкая ячейка занимает две колонки, и
  обработка нажатия вынесена в один метод для геймпада, мыши и тестов.
- **Громкость нельзя было менять мышью.** Экран громкости был единственным экраном настроек,
  который игнорировал указатель. Теперь клик по полосе выбирает её и ставит значение туда,
  куда нажали (а не «на шаг от текущего»), и полосу можно тянуть.
- **В инвентаре не кликались вкладки.** Слоты под указателем выбирались, а пять вкладок —
  нет, хотя это первое, что пробует человек с мышью. Прямоугольники вкладок
  запоминаются при отрисовке и проверяются на клик; недоступная вкладка игнорируется, а не
  выбирается. Слоты теперь тоже обрабатываются в любом разделе, а не только в «предметах».
- **Из настроек нельзя было выйти.** Возврат с подэкрана шёл через `SetMenu(SETTINGS)`, а
  `SetMenu` запоминает экран, с которого уходит, — то есть каждый возврат клал в историю сам
  подэкран. «Назад» в настройках после этого снова открывал его же. Теперь подэкраны
  возвращаются через `PrevMenu()`, а `PrevMenu` дополнительно пропускает записи, совпадающие
  с текущим экраном, — так что застрять нельзя даже со старой историей.
- **Мышь «думала по-старому» после смены разрешения.** Три отдельные причины, все про одно:
  - игра рисует в `RenderTarget` внутреннего разрешения и растягивает его на окно, а указатель
    приходит в пикселях окна. Теперь координаты пересчитываются один раз, в
    `KeyboardMouseInput.SetViewport` (при 1080p в окне 720p курсор доставал лишь две трети
    экрана, при 540p не доставал до правого края);
  - хит-тест меню сравнивал `MouseY` с `menuTop` без `ScreenMultiplier`, а рисовало меню с ним:
    на любом пресете кроме 540p кликабельная область уезжала от нарисованной строки;
  - мини-карта считала границы прокрутки без `ScreenMultiplier`, а рисовалась с ним.
- **Область экрана в игровой логике была зашита под 1080p.** Проверки «видно ли игрока»
  (спавн монстров, телепорт городских NPC, падение метеорита) собирались как
  `1920x1080` с отступами 960/540. При 540p такая область больше двух экранов, при 720p —
  просто неверная. Все семь мест сведены к `Main.ScreenAreaAround`.
- **Секции для городских NPC отправлялись не туда.** `sectionX2` и `sectionY2` считались
  из `XYWH.X` (обе), делились на 640 пикселей вместо 3200 (200 тайлов) — клиент получал
  участок мира вокруг нулевой координаты вместо участка с NPC.
- **`<ui.net.password>` вместо строки.** Ключ использовался в экране сети, но не был добавлен
  в таблицу. Добавлен; вдобавок `Texts.Get` теперь пишет в лог `no text for key '…'` (один раз
  на ключ), чтобы следующая такая опечатка не ждала, пока её заметят глазами. Покрыто тестом
  `every text key used`.
- **Мастер-сервер теперь есть в репозитории.** Клиент умел говорить с мастером, но самого
  сервиса не было: адрес по умолчанию работал только если кто-то его поднимал. `tools/MasterServer` —
  консольная программа без зависимостей (`TcpListener`, свой мини-JSON, net40), которая держит
  список миров, отдаёт его по `GET /v1/servers`, принимает `POST /v1/announce` и
  `POST /v1/remove`, показывает страницу со списком и `/health` со счётчиками, и **печатает
  каждый запрос и каждое изменение списка**, чтобы «работает или нет» было видно без клиента.
  Пустой `host` в announce подменяется адресом соединения — единственный правильный ответ за NAT.
  Собственный `--selftest`: 31 проверка (обновление вместо дублирования, истечение по TTL,
  отказы на битый JSON/метод/путь, статистика достижений и рейтинги по сумме колонок). Проверено вживую: игра с `MasterServer=127.0.0.1:17777`
  видит список, а тест `master server live` печатает `1 server(s) listed`.
- **Исправление порта мастера записывается в конфиг.** Раньше `play.dartpower.xyz:7777`
  правился только в памяти, и предупреждение повторялось каждый запуск. Теперь конфиг
  чинится один раз на диске.
- **Start Game не нажимался, если убрать галочки.** В меню режима игры единственная область
  нажатия заканчивалась выше надписи «Start Game», поэтому клик по ней не переводил выбор, а
  активировал **последнюю** строку под курсором — обычно ту галочку, которую только что сняли,
  и она включалась обратно. Теперь каждая строка (включая Start Game) имеет свой прямоугольник,
  записанный при отрисовке.
- **Крах «Begin has been called before calling End».** Несбалансированная пара `Begin`/`End`
  в отрисовке убивала сессию на следующем кадре, с сообщением, которое не говорило, какой
  экран виноват (воспроизводилось на E/I в инвентаре). `SpriteBatch` теперь закрывает
  оставшийся батч сам, `Main.Draw` страхует кадр через `ForceEnd()`, а в лог пишется
  предупреждение со счётчиком — то есть расхождение стало видимым, а не фатальным.
- **Мастер-сервер никогда не опрашивался при настройке без порта.** `TryParseAddress`
  подставлял **игровой** порт 7777 для любого адреса без порта, поэтому
  `MasterServer=play.dartpower.xyz` превращался в `:7777` вместо `:17777`, и список серверов
  всегда был пустым. Адрес теперь разбирается с явным портом по умолчанию, а уже
  сохранённый в конфигах `play.dartpower.xyz:7777` **исправляется** при загрузке (узко:
  только встроенный хост, только игровой порт и только когда порт мастера отличается).
  Добавлена проверка `master server live`: она спрашивает реальный мастер-сервер и пишет
  `skip`, если тот не запущен, — единственная проверка, которая доказывает, что развёрнутый
  сервис говорит на том же протоколе, что и клиент.
- **Меню читов выглядит как остальные экраны**: панель, заголовок, акцентная линия и
  подпись «только одиночная игра» вместо текста поверх замороженного мира.
- **`!debugkit` получил наборы**: `default` / `pvp` / `pve` / `full`, и `!debugsave` —
  сохранить отладочного персонажа обычным сейвом.
- **Виртуальная клавиатура не принимала ввод с клавиатуры.** Она была модальной по замыслу —
  открытие ставит `TextInputActive` и глушит синтетический геймпад, — но при этом **не**
  блокировала остальной UI: клик по клавише одновременно попадал в строку настроек под ней,
  которая заново открывала диалог и сбрасывала текст. Теперь, пока клавиатура открыта,
  `UI.Update` и `ChatInput` не читают ввод, а сама клавиатура понимает Enter (подтвердить),
  Esc (отмена) и клики. Заодно `Main.Update` обновляет состояние геймпада **до** чата и
  клавиатуры: раньше они читали состояние прошлого кадра, и нажатие могло потеряться.

### Отладка (только Debug-сборка)

- **Консоль разработчика**: окно с живым логом и строкой команд, по `F12`. Команды
  складываются в очередь и исполняются на игровом потоке — из UI-потока нельзя трогать
  `Main.*`. Весь файл под `#if DEBUG`: в Release нет ни окна, ни строк, ни команд (проверено
  поиском по exe).
- **`!debugkit`** — тестовый персонаж: 500 HP, 200 маны и набор инструментов, чтобы дойти
  куда угодно (кирка, топор, молот, факелы, блоки, зеркало, крюк, зелья).
- **`!allitems <page>`** — 44 id предметов за раз, 15 страниц на все 632 id. Свободные слоты
  заполняются, занятые не затираются. Идея мира с домом и сундуками по категориям записана
  в `IDEAS.md`.

## Сеть

- Прямое подключение по адресу (`host[:port]`) с клавиатуры или виртуальной клавиатуры.
- Мастер-сервер: HTTP/JSON (`GET /v1/servers`, `POST /v1/announce`, `POST /v1/remove`),
  кэш в `Storage/Cache/servers.json`, таймаут 4 с, экспоненциальный backoff, строгая
  валидация ответа. Публикация своего мира — **по умолчанию выключена**, шлётся фоновым
  потоком, сингл не публикуется никогда.
- Свой JSON-парсер: в net40 нет `System.Text.Json`.
- Список серверов: LAN + онлайн в одном месте, пометки `[pw]`, `[mods]`, `[vN]`,
  реальные игроки/слоты, **пинг в строке** (проба идёт отдельным сокетом и не мешает
  подключению; отказ по паролю/модам считается живым сервером), обновление по `F5` и
  автообновление раз в 20 с с сохранением выбранной строки.
- Избранные серверы (`Storage/Cache/favorites.txt`), видны даже когда мастер и LAN молчат.
- Экран **Настройки → Network**: имя игрока, порт, пароль, публикация, адрес
  мастер-сервера, интервал автообновления. Имя по умолчанию берётся из учётной записи ОС
  (раньше у всех было «Terrarian») и меняется без перезапуска: обновляются и настройка, и
  уже вошедший игрок, которого читает транспорт.
- Тест `host and two clients`: настоящий хост и два клиента на реальных сокетах — roster,
  relay в обе стороны, уведомление о выходе, кик.
- **Команды хоста** в чате: `!who`, `!kick`, `!ban`, `!unban`, `!bans`, `!mute`,
  `!unmute`, `!whisper`, `!motd`, `!rules`, `!say`, `!help`. Раньше `!` в мультиплеере
  проглатывался консолью читов (она только для сингла), и убрать игрока было нечем.
- **Мут** проверяется в relay-цикле хоста, до пересылки: сообщение не доходит ни до
  других клиентов, ни до хоста. Действует на сеанс, точное совпадение по имени.
- **Права и группы** (`Storage/Config/permissions.ini`): `admin`/`mod`/`player` из коробки,
  права флагами (`inspect`, `kick`, `ban`, `mute`, `whisper`, `servertext`, `manage`,
  `build`, `play`). Хост — владелец **из кода**, поэтому опечатка в файле не запирает его;
  удалённый игрок не получает права хоста даже под его именем — имя берётся из соединения,
  а не из текста сообщения. Команды клиентов исполняются на хосте с их правами и не
  пересылаются как чат. Покрыто тестом `permissions`.
- **Защита мира**: право `build`, защита квадрата вокруг спавна и аварийный
  `DisableBuild`. Проверка стоит в приёмнике тайловых пакетов (17/20/34) **до** применения
  и до пересылки, иначе отказ был бы косметическим. Действует на удалённых игроков: правки
  хоста локальны и в сеть не идут. Покрыто тестом `world protection` и живой проверкой в
  `host and two clients` (тайл внутри спавна не меняется, снаружи — меняется).
- **Регионы** (`Storage/Config/regions.txt`): именованные области с группой, которой
  разрешено строить. Без группы — только хост. Пересечения запрещены (иначе ответ зависел
  бы от порядка проверки), обратный прямоугольник нормализуется, координаты вне мира
  отклоняются. Команды `!region list|add|remove|group`. Покрыто тестом `regions`,
  включая проверку, что гейт правок действительно спрашивает регионы.
- **Запрет предметов** (`Storage/Config/items.txt`, `!additem`/`!delitem`/`!items`):
  хост отклоняет синхронизацию инвентаря с запрещённым id и не пересылает её — это
  единственное место, где сервер авторитетен. Имена не принимаются: таблицы «имя → id» в
  этом порте нет, и честнее отказать, чем молча ничего не запретить.
- **`!stats` и `!world`**: игроки, трафик, аптайм; имя мира, размер, спавн, боссы.
- **Профиль хостинга** `Storage/Config/ServerConfig.ini` (необязательный): порт, пароль,
  лимит игроков, MOTD, правила, защита и публикация в одном файле, отдельно от клиентских
  настроек. Если файл есть, его ключи побеждают; пропущенные берутся из `Settings.ini`.
  Сам не создаётся (`!serverconfig create`), меню пишет в тот файл, который в силе.
  Покрыто тестом `server config`.
- **MOTD и правила** отправляются каждому при подключении и хранятся в `[Network]`.
- **Бан-лист** `Storage/Config/banlist.txt` с точным сравнением по имени или IP;
  проверяется в handshake, до регистрации пира.
- **Имя в чате больше не `<Player>`**: раньше локально подставлялась эта заглушка, а
  удалённые игроки получали текст вообще без имени (пакет несёт только строку).

## Мастер-сервер: статистика, достижения и таблицы рекордов

Xbox Live в порте нет, поэтому «сколько игроков получили достижение» и таблицы считает
мастер-сервер.

- **`POST /v1/stats`** — клиент присылает свой прогресс: индексы полученных достижений и
  именованные счётчики (`AirTravel`, `Deaths`, …). Мастер складывает достижения
  объединением и берёт **максимум** по счётчику: счётчик не убывает, поэтому меньшее
  значение — устаревший отчёт, а не исправление.
- **`GET /v1/achievements`** — `{"totalPlayers":N,"counts":[…]}`. Экран достижений пишет
  под каждой строкой «Reported by N of M players». Именно «reported»: числа присланные,
  проверить их без серверного геймплея нельзя.
- **`GET /v1/leaderboard?stats=A,B&limit=50`** — рейтинг по сумме колонок, ровно как
  консольная версия считала `Rating` записи в Xbox Live. Клиент просит все колонки доски
  сразу, поэтому таблица заполняется одним запросом.
- Хранение — `*.stats.json` рядом с файлом списка миров: список живёт две минуты,
  статистика — всегда, и одна очистка не должна уносить обе.
- **Таблицы рекордов больше не врут.** `LeaderboardData` идёт сначала на мастер, а не в
  Xbox Live: `LeaderboardReader` в порте — заглушка, которая придумывает правдоподобные
  имена и числа, поэтому Live-first экран показывал выдуманных игроков. Заглушка осталась
  только для списка достижений (там она перечисляет реальные локальные достижения).
  Запрос идёт фоном: настроенный, но не отвечающий мастер иначе подвешивал бы меню на
  весь таймаут.
- **Кода Xbox Live в таблицах больше нет вообще.** Раньше при неудаче экран показывал
  диалог «The connection to Xbox LIVE has been lost» — при том, что Live тут ни при чём и
  ни к чему не подключается. Теперь: пустой ответ мастера — это пустая таблица с
  пояснением («No rankings yet»), недоступный мастер — строка «Could not read the rankings
  from the master server» прямо на экране, без модального окна. `LeaderboardData` больше не
  содержит ни `LeaderboardReader`, ни пейджинга Live; прокрутка идёт по одной пачке строк.
- `tools/MasterServer` — 31 проверка в `--selftest`, включая счётчики, максимум,
  стабильный порядок при равных значениях и отказы.
- Проверено вживую: игра с `MasterServer=127.0.0.1:17777` печатает
  `stats: 1 player(s), 2 achievement(s) reported, 1 ranked by air travel`.

## Локализация: новый язык без пересборки

Раньше это было невозможно по двум причинам сразу, и обе сняты.

- **Язык.** `Lang` знал ровно пять вариантов, прошитых ветвлениями `LangOption == N`.
  Добавлен шестой — `Custom`: у него нет скомпилированных таблиц, он стартует с английского
  (он же фолбэк для всего, что файл не покрывает) и берёт текст из `Storage/Lang/<code>.txt`.
  Код языка задаётся в `[Display] CustomLanguage` и **фильтруется как имя файла** — иначе
  настройка указывала бы на любой файл на диске.
- **Шрифт.** Глифы были запечены в `Content/Fonts/HD` с зашитым в код списком символов, так что
  кириллица не помещалась. Теперь `Storage/Fonts/<code>.*` — PNG плюс текстовые метрики —
  заменяет атлас для этого языка. Формат читается глазами намеренно: бинарный сэкономил бы
  килобайты и превратил каждую ошибку выравнивания в дамп.
- **Соглашение ячейки** — как у встроенных атласов (`cropping = (0,0,w,h)`,
  `kerning = (0,w,0)`), а не плотная обрезка конвейера XNA. Перепутать — значит рисовать
  каждый глиф не на своём месте; это закреплено тестом, а не оставлено на внимательность.
- **Все три набора или ни одного.** Язык с двумя из трёх шрифтов нарисовал бы меню и оставил
  HUD пустым, поэтому при любой проблеме остаётся встроенный атлас.
- **Генератор — отдельный инструмент** (`tools/FontAtlas`): растеризация TrueType требует
  GDI+ (только Windows), а игра должна работать и на Linux. Игра читает только PNG и текст.
- **`--font-check`** проверяет готовый атлас, не запуская игру: число глифов, размер текстуры,
  сколько из них кириллических, и не вылезает ли какой-нибудь глиф за край картинки.

Проверено вживую на `arial.ttf`: 227 глифов, 66 кириллических, клетки кириллицы содержат
реальные чернила (латинская `A` и кириллическая `А` дают одинаковое число пикселей — так и
должно быть), пробел пустой, `--font-check` принимает файл.

## Интерфейс: карточки серверов вместо пометок в строке

Строка списка была одна, и всё, что нужно знать перед подключением, приклеивалось к имени:
`Bob [pw] [mods] [v3] [relay]`. При двух причинах сразу пометки упирались в счётчик игроков
справа, и читаемым оставалось только имя.

- **Две строки** (`Terraria/ServerCard.cs`): сверху номер, звёздочка избранного и имя, справа
  пинг и заполненность; снизу адрес и пометки. Пометка — слово в предложении, а не скобочный
  тег, приклеенный к имени.
- **Версия называется вместе со своей**: `protocol 4, yours 3`. Просто «v4» не говорит, что
  понимает эта сборка, а разница — весь смысл предупреждения.
- **Релейный сервер не показывает адрес**, которого у него нет, — вместо него `via relay`.
- **Высота карточки вдвое больше строки мира**, поэтому в панель входит вдвое меньше
  серверов. Это отдельное число (`MouseSessionRowHeight`), а не общее с миром: две панели с
  разной высотой строки и одним общим числом — это клик по не тому серверу.
- **Одна функция на обе раскладки** (`WorldSelect.RowAt`). Продублированное целочисленное
  деление в двух местах — ровно то, из-за чего клик попадает на строку выше.
- **Прокрутка серверов** появилась вместе с этим: раньше колесо работало только на списке
  миров, а видимое число бралось из захардкоженных 16. Теперь — из высоты панели.

## Сеть: предел на правки мира

Защита мира отвечала на вопрос «**можно** ли здесь строить», но не на «**как часто**». Изменённый
клиент мог слать пакет 17 тысячи раз в секунду, и каждая правка применялась и
**ретранслировалась всем** — отказ в обслуживании для хоста и остальных игроков. Разрешение
строить для этого не нужно вовсе.

- **Два ведра на игрока** (`Terraria/Net/EditBudget.cs`). Одиночные правки: 200 в запасе,
  60/с. Секции (пакет 20): 8 в запасе, 0.5/с. Числа взяты из честного случая, а не на глаз:
  быстрейшая кирка — 20 тайлов/с, взрыв уносит ~150 сразу.
- **Ведро, а не счётчик в секунду.** Игрок, который десять секунд копал, а потом рванул
  динамит, даёт всплеск; счётчик в секунду отказал бы честному всплеску, а терпеливый читер
  остался бы под лимитом.
- **Отказ ничего не списывает** — иначе клиент опустошал бы себя, попросив слишком много.
- **Двери (пакет 19)** обходили защиту мира полностью: `WorldProtection` их не проверял
  вообще. Теперь они расходуют бюджет. Гейт по правам им намеренно не добавлен — иначе в
  защищённом доме нельзя открыть дверь, в которую надо войти.
- **Права спрашиваются первыми.** Игрок без права строить не должен тратить бюджет на
  выяснение этого на каждом клике; порядок закреплён функцией `WorldProtection.MayEdit` и
  тестом.
- Отказ говорится игроку не чаще раза в 5 с: иначе лимит превращается в флуд чата.
- Бюджет сбрасывается при выходе игрока и при завершении сессии.

## Сеть: пакеты уходят одним куском

Каждый кадр писался отдельным `Write` при `NoDelay=true` — то есть отдельным TCP-сегментом.
Хост на четырёх клиентов делал десятки мелких записей за тик: состояния игроков, правки
тайлов, предметы, NPC. У каждой — 40 байт заголовка и своя история с подтверждениями.

- **`Terraria/Net/PacketBufferer.cs`**: игровые данные копятся и уходят **одной записью на
  соединение за тик**. Сброс — в `TcpPeer.Drain`, на игровом потоке, в том же тике, где данные
  появились, поэтому задержка не растёт.
- **В буфер попадает только `OpData`.** Handshake, roster, reject и ping уходят сразу: это
  кадры, которых кто-то ждёт. Отдельно важное — `Close` сначала сбрасывает буфер, иначе
  причина отказа, положенная в буфер в том же тике, не дошла бы никогда.
- **Порядок сохраняется**: буферизованный кадр, за которым идёт немедленный, выталкивает
  буфер первым.
- **Предел 32 КиБ**: всплеск больше этого — уже не «тик игры», и держать его нет смысла.
- В `NetworkStats` появился счётчик реальных записей: `Describe()` показывает
  `frames N in M write(s)`, так что выигрыш виден в HUD, а не только в коде.

## Сеть: порт открывается через роутер (UPnP)

Порядок хостинга из `IDEAS.md` — UPnP, потом ручной проброс, потом релей — теперь выполняется
целиком: первый шаг был не сделан.

- **Своими сокетами, а не COM.** ПК-версия ходила через `HNetCfg.NATUPnP` (`refs/NATUPNPLib`),
  это Windows-only COM. Здесь SSDP-поиск, чтение описания устройства и SOAP-управление на
  обычных сокетах: `Terraria/Net/UPnP.cs`. Работает и на Linux, ничего не тащит с собой.
- **Хостинг не ждёт роутер.** Всё в фоне (`PortForwarder`): роутер может думать секунды или
  не ответить вообще, а мир должен появиться сразу.
- **Ручной проброс не ломается.** `DeletePortMapping` снимает запись независимо от того, кто
  её создал, поэтому запоминается, создали ли правило мы. Найденный проброс остаётся на месте —
  иначе выход из игры удалял бы то, что игрок настроил руками.
- **718 «порт занят» читается обратно.** Если порт уже проброшен на эту машину — хорошо; если
  на другую — ошибка называет адрес. Это ровно тот случай, когда «вроде всё работает, но никто
  не заходит».
- **Диагностика.** `TerrariaXDK.exe --upnp [порт]` показывает шлюз, внешний адрес и куда
  сейчас ведёт порт. Только чтение.

## Ввод: кнопка, зажатая до того, как игра её заметила

Разбор `mouseLeftRelease` по `refs/T12` дал неожиданный результат: в ПК-версии это не
«отпустил», а «нажал именно в этом кадре» (`Main.Draw` пишет `mouseLeftRelease = !mouseLeft`
в конце кадра, UI читает `mouseLeft && mouseLeftRelease`). У нас этот смысл уже был —
`LeftClicked`. А вот чего не хватало — того, ради чего в ПК-версии стоит `delayUseItem`.

- **Возврат фокуса в окно больше не бьёт мечом.** Клик, которым игрок переключается обратно
  в игру, засчитывался как удар или копание: кнопка уже была зажата, и первый же кадр с
  фокусом видел её нажатой.
- **Закрытие меню с зажатой кнопкой больше не продолжает копать.** Клик по «Resume» (или
  `E`, если ЛКМ была зажата) отдавал ту же кнопку миру.
- Оба случая теперь **ждут отпускания**, а не «одного кадра тишины»: медленный клик — это
  один клик. `AnyMouseButtonDown` / `EffectiveMouseButtons` в `KeyboardMouseInput` — одно
  место, где решается, доходят ли кнопки до игры; `LeftPressed`/`RightPressed`/`LeftClicked`
  соблюдают то же правило, иначе UI нажимал бы кнопку кликом, который игра игнорирует.
- **Крюк на средней кнопке** читал состояние напрямую и был единственной кнопкой, обходившей
  это правило. Теперь он тоже через `EffectiveMouseButtons`.
- Курсор при этом всё равно появляется: проглатывается ввод, а не факт «игрок взялся за
  мышь».

## Моды: правка статов предметов и конвертер tConfig

- **`Context.Item("Copper Shortsword")`** — публичный способ менять статы существующего
  предмета из мода. Раньше это умел только импортёр INI, то есть у мода не было вообще
  никакого доступа к числам предметов. Ручка `ItemOverride` намеренно только для записи:
  правка применяется после `Item.SetDefaults`, поэтому её видят все копии предмета, а
  «прочитать» через неё можно было бы лишь саму правку.
- **`--tconfig-convert <пак>`** — превращает папку `Storage/tConfig/<Пак>` в проект мода в
  `Storage/ModSources/<Имя>/`. Причина, по которой это стоит делать: папка tConfig меняет
  числа на одной машине и **не участвует в подписи набора**, поэтому хост не может её
  потребовать, а мод — может. Числа переносятся вызовами API, а не текстом INI.
- **Ничего не выбрасывается молча.** Неизвестные имена предметов и поля без эквивалента
  перечисляются в сгенерированном `README.md`. Иначе конвертация «прошла успешно» и просто
  не сделала половину.
- **Проверено вживую:** сгенерированный проект собирается `dotnet build`, загрузчик видит
  мод (`mods loaded: 2`), подпись набора меняется. Тест `tconfig convert` дополнительно
  сверяет, что каждому поддерживаемому полю соответствует существующее свойство
  `ItemOverride` — переименование иначе дало бы проект, который не собирается.

## Интерфейс: точечные исправления

- **Меню режима мира** (Online / Invite Only / Start Game) не отзывалось слева. Панель
  рисовалась от `ViewWidth/2 - 190` шириной 380, а кликабельные строки считались от
  другого числа — 320 шириной и на 90 px правее. Теперь и панель, и строки выводятся из
  одного прямоугольника, а клик вне строки больше не активирует «последнюю выбранную»:
  так нажатие на Start Game переключало чекбокс над ним. `Start Game` привязан к нижней
  кромке панели, а не к трём захардкоженным `y` для трёх пресетов.
- **Клик «только по тексту» на экранах со своей отрисовкой.** Таблица хит-прямоугольников
  меню обнулялась только для строк, у которых нет текста, поэтому экран, рисующий себя сам
  (режим мира, выбор мира, …), наследовал прямоугольники предыдущего меню. Из-за этого
  `ClickOutsideMenuEntries` оставался `true`, и каждый клик мимо *тех* прямоугольников
  съедался вместо превращения в `A`: галочки реагировали на подпись, но не на иконку, а
  Start Game — вообще никак. Теперь таблица обнуляется целиком в начале кадра
  (`UI.ClearMenuHits`), и это закреплено проверкой `menu hit table`.
- **Меню читов** рисуется мелким шрифтом, а не большим: строки — длинные фразы
  («Infinite buffs: OFF», «Spawn Eye of Cthulhu») и большим шрифтом не вмещались. Шрифт
  один и тот же для отрисовки, замера и хит-теста, иначе рамка клика разъезжается с
  текстом. *(Позже экран переписан целиком — см. «Меню читов: свой экран вместо чужого
  рендерера»: тот же шрифт, что у `Display`/`HUD`, и высота строк из свободного места.)*
- **Колесо мыши в хотбаре** теперь как на ПК: вниз — следующий слот вправо. Направление
  сверено с `refs/T12` и `refs/T111M` (`selectedItem -= ScrollWheelValue / 120`), а не
  угадано.
- **Виртуальная клавиатура в создании персонажа.** После подтверждения имени Enter оставался нажатым, а экран под клавиатурой видел в нём свежее нажатие «Start» — и снова
  открывал запрос имени. Теперь ввод остаётся выключенным, пока клавиша, закрывшая окно,
  не отпущена (`KeyboardMouseInput.HoldUntilRelease`). Заодно:
  - создание персонажа больше не пропадает за клавиатурой (рисуется и в `NAME_CHARACTER`);
  - неудачное сохранение нового персонажа больше не «проглатывается»: показывается ошибка
    и экран остаётся в создании, а не переходит к списку с персонажем, которого нет на
    диске;
  - исключение из обработчика подтверждения клавиатуры логируется, а не вылетает из
    кадра.
- **Карта больше не роняет игру.** `MiniMap.CreateMapThread` читал `CurrentView` и писал в
  `MapTexture` без всякой связи с тем, что делает игра: закрыть карту во время построения
  или выгрузить мир — и поток писал в освобождённые текстуры либо разыменовывал `null`.
  Это был `NullReferenceException` в фоновом потоке, который роняет процесс мимо
  crash-лога (в логе остаётся только `Crash | Unhandled exception`). Теперь у построения
  есть номер поколения и замок: поток проверяет поколение перед каждой записью, `CreateMap`
  и `DestroyMap` меняют поколение и освобождают текстуры под тем же замком, а тайлы и цвет
  неба снимаются один раз в начале, а не читаются из живого мира на каждом тайле.
- **Диагностика падений.** В `client-crashlog.txt` теперь пишется строка `UI:` — экран,
  секция инвентаря, число строк, выделенная строка и позиция курсора, — плюс IL-смещение
  каждого кадра. Без этого отчёт выглядел как «IndexOutOfRangeException в UpdateMenu», а
  этот метод обслуживает все экраны игры, и по нему нельзя было ничего найти.
- **Пять персонажей — предел, и он теперь не роняет игру.** Переход в создание при занятых
  слотах и сохранение имени проверяют границу массива и сообщают об ошибке вместо
  `IndexOutOfRangeException`; выбор персонажа действует по выбранной строке, а не по
  строке под курсором (это мог быть слот «New» с индексом 5 при пяти персонажах); таблица
  координат паузы расширена — в trial-сборке в неё писался индекс 7 при длине 7.

- **Инвентарь по E/I — одна клавиша, одно действие.** Раньше `E` подставлялся как
  `Buttons.Y`, а `Y` в консольной сборке значит три разные вещи: открыть инвентарь (по
  *отпусканию*), переключить раздел крафта, показать/скрыть список NPC. Одно нажатие делало
  два из них, а закрыть инвентарь той же клавишей было нельзя вообще — только `B` или Esc.
  Теперь `E`/`I` — отдельный запрос (`ConsumeInventoryToggle`), который открывает и
  закрывает инвентарь; `Y` остаётся геймпаду, а в создании персонажа клавиша по-прежнему
  значит «рандомизировать». Закреплено проверкой в `input`.
- **Мышь на экране карты (Tab).** Экран был написан только под геймпад: курсор на стрелках
  обходил PvP, точки команд и список игроков, карта двигалась стиком и триггерами, а мышь
  могла только водить нарисованным указателем. Теперь `Terraria/MapScreenMouse.cs`:
  клик по PvP и по точкам команд (они же подсвечиваются под курсором), клик по строке
  игрока открывает карточку, карта тянется левой кнопкой и масштабируется колесом.
  ЛКМ на этом экране больше не превращается в `A`, иначе клик по галочке срабатывал бы
  дважды — один раз мышью, второй раз консольным курсором. Порядок «точка → команда»
  закреплён проверкой `map screen mouse`.

- **Инвентарь: одно действие за клик и за нажатие.** Три отдельных двойных срабатывания:
  наведение на вкладку переключало раздел, а тот же клик ещё и срабатывал по слоту,
  подсвеченному *до* переключения (клик по «Equipment» мог переложить предмет); обработка
  экрана успевала пройти дважды за кадр (путь мыши и путь стика), поэтому одно нажатие
  бампера переключало две вкладки; вкладки категорий крафта вообще не имели хит-теста.
  Теперь вкладки переключаются кликом и клик поглощают, обработка экрана идёт ровно раз
  за кадр, а категории крафта кликаются (и кнопкой, и мышью — через одну
  `SelectCraftingCategory`, чтобы состояние панели не разъезжалось).
- **Колесо на экране карты** больше не копится: счётчик шагов общий с хотбаром, и после
  закрытия карты он прокручивал хотбар на несколько слотов.

## Инвентарь: быстрый перенос Shift-кликом

- Shift + ЛКМ по слоту отправляет весь стек в открытый контейнер (сундук, свинью-копилку,
  сейф) и обратно. Раньше такого не было вовсе: каждый предмет перекладывался двумя
  кликами — взять в руку, положить.
- Логика вынесена в `Terraria/InventoryTransfer.cs` и покрыта проверкой `inventory transfer`,
  потому что именно она может потерять или удвоить предметы: сначала дозаполняются
  существующие стеки того же предмета, потом берётся первый пустой слот, а недоложенное
  остаётся в источнике (частичный перенос лучше пропажи).
- Клик, который переносит, не ещё и берёт стек в руку: перенос обрабатывается до обычного
  клика, то есть одно действие — один результат.

## Сохранения без лимитов
Персонажи и миры больше не ограничены размером массива.

- **Персонажи.** Файлы читаются маской `player*.plr` — раньше было `player?.plr`, и
  однобуквенный шаблон молча ограничивал список девятью файлами (а массив — пятью).
  Слоты теперь динамические и никогда не сжимаются: номер слота = номер файла, поэтому
  удаление персонажа освобождает слот, а не переставляет остальных. Раньше последний
  персонаж «переезжал» в дырку и менял имя файла — то есть мог перезаписать чужой сейв.
- **Миры.** Читаются `world*.wld` вместо цикла `0..15`; `WorldCap` и вторая страница
  (8 / 11 / 16 строк в зависимости от разрешения) убраны. Список показывает столько
  строк, сколько влезает по высоте, и прокручивается колесом мыши или `LB`/`LT`.
- **Прокрутка.** Общая арифметика в `Terraria/Storage/SaveSlots.cs`: разбор имён файлов,
  свободный слот, окно вокруг курсора, перенос курсора по краям, число видимых строк.
  Покрыта проверкой `save slots` — включая границы (список короче окна, курсор ниже окна,
  прокрутка за конец, дырка от удаления).
- Счётчик `< 10/24 >` появляется только когда список длиннее окна: он должен отвечать на
  вопрос «это всё?», а не занимать место всегда.
- Клавиатура: `E`/`I` в списке персонажей не участвуют, навигация — стрелки/D-Pad, как и
  раньше; курсор обходит все строки, окно едет за ним.

## Отладка (только Debug)

- **`!debugworld`** — строит рядом с игроком комнату: верстак, печь, наковальня, факелы и
  девять сундуков, разложенных по категориям (оружие, броня, аксессуары, инструменты,
  блоки, стены, зелья, материалы, мебель). Содержимое берётся из живой таблицы предметов
  (628 на текущей), поэтому не устаревает и не требует бинаря мира в репозитории.
  Геометрия — десяток чисел, а не шаблон `.wld`.
- **Исправлено: наборы `!debugkit` теряли портовые предметы.** `SetDefaults(int)` для
  отрицательных id (Copper/Gold/Silver инструменты) не заполняет поля вообще — их создаёт
  `NetDefaults`. Наборы вызывали `SetDefaults`, видели `Type <= 0` и молча пропускали эти
  предметы, то есть «default» набор выдавал меньше, чем обещал. Теперь есть `DebugKit.Create`,
  который выбирает нужную таблицу по знаку id.

## Создание персонажа и ввод текста

- **Из создания персонажа нельзя было выйти, а сохранённый персонаж не появлялся в
  списке.** Обе ветки — «Leave without create character? → Yes» и подтверждение имени —
  вызывали `PrevMenu(-2)`. Параметр `PrevMenu` — это **абсолютная глубина** истории, а
  отрицательное значение значит «на шаг назад», так что обе ветки делали один шаг и
  возвращали игрока в редактор персонажа. Сохранение при этом проходило: имя на диске есть,
  а экран «застревал», и Yes в диалоге выхода выглядел как «ничего не делает».
  Теперь есть `UI.ReturnToCharacterSelect()` — возврат именно к списку персонажей
  (с очисткой «нажатой строки» и короткой задержкой ввода, чтобы зажатая клавиша не
  выбрала другого персонажа тем же нажатием). Покрыто тестом `creation flow back`.
- **Виртуальная клавиатура: буквы не набирались, хотя Enter работал.** `StartTextInput`
  вызывался один раз, ошибка проглатывалась — и до конца сессии SDL не присылал символы,
  при этом `Enter` и сетка продолжали работать. Теперь запуск повторяется при каждом
  открытии, ошибка пишется в лог, а если за кадр не пришло ни одного символа от SDL,
  работает резервный разбор нажатий (`VirtualKeyboard.KeyChar`, US-раскладка, Shift).
  Резервный путь молчит, когда SDL символы присылает, поэтому двойного ввода нет.
  Стрелки теперь тоже двигают подсветку сетки (раньше их съедало подавление
  синтетического пада на время ввода). При закрытии клавиатуры в лог пишется, сколько
  символов пришло каким путём. Покрыто тестом `typed characters`.

## Релей: хостинг без проброса портов

- **Мастер умеет перекачивать игру.** `tools/MasterServer/RelayHost.cs`, отдельный порт 17778
  (не HTTP: длинный двунаправленный поток не влезает в парсер списка миров). Хост и клиент
  приходят **исходящими** соединениями, поэтому это работает за CGNAT, мобильным интернетом и
  гостевым Wi-Fi — там, где пробрасывать нечего.
- **Релей не разбирает пакеты.** `TcpPeer` уже режет поток на кадры, так что релею достаточно
  переливать байты: он не зависит от версии протокола и не может подделать ни одну сторону.
  Handshake (версия, подпись модов, пароль, бан-лист) остаётся сквозным.
- **Протокол:** `HOST <token>` → `OK <roomId>`, `JOIN <roomId>` → `WAIT`, `POLL <token>` →
  `JOIN <ticket>…END`, `ACCEPT <ticket>` → склейка пары. Токен 128 бит, тикет одноразовый
  (30 с), лимиты: 64 комнаты, 16 ожидающих, 512 КиБ/с на комнату.
- **Клиент:** `Terraria/Net/RelayLink.cs` — регистрация комнаты, фоновая карусель `POLL` +
  `ACCEPT`, и `Join` для клиента. Хост отдаёт принятый сокет в тот же путь, что и обычный
  `Accept` (`TcpPeer.AdoptRelaySocket`), поэтому второго кода handshake/roster/мира нет.
- **Настройки:** `[Network] AllowRelay` (по умолчанию **выключено**: релей — фолбэк, он стоит
  хопа задержки и чужого трафика), `RelayServer`, `RelayPort`. Объявление в мастере несёт
  `relayRoom`, список помечает такие строки `[relay]`.
- **Проверено:** `--selftest` мастера — 45 проверок, из них 14 про релей (комната живёт и
  умирает вместе с хостом, клиент паркуется, тикет выдаётся один раз, чужой токен не пускается,
  байты идут в обе стороны). В игре три проверки:
  - `relay client` — протокол против независимой заглушки;
  - `relay session` — **настоящая сессия через релей**: хост поднимает `NetworkSession`,
    клиент подключается, зная только адрес релея и комнату, проходит handshake, появляется в
    roster с правильным gamertag, и пакет доходит через тот же сокет. Это то, что раньше
    оставалось непроверенным;
  - `relay live` — против живого релея (`play.dartpower.xyz:17778`): комната, пара, байты.
- **Честно про остаток:** глазами игра через релей не проверялась (нет GPU) — проверены
  сессия, handshake, roster и передача данных, но не отрисовка мира. UPnP по-прежнему не
  реализован, поэтому порядок «прямое подключение → релей» пока означает «прямое, если оно
  настроено вручную».

## Вайтлист: пускать только своих

- **`Storage/Config/whitelist.txt`** — по строке на игрока: имя или IP, `#` — комментарий.
  Сравнение целой строкой и без учёта регистра, как в бан-листе: подстрочное совпадение
  пустило бы «Bobby» за «Bob».
- **`[Network] Whitelist`** (по умолчанию **выключено**) и команда `!whitelist
  on|off|add <имя|ip>|remove|list`. Чтение списка — `Inspect`, изменение — `Ban`: модератор,
  который видит roster, не должен уметь запереть владельца снаружи.
- **Проверка в handshake**, после пароля и до регистрации пира: не прошедший не видит ни
  roster, ни мир. Порядок выбран для игрока: «неверный пароль» — это действие, «вас нет в
  списке» — нет.
- **Пустой список при включённой проверке не пускает никого** — это честное прочтение
  «только эти»; обратное («пусто = все») выглядит как сломанная функция. В лог пишется
  предупреждение, а команда `on` сразу говорит, что список пуст.
- Хоста это не касается: список проверяется на входящих соединениях, сессия хоста через него
  не идёт.
- **Отдельный код отказа** `NotWhitelisted` (7) со своим текстом — клиент показывает причину
  на своём языке, как и остальные отказы.
- Покрыто тестом `whitelist` (комментарии, обрезка пробелов, подстрочное совпадение, off =
  все, пустой = никто, add/remove через файл) и живым отказом в `reject reasons`: настоящий
  хост с включённым списком отвечает `NotWhitelisted`.
- **Не сделано намеренно: личные логины.** Пароль на аккаунт требует хранения паролей (хэш,
  соль, сброс), ещё одного шага в handshake и версии протокола — и решает ту же задачу хуже
  вайтлиста: пароль всё равно можно передать другому.

## Моды
- Менеджер в игре: список, вкл/выкл (`disabled.txt`), ошибки загрузки.
- **Порядок загрузки**: `Storage/Mods/loadorder.txt`, меняется стрелками ←/→ в меню.
- **Сетевые пакеты модов** без регистрации id: отдельный opcode транспорта, id мода
  внутри кадра, лимит 64 КиБ, хост ретранслирует как обычные данные.
  `Context.SendPacket` / `Mod.OnPacket`.
- **События мира**: `OnTilePlaced`, `OnTileKilled`, `OnNpcHurt`, `OnNpcSpawn`,
  `OnNpcDeath`, `OnPlayerHurt`, `OnLiquidChanged`. Один вызов на точку входа, гейт
  `ModEvents.IsActive` — без модов, во время генерации и в меню не стоит ничего. Упавший
  мод отключается, остальные продолжают работать.
  - `OnNpcDeath` отдельно от `OnNpcHurt`: первый — ровно один раз на смерть, второй — на
    каждый удар. Мультиударное оружие иначе сообщало бы «убит» несколько раз.
  - `OnLiquidChanged` — только действие игрока (ведро), не течение: симуляция трогает
    тысячи клеток за кадр, и хук на неё был бы хуком на саму воду.
- Импорт tConfig-паков как правок существующих предметов.
- Пример мода `Examples/ExampleMod` со всеми хуками.

## Настройки и экран

- Экран `Display`: размер окна, полноэкранный режим, внутреннее разрешение
  540p/720p/1080p, счётчик FPS, VSync, лимит кадров. Окно применяется сразу,
  внутреннее разрешение — после перезапуска (экран об этом пишет).
- Профили `Default` / `TV` / `Handheld`: один пункт выставляет всё разом. Определение по
  значениям, поэтому ручная правка честно даёт `Custom`.
- Экран `HUD`: зум камеры (применяется сразу), сброс зума, «всегда включённые» часы,
  глубина и компас без соответствующих аксессуаров, предупреждение о хардмоде. Значения
  жили в файле и не были доступны в игре; зум к тому же парсился через `Convert.ToSingle`
  (падение на мусоре) и нигде не применялся, а переход в полноэкранный вид сбрасывал его
  в 1.0.
- **Имена персонажа и мира** вводятся с клавиатуры или виртуальной клавиатуры
  (`NameRules` + `NamePrompt`). Раньше они генерировались и сразу сохранялись: имя
  выбрать было нельзя, а сгенерированное оставалось навсегда.
- **Виртуальная клавиатура** (`VirtualKeyboard`): буквы/цифры/символы, D-Pad и стики,
  `Y` — символы, `X` — регистр, `Start` — подтвердить, `Back` — отмена. Используется
  для чата, имён, адреса сервера и пароля хоста.
- **Колесо мыши** листает то, что в фокусе: хотбар в игре и список рецептов в крафте.
  Раньше оно было замаплено на бамперы, поэтому в инвентаре переключало раздел, а не
  рецепты. Учтены дробные дельты (тачпады) и ограничено накопление.
- **Выбор языка**: `Настройки → Display → Language` — Auto / English / Deutsch / Italiano /
  Français / Español. Применяется сразу (переключение перезаполняет все строковые таблицы,
  поэтому меняется и само меню) и сохраняется в `[Display] Language`. Пять переводов в
  `Lang.cs` были всегда, но выбирать их было нечем: язык брался только из культуры ОС.
- **Правки перевода без пересборки**: `Storage/Lang/<code>.txt` читается поверх встроенных
  строк, шаблон генерируется командой `TerrariaXDK.exe --lang-export de` (без окна и без
  GPU). Файл может быть частичным. Ошибка в файле не ломает интерфейс: пустое значение не
  стирает метку, индекс вне диапазона и неизвестная секция объясняются в логе. Повторный
  экспорт сохраняет уже переведённое. См. `docs/LOCALIZATION.md`.
- **Текст наших фич тоже переводится**: ответы читов, всех команд хоста, модерации и
  `!serverconfig` собраны в `Terraria/Texts.cs` (`chat.*`) и лежат в секции `[Texts]` того
  же файла. Раньше немецкий игрок видел немецкий мир с английской консолью: эти строки
  появились в порте, а `Lang.cs` содержит только оригинальные. Подстановки `{0}` заполняются
  своим мини-форматтером — лишняя фигурная скобка в переводе не роняет игру, а пропущенный
  аргумент остаётся видимым, чтобы опечатка не выглядела как «Kicked .».
- **Экраны тоже переведены**: `Display`, `HUD`, `Mods`, `Network`, `Cheats`, бэкапы,
  переназначение клавиш, строки меню настроек и заголовки окон ошибок. Названия клавиш
  строятся из имени действия, поэтому новое действие без текста видно сразу — и на экране
  (`<ui.key.newaction>`), и в тесте по имени действия. Комментарии `Settings.ini` остались
  английскими намеренно: файл читают при разборе проблем.
- **Список серверов больше не сравнивает текст с «timeout»**: строка «не отвечает»
  переведена, а цвет выбирается по отдельному признаку, иначе покраснение работало бы
  только в английском.
- **Проверка движения в мультиплеере (анти-чит).** Позиция приходит пакетом 13, и хост верил
  всему — включая ретрансляцию остальным. Теперь есть бюджет перемещения: ёмкость 512 px,
  пополнение 700 px/с (выше терминальной скорости падения 600 px/с), из бюджета вычитается
  фактическая дистанция. Лимит на пакет не годится: пакеты приходят неравномерно, и при
  подвисании несколько тиков едут одним пакетом. Проверка стоит **до** применения и до
  пересылки. Три режима: `Off`, `Observe` (по умолчанию — собирает доказательства, ничего не
  блокирует), `Enforce` (отказывает). Возрождение и крюк освобождены; `NaN`, `∞` и позиция за
  миром отклоняются даже в `Observe`. По умолчанию наблюдение, потому что одно ложное
  срабатывание замораживает честного игрока для всех — это дороже пропущенного чита.
  `!anticheat off|observe|enforce`. См. `docs/ANTICHEAT.md`.
- **Текстуры можно заменить без пересборки.** Раньше — только `.xnb`, то есть инструменты
  MonoGame и Windows-машина. Теперь PNG в `Storage/Textures/` с тем же относительным путём:
  `Storage/Textures/Images/_sheetTiles.png` заменяет `Content/Images/_sheetTiles.xnb`.
  Свой декодер PNG (все типы цвета, битности 1–16, пять фильтров, `tRNS`; Adam7 отвергается
  с причиной) — потому что `System.Drawing` это GDI+ и его нельзя вызвать из headless-теста.
  Битый, интерлейсенный или неподдерживаемый файл не роняет игру: грузится встроенная
  текстура, причина уходит в лог. RGB при конверсии умножается на альфу — контент-пайплайн
  XNA хранит текстуры премультиплицированными, и прямая альфа дала бы светлые края.
  См. `docs/TEXTURES.md`.
- **Один спрайт атласа можно заменить отдельно.** `Storage/Textures/Atlases/_sheetTiles/TILES_0.png`
  заменяет только этот регион листа — не нужно вырезать 2048² PNG и не сдвинуть ни одного
  пикселя. Имена берутся из enum атласа (`Enum.GetNames`), поэтому второго списка нет, а
  опечатка попадает в лог с именем файла. Заплатка ложится на уже загруженный лист (чтение →
  наложение → загрузка), поэтому не нужен render target и не трогается `SpriteBatch` во время
  загрузки. Наложение — чистый CPU и проверяется без видеокарты; тест дополнительно сверяет,
  что имена и `Source` не разошлись (219 плиток, 1489 спрайтов), иначе замена после разрыва
  попадала бы в чужой слот. См. `docs/TEXTURES.md`.
- **Пути не зависят от разделителя там, где это важно.** Аудит контента сравнивал манифест
  (через `\`) с листингом каталога, который отдаёт разделитель ОС: на Windows сходилось, на
  Linux вся игра считалась бы «осиротевшей» — 277 МБ мусора. Обе стороны теперь приводятся к
  `/` (`Terraria/Portability.cs`), и это проверяется на настоящем каталоге тестом
  `portable paths`. См. `docs/PORTABILITY.md`.
- **Collectors Edition больше не привязан к реестру.** Флаг читался только из
  `HKCU\Software\Terraria`, а исключение глушилось — вне Windows значение всегда было
  `False`, и `Main.cs` держал `using Microsoft.Win32` ради одной строки. Теперь есть ключ
  `[Game] CollectorsEdition` (Auto/True/False), реестр остаётся источником для Auto и только
  на Windows. В лог добавлена строка `Platform :`.
- **Причину отказа в подключении выбирает клиент, а не сервер.** `OpReject` теперь несёт код
  (`неверный пароль`, `сервер полон`, `бан`, `кик`, `другой набор модов`, `версия протокола`)
  и поля к нему, а фразу клиент составляет на своём языке. Раньше сервер присылал английское
  предложение, и немецкий игрок читал причину по-английски — это было единственное место в
  языке, которое нельзя было починить на стороне клиента. Протокол поднят до версии 3; старый
  текстовый отказ клиент по-прежнему показывает как есть.
- **Переназначение всех клавиш** с сохранением в `[Keys]`.
- Автосейв, громкости, тексты предметов, читы, моды, сеть — всё в игре, не в файле.

## Мир и данные

- **Диагностика миров**: `WorldFileInspector` разбирает `.wld` без загрузки и объясняет
  отказ — обрезанный сейв (с номером байта), повреждённый заголовок, слишком короткий файл
  или мир ПК-версии. Раньше все три случая выглядели одинаково: «не удалось загрузить».
  Поддержаны обе раскладки — старая (≤46) и текущая (47–49). См. `docs/WORLD_FORMAT.md`.

- **Датированные бэкапы миров** в `Storage/Backups/` после каждого сохранения, с лимитом
  на мир и минимальным интервалом, чтобы автосейв не забивал папку.
- **Восстановление из бэкапа в игре**: `B` в списке миров открывает список копий
  выбранного мира. Раньше единственным способом было вручную копировать файл, поэтому
  копии существовали, но не использовались. Перед перезаписью текущий сейв сохраняется
  как `.prerestore` — ошибочное восстановление тоже обратимо.
- **Прошлый лог сохраняется**: `terraria-debug.log` затирался при каждом запуске, то есть
  перезапуск после падения уничтожал ровно тот лог, который был нужен. Теперь предыдущий
  запуск остаётся как `terraria-debug.prev.log`, а крашлог и раньше дописывался.
- Стриминг музыки через OGG: около 80 МБ резидентной памяти освобождено.
- Настраиваемая загрузка: задачи по одной на кадр, честный прогресс, исходный вид полоски.

## Инструменты

- **CI** (`.github/workflows/build.yml`): на каждый push/PR — сборка Release с
  `-warnaserror` и `--selftest`, лог артефактом. Стало возможным после того, как тест
  перестал зависеть от `Content/` и нативных DLL: он не инициализирует `FNAPlatform`, а
  контентные проверки без ассетов рапортуют `skip`, а не `FAIL`.
- `tools/build.ps1` — сборка + `--selftest` + упаковка портативной папки (`-Pack`,
  `-Zip`) одной командой. Сам подкладывает нативные DLL и делает junction на `Content`.
- `tools/XnbToPng` — извлечение PNG из `.xnb`: свой LZX-декодер, DXT1/3/5, 565-форматы,
  свап байтов для Xbox-текстур. На текущем `Content/`: 194 текстуры, 0 ошибок.
  См. `docs/XNB.md`.

## Что осталось

Крупные и рискованные пункты, которые требуют либо железа, либо отдельного рефакторинга:

- **Dedicated-хост** без окна: упирается в статический `Main` и загрузку контента.
- **Разделение `Main.cs`** (3996 строк) на ввод, рендер, сеть и звук — постепенно.
  Звук уже вынесен в `Terraria/Audio/`; остальное требует стенда с OpenGL.
- **TrueType-шрифты и вынос `Lang.cs` в файлы** (мультиязычность). Атласы шрифтов
  кастомные, с ручным кернингом, поэтому это отдельная большая работа.
- **Совместимость форматов миров с ПК-версией.** Миры ПК опознаются и объясняются
  (`WorldFileInspector`), но не конвертируются: раскладка ПК гейтится по версиям, и без
  образцов реализация была бы непроверяемой.
- **Кроссплатформенность** (Linux/ARM): мешают `Microsoft.Win32.Registry` и пути
  `StorageDevice`.
- **Визуальная проверка** 720p/1080p и всего, что рисуется: на машине разработки нет
  OpenGL 2.1, поэтому проверено только логикой и тестами.
