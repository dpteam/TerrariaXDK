# AGENTS.md

Правила для всех, кто меняет код TerrariaXDK — людей и агентов.

Автор коммитов: **Terraria Agent**.

---

## 1. Базовая картина

TerrariaXDK — это **консольная** кодовая база Terraria (Xbox 360 v0.7.8), посаженная на
FNA/SDL2. Она принципиально отличается от ПК-версии:

| | TerrariaXDK (этот репозиторий) | ПК-версия (`refs/`) |
|---|---|---|
| Ввод | `GamePadState`, виртуальный курсор | `KeyboardState`/`MouseState` напрямую |
| Экран | 540p/720p/1080p, `ScreenMultiplier`, safe area | произвольное окно, зум 1.0–2.0 |
| Игроки | до 4 локальных (split-screen), `UIInstance[4]` | один игрок |
| Сеть | `NetworkSession` (Xbox Live → теперь TCP) | `Netplay` на `TcpListener`/`TcpClient` |
| Контент | атласы `_sheetSprites`/`_sheetTiles`, `Fonts/HD` | россыпь PNG + `Content/Images` |
| UI | полностью свой (`UI.cs`), без ImGui/меню ПК | свои экраны |

**Нельзя** копировать код из `refs/` один-в-один — он не соберётся. Из `refs/` берутся
**идеи и алгоритмы**, реализация пишется под консольную модель.

## 2. Архитектурные правила

1. **Игровую логику не переписываем.** Основной поток (Update/Draw, `WorldGen`, `NPC`,
   `Projectile`) трогаем только точечно, с сохранением поведения.
2. **Новые возможности — отдельными файлами и папками.**
   `Terraria/Input/`, `Terraria/Cheats/`, `Terraria/Net/`, `Terraria/Mods/`,
   `Terraria/Storage/`, `Terraria/Headless/`, `Terraria/Audio/`. Ничего общего не
   сваливаем в `Main.cs`.

### Что уже вынесено из `Main.cs`

`Main.cs` (~3700 строк) исторически смешивает ввод, рендер, сеть, генерацию мира и звук.
Разделение идёт по одному куску за раз, и правило простое: **перенос должен быть
побайтовым, а не «улучшением по дороге»**.

| Что | Куда | Как сделано |
|---|---|---|
| звук (`PlaySound`) | `Terraria/Audio/SoundPlayer.cs` | тело перенесено дословно (`using static Terraria.Main`), в `Main` остался однострочный враппер, поэтому ~300 вызовов не менялись |
| пулы и музыка | `Terraria/Audio/` | `SfxInstancePool`, `SoundManager`, `MusicEntry` |

Врапперы в `Main` **обязательны**: они держат точку вызова, а перенос без переименований
позволяет проверить себя диффом (`Compare-Object` по телу метода), а не глазами.

Оставшееся (рендер, ввод, сеть, генерация) выносить сложнее: там либо нужен
`GraphicsDevice`, либо статический `Main`, и проверить это без GPU нельзя. Поэтому
следующие куски берутся только вместе с возможностью запустить игру.
3. **Только аддитивные правки в существующих файлах.** По возможности — одна-две строки
   вызова в уже существующую точку (`Main.Update`, `Player.Hurt`, `UI.UpdateGamePad`).
   Если правка большая — выносим в helper и вызываем из одной строки.
4. **Всё новое — под фича-флагом**, если оно меняет поведение. Флаги живут в `Settings.ini`
   (`Main` парсит их в конструкторе) и в статическом классе фичи (например
   `KeyboardMouseInput.Enabled`).
5. **Сингл vs мультиплеер.** Читы (и вообще любые локальные читерские вещи) обязаны
   проверяться через `CheatState.IsAvailable` → `Main.NetMode == 0`. Никаких «протащу
   проверку по месту» — гейт один.
6. **Сеть — только через `IPeerTransport`.** Не вызывайте `Lidgren` из игрового кода.
   Всё, что нужно игре, уже умеет `NetworkSession`. Модам — `ModNet` (отдельный opcode
   транспорта), а не `NetMessage`: его id зафиксированы консольным протоколом.
   **По проводу не ходит текст, который увидит игрок.** Причина отказа, ошибка, статус —
   это код плюс поля (`RejectReason`), текст подбирает получатель на своём языке. Иначе
   язык собеседника решает, что прочитает игрок. Меняете формат кадра — поднимите
   `TcpPeer.ProtocolVersion` и опишите изменение в `docs/MULTIPLAYER.md`.
   **Данные клиента проверяются на хосте, до применения и до пересылки.** Проверка после
   применения оставляет у хоста состояние, которому он не доверяет, и всё равно рассылает
   его. Движение — `AntiCheat` (пакет 13), правки тайлов — `WorldProtection`, предметы —
   `ItemRestrictions`. Для нового типа клиентских данных отказ обязан стоять там же.
   **Анти-чит по умолчанию наблюдает** (`AntiCheatMode.Observe`): ложное срабатывание
   замораживает честного игрока для всех, и отличить «читерит» от «не повезло» в момент
   срабатывания нельзя. `Enforce` — осознанный выбор хоста, а не дефолт.
7. **Потоки.** Игровая логика — один поток. Всё, что приходит из сети, кладём в очередь
   и применяем на игровом потоке (`TcpPeer.Drain` вызывается из `NetworkSession.Update`).
   Из фонового потока **нельзя** трогать `Main.*`, `UI.*`, мир и игроков. Исключение —
   `Mod.OnPacket`: он вызывается на сетевом потоке и обязан только складывать данные.

## 3. Стиль кода

- Язык — C#, `net40`, `LangVersion=latest`, `PlatformTarget=x64`, `AllowUnsafeBlocks`.
- **Код только для разработчика — под `#if DEBUG`, а не под флагом в настройках.**
  Отладочные команды, консоль и наборы предметов живут в файлах, целиком обёрнутых в
  `#if DEBUG` (`Terraria/Cheats/DebugKit.cs`, `Terraria/Cheats/DebugConsole.cs`). Причина:
  читерская возможность, которая «есть, но выключена», всё равно есть и включается правкой
  файла. Препроцессор гарантирует, что в Release её нет ни в каком виде — ни кода, ни строк.
  Проверка после сборки: в Release-`exe` не должно находиться строк вроде `allitems`.
  Тесты для такого кода тоже под `#if DEBUG`, иначе Release-сборка не соберётся.
- Скобки — новая строка (как в существующих файлах).
- Отступ — **табы**.
- Приватные поля — `_camelCase`, статические — `PascalCase`.
- `var` не используем (в декомпилированном коде его нет; единообразие важнее).
- Комментарии — по-английски, по делу: объясняют **почему**, а не «что».
- Публичные типы фич — `public`; внутренности — `internal`.
- Файл на тип/фичу, не «God class».

## 4. Обязательные проверки перед коммитом

```powershell
tools\build.ps1                                   # Release: build + self-test одним шагом
tools\build.ps1 -Configuration Debug              # Debug: то же плюс отладочные проверки
# или вручную:
dotnet build TerrariaXDK.csproj -v q --nologo     # 0 ошибок
# staging: Content + нативные DLL рядом с exe
.\bin\Debug\net40\TerrariaXDK.exe --selftest       # 0 failed
```

**Число проверок зависит от конфигурации, и это нормально:** Debug-сборка содержит
`debug kit` и `debug console` (они под `#if DEBUG`), поэтому даёт 83 проверки, Release — 81.
`tools\build.ps1` по умолчанию собирает Release, то есть CI проверяет 81; отладочный код
проверяется только в Debug-конфигурации. Не «исправляйте» это, добавляя отладочные проверки в
Release: их там быть не должно.

Код возврата `--selftest` — через `Start-Process -PassThru`:

```powershell
$p = Start-Process .\bin\Debug\net40\TerrariaXDK.exe -ArgumentList --selftest -Wait -PassThru
$p.ExitCode                                       # 0 = всё прошло
```

`cmd /c "... & echo %ERRORLEVEL%"` для этого **не годится**: `%ERRORLEVEL%` подставляется
при разборе всей строки, до запуска, поэтому всегда печатается старый код (обычно 0).

`--selftest` **не** требует GPU и не требует ни `Content/`, ни нативных DLL: он намеренно
не инициализирует `FNAPlatform` (`AppPaths.Headless`). Поэтому он гоняется везде, включая
CI и чистый клон.

- Если вы добавили загрузку нового ассета — добавьте его в манифест
  `Headless/SelfTest.cs`, иначе тест «content orphans» начнёт ругаться (и это правильно).
- Проверка, которая без чего-то не имеет смысла, обязана вызвать `Skip("причина")`, а не
  `Fail`. Пропуск виден в итоговой строке (`Skipped: N`) и в списке — он не засчитывается
  как успех. Если эта проверка ловит `Exception` у себя внутри, первой обязана стоять
  ветка `catch (SkipCheckException) { throw; }`: иначе `Skip` превращается в `FAIL`.
- Сборка должна проходить и с `-warnaserror`: новое предупреждение — это дефект, а не шум.

Полноценный запуск игры возможен только там, где есть OpenGL 2.1+. Если графики нет,
это фиксируется строкой `NoSuitableGraphicsDeviceException` в `terraria-debug.log`.

## 5. Content

- Игра грузит **только** `.xnb` (плюс `Content/Worlds/tutorial.wld` и `Content/ExtMusic/*.wav`).
- **Замена контента идёт через `Storage/`, а не правкой `Content/`.** Текстура — PNG в
  `Storage/Textures/` с тем же относительным путём (`Textures/Images/_sheetTiles.png`),
  текст — `Storage/Lang/<code>.txt`. `Content/` остаётся неизменяемым: обновление игры его
  затрёт, а пользовательская правка должна пережить обновление.
- Все `Content.Load<Texture2D>(...)` проходят через `TextureContentManager`
  (`Game.Content` подменяется в конструкторе `Main`). Поэтому новую текстуру **не нужно**
  нигде регистрировать в списке «поддерживает замену» — она получает её автоматически.
  Не обходите это, вызывая `new ContentManager(...)` где-то ещё.
- **Один спрайт в атласе адресуется своим именем из enum** (`_sheetTiles.ID.TILES_0` →
  `Atlases/_sheetTiles/TILES_0.png`). Второго списка имён нет и заводить его нельзя: имя
  берётся из `Enum.GetNames`, поэтому опечатка попадает в лог, а не теряется. Если меняете
  `Source`/`ID` в атласе — помните, что порядок массива и enum обязаны совпадать, это
  проверяет тест `atlas overrides`.
- `Content/` — только чтение. Ничего не пишите туда, и не возвращайте `.dds`/`.png`.
- `.dds`/`.png` в `Content/` — сырьё, игрой не читаются.
- Перед удалением любого файла: искать в коде **без расширения** (`_sheetSprites`,
  `Achievement07`, `Background_12`), учитывая, что имена могут собираться конкатенацией
  (`"Achievement" + k.ToString("00")`, `"Fonts/HD/" + name + "_PS3"`).
- Удалённое — в `_RemovedContent/` с сохранением структуры, и фиксируется в
  `docs/CONTENT_AUDIT.md`.
- После любой правки `Content/` — прогнать `--selftest`.

## 6. Storage (что и куда пишется)

**Правило: игра не пишет ничего рядом с exe и ничего в профиль пользователя.**
Всё изменяемое идёт в `Storage/` рядом с exe — это делает установку портативной.

| Что | Куда | Кто пишет |
|---|---|---|
| Персонажи | `Storage/Saves/Characters/PlayerN/*.plr` | `StorageContainer` |
| Миры | `Storage/Saves/Worlds/PlayerN/*.wld` | `StorageContainer` |
| Настройки игрока | `Storage/Saves/Settings/PlayerN/config.dat` | `StorageContainer` |
| Настройки игры | `Storage/Config/Settings.ini` | `Settings` |
| Бан-лист | `Storage/Config/banlist.txt` | `BanList` |
| Права и группы | `Storage/Config/permissions.ini` | `Permissions` |
| Регионы | `Storage/Config/regions.txt` | `Regions` |
| Запрещённые предметы | `Storage/Config/items.txt` | `ItemRestrictions` |
| Профиль хостинга (опционально) | `Storage/Config/ServerConfig.ini` | `ServerConfig` |
| Моды | `Storage/Mods/<Mod>/<Mod>.dll` | `ModLoader` |
| Отладочный лог | `Storage/Logs/terraria-debug.log` (прошлый запуск — `terraria-debug.prev.log`) | `Program` |
| Крашлог | `Storage/Logs/client-crashlog.txt` | `Program` |
| Резервные копии | `Storage/Backups/<мир>_<дата>.wld` | `WorldBackups` |
| Кэш сети | `Storage/Cache/servers.json`, `favorites.txt` | `MasterServerClient`, `ServerFavorites` |
| Кэш | `Storage/Cache/` (свободная папка: скретч, будущие кэши) | `AppPaths` |
| Правки переводов | `Storage/Lang/<code>.txt` (EN/DE/IT/FR/ES) | `LangOverrides` |
| Замена текстур | `Storage/Textures/<путь как в Content>.png` | `TextureContentManager`, `TextureOverrides` |
| Замена одного спрайта | `Storage/Textures/Atlases/<атлас>/<SPRITE>.png` | `AtlasOverrides`, `AtlasComposer` |
- **Никогда не хардкодьте пути.** Единственный источник — `Terraria/Storage/AppPaths.cs`.
  Нужна новая папка — добавьте свойство туда и в `EnsureDirectories()`.
- **Видимый игроку текст — не литерал.** Текст, который видит игрок, идёт через
  `Terraria/Texts.cs` (`Texts.Get("chat.host.kick.done")`, `Texts.Format(...)`), а не
  строкой в коде: иначе он останется английским при любом выбранном языке. Ключ — имя
  (`chat.<область>.<что>`), а не английская фраза. Логи (`Program.Log*`), имена файлов и
  служебные строки переводить не нужно.
- **Чужой файл — только чтение.** `Settings.Close()` перезаписывает файл из памяти: для
  `Settings.ini` это правильно, для файла, который правит игрок (`Storage/Lang/*.txt`), —
  нет. Прочитали и закрыли → `Discard()`, а не `Close()`.

### Экран: рисуешь и проверяешь одними и теми же числами

Правило, которое стоило нескольких багов подряд: **если координата умножается на
`Main.ScreenMultiplier` при отрисовке, она обязана умножаться и в хит-тесте.** Проще — считать
обе стороны одной функцией.

Из этого следуют три конкретные вещи:

- **Указатель приходит в пикселях окна, а игра живёт во внутреннем разрешении.** Пересчёт делает
  `KeyboardMouseInput.SetViewport` (вызывается каждый кадр из `Main.Update`), поэтому
  `MouseX`/`MouseY` уже в координатах `ResolutionWidth/Height`. Не пересчитывайте их повторно.
- **Не пишите `1920`, `1080`, `960`, `540` как «размер экрана»**, если имеется в виду именно
  экран: это пресеты консоли. Для «области, которую видит игрок» есть
  `Main.ScreenAreaAround(x, y)` и `Main.ResolutionWidth/Height`.
- **Но не всякое большое число — про экран.** Расстояния спавна в `NPC.cs`, радиус подбора
  предметов в `Item.cs`, зона Стены Плоти в `Player.cs` — это игровые дистанции, они
  фиксированы в оригинале и **не должны** масштабироваться. Отличить просто: если число
  описывает «сколько видно» — масштабировать; если «насколько далеко» — нет.

### Модальные окна

`VirtualKeyboard` — модальное: пока оно открыто, `UI.Update` и `ChatInput.Update` выходят
сразу, иначе клик по клавише попадает ещё и в экран под ней, а Enter подтверждает дважды.
Если появится ещё одно модальное окно, оно обязано делать то же самое — иначе это не модальное
окно, а наложение.

### Пути и платформа

- **Путь, который сравнивается или показывается, — переносимый (`/`); путь, который
  открывается, — нативный.** Не наоборот. Обратный порядок даёт проверку, которая проходит
  на машине автора и врёт везде остальных: именно так аудит контента на Linux объявил бы
  мусором все 277 МБ. Помощники — `Terraria/Portability.cs` (`Portable`, `Native`,
  `Combine`, `RelativeTo`), не изобретайте `.Replace('\\','/')` по месту.
- **Windows-only API — только под `Portability.IsWindows`,** а не «в try/catch, там
  разберёмся»: проглоченное исключение превращает флаг функции в тихое `false` и выглядит
  как «функция не работает», а не «платформа другая». Реестр — единственное такое место
  (`CollectorsEdition`). Полный список того, что ещё мешает сборке вне Windows, —
  `docs/PORTABILITY.md`.
- `StorageDevice.RootOverride` выставляется в `AppPaths.EnsureDirectories()`; не
  переопределяйте его в другом месте.
- `Storage/` не коммитится. `Content/` — тоже (он рядом, вне git).
- `Settings.ini` рядом с exe — это **шаблон**: при первом запуске копируется в
  `Storage/Config/`. Не читайте его напрямую.

## 7. Git

- Репозиторий — этот корень; код и вся документация в нём.
  `Content/`, `refs/`, `_RemovedContent/` лежат рядом с корнем, но в него не входят.
- Автор: `Terraria Agent <terraria-agent@localhost>`.
- **Правило в `.gitignore` без ведущего слэша матчит на любой глубине.** `Mods/` вычеркнуло
  `Terraria/Mods/` целиком, и проект собирался только там, где файлы ещё были на диске; в CI
  это выглядело как «namespace Terraria.Mods не существует». Всё, что относится к данным
  времени выполнения (`/Mods/`, `/Worlds/`, `/Players/`, `/Settings.ini`, `/Logs/`), пишется
  с ведущим `/`. После правки `.gitignore` проверяйте `git status --ignored` на `*.cs`.
  `tools/build.ps1` и CI-шаг «Check that no source file is ignored» делают это сами и
  называют файл.
- **Не проверяйте «собирается ли» только у себя.** Свежий клон — единственная честная
  проверка: `git worktree add ../verify HEAD` и сборка там. Всё, что не закоммичено,
  отсутствует, и это ровно то, что увидит CI.
- Сообщения — Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
  Английский, императив, до 72 символов в заголовке.
- Один коммит = одна законченная мысль. Сборка должна быть зелёной на каждом коммите.

## 8. Что делать при сомнении

1. Прочитать `IDEAS.md` — возможно, вопрос уже решён или отклонён с причиной.
2. Посмотреть `CHANGELOG.md` — что уже работает и какие баги были (чтобы не «чинить»
   заново то, что чинили, и не возвращать старое поведение).
3. Посмотреть `docs/REFS_DIFF.md` — как это было устроено в ПК-версии.
4. Если решение меняет архитектуру — сначала записать идею в `IDEAS.md`, потом код.
5. Не «улучшать» попутно декомпилированный код: переименования ради красоты ломают
   соответствие с `refs/` и усложняют диффы.
