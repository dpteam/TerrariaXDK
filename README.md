# TerrariaXDK

Порт **Terraria (Xbox 360, v0.7.8)** на десктоп через [FNA](https://fna-xna.github.io/) /
SDL2, с добавленными клавиатурой-мышью, встроенным мультиплеером, читами для сингла и
поддержкой модов.

Проект вырос из **TerrariaOGC v1.03** (переименован в TerrariaXDK) и использует исходники
консольной версии как основу, а сборки ПК-версии из `refs/` — как источник идей.

---

## Что умеет

| Возможность | Где | Статус |
|---|---|---|
| Клавиатура + мышь | `Terraria/Input/KeyboardMouseInput.cs` | работает |
| Чит-меню (сингл) | `Terraria/Cheats/` | работает |
| Чат и консольные команды (`!god`, `!give`…) | `Terraria/Input/ChatInput.cs` | работает (сингл) |
| Мультиплеер без серверного EXE | `Terraria/Net/` | работает (LAN + IP) |
| Моды (сингл и онлайн) | `Terraria/Mods/` | API + загрузчик |
| Headless self-test | `TerrariaXDK.exe --selftest` | работает |
| Виртуальная клавиатура для геймпада | — | в планах, см. `IDEAS.md` |

## Сборка

Нужен .NET SDK (проверено на 9.0) и Windows для запуска (FNA-нативные DLL — Win64).

```powershell
tools\build.ps1                 # сборка + --selftest
tools\build.ps1 -Pack           # + dist/TerrariaXDK/ — готовая портативная папка
tools\build.ps1 -Pack -Zip      # + dist/TerrariaXDK-<дата>.zip
```

Скрипт сам подкладывает к exe нативные DLL (из `bin\Debug\net40`, `native\win64` или
переменной `TXDK_NATIVE_DIR`) и делает junction на `Content`, поэтому `--selftest`
работает в любой конфигурации.

Вручную то же самое:

```powershell
dotnet build TerrariaXDK.csproj -c Release
```

Результат: `bin/Release/net40/TerrariaXDK.exe` (net40, x64).

### Что положить рядом с exe

Игра ищет контент и нативные библиотеки рядом с исполняемым файлом:

```
TerrariaXDK.exe
TerrariaXDK.exe.config
Content/            <- копия Content из корня проекта (рядом с этой папкой)
FAudio.dll
FNA3D.dll
libtheorafile.dll
SDL2.dll
Settings.ini        <- опционально: шаблон настроек
```

Всё остальное игра создаёт сама в `Storage/`:

```
Storage/
  Saves/Characters/Player1/player1.plr    персонажи
  Saves/Worlds/Player1/world1.wld         миры
  Saves/Settings/Player1/config.dat       настройки игрока
  Config/Settings.ini                     настройки игры
  Mods/<Mod>/<Mod>.dll                    моды
  Logs/terraria-debug.log                 отладочный лог (текущий запуск)
  Logs/terraria-debug.prev.log            лог предыдущего запуска (для разбора падений)
  Logs/client-crashlog.txt                крашлог (дописывается, не затирается)
  Backups/world1_20260101_120000.wld    резервные копии миров
  Cache/                                  кэш сети и прочее
  Lang/de.txt                             правки перевода (см. «Переводы»)
  Textures/Images/_sheetTiles.png         замена текстуры без пересборки (см. «Текстуры»)
  Textures/Atlases/_sheetTiles/TILES_0.png  замена одного спрайта в атласе
```

Установка **портативна**: чтобы перенести игру на другую машину или флешку,
достаточно скопировать всю папку целиком — сохранения, моды и настройки поедут с ней.

Быстрый способ собрать рабочий каталог:

```powershell
dotnet build TerrariaXDK.csproj
$dst = "bin\Debug\net40"
Copy-Item -Recurse -Force ..\Content $dst
Copy-Item -Force ..\Settings.ini,..\FAudio.dll,..\FNA3D.dll,..\libtheorafile.dll,..\SDL2.dll $dst
```

Требуется **OpenGL 2.1+**. На машинах без GPU (или в RDP/VM с `GDI Generic`)
игра не запустится — для таких случаев есть `--selftest` (см. ниже).

Планируется отказаться от этих четырёх DLL совсем — свой бэкенд поверх системных API
(`user32`, `d3d9`, `dsound`), что заодно вернёт совместимость с Windows XP+. Это
последний этап и отдельная большая работа: см. `ROADMAP.md`, этап 8, и `IDEAS.md`.

### Управление (клавиатура)

| Клавиша | Действие |
|---|---|
| `W A S D` | движение |
| `Space` | прыжок |
| `Shift` | двойной прыжок |
| `Enter` | чат (в сингле — консоль команд, у хоста — `!kick`/`!ban`/…) |
| `E` / `I` | инвентарь |
| `Esc` | пауза / назад |
| `Tab` / `M` | карта |
| `F1` | чит-меню (только сингл) |
| `F` | полный экран |
| `+` / `-` | зум |
| ЛКМ | использовать предмет |
| ПКМ | поставить блок / взаимодействовать |
| Средняя кнопка / `V` | граппл |
| `Q` / `R` | бросить предмет |
| `H` / `J` / `B` | быстрое лечение / мана / баффы |
| `1`…`9`, `0` | выбрать слот хотбара |
| Колесо | листает хотбар; в инвентаре — рецепты крафта |
| Стрелки | навигация по меню |
| `C` | переключить smart cursor |

В списке серверов: `F5` (или `LB`) — обновить, `F` — сохранить сервер в избранное
(такие помечены `*`), `D` (или `RB`) — подключиться по адресу вручную.

В списке миров: `B` (или `RS`) — восстановить мир из резервной копии. Окно показывает
копии выбранного мира (дата, время, размер), `Space`/ЛКМ — восстановить (второй раз
подтвердить), `R` — перечитать список, `Esc` — назад. Текущее сохранение перед
восстановлением сохраняется как `<файл>.prerestore`, так что ошибочное восстановление
тоже обратимо.

Команды хоста (в чате, только в мультиплеере): `!who`, `!kick <игрок> [причина]`,
`!ban <игрок|ip>`, `!unban <игрок|ip>`, `!bans`, `!mute`/`!unmute <игрок>`,
`!whisper <игрок> <текст>`, `!motd [текст]`, `!rules [текст]`, `!say <текст>`,
`!op <игрок> [группа]`, `!deop <игрок>`, `!groups`, `!region ...`, `!additem`/`!delitem`/`!items`,
`!stats`, `!world`, `!serverconfig [show|create]`, `!help`.Бан-лист — `Storage/Config/banlist.txt`; MOTD и правила — `[Network] Motd`/`Rules`;
права — `Storage/Config/permissions.ini` (группы `admin`/`mod`/`player` есть из коробки,
хост всегда владелец); регионы — `Storage/Config/regions.txt`.

**Регионы** — именованные защищённые области: `!region add <имя> [радиус]` создаёт
область вокруг хоста, `!region group <имя> <группа>` разрешает в ней строить этой группе
(без группы — только хост), `!region list` / `!region remove <имя>`. Пересекающиеся
области отклоняются: иначе ответ на «можно мне тут строить» зависел бы от порядка проверки.

Защита мира — **Настройки → Network**: радиус защиты спавна (0/8/16/24/32/48 тайлов) и
аварийный выключатель «запретить строительство». Плюс право `build` в группах: у кого его
нет, тот не может менять мир. Правила действуют на удалённых игроков; хост может всё.

Все клавиши переназначаются: **Настройки → Keyboard bindings**. Значения пишутся
в `Storage/Config/Settings.ini`, секция `[Keys]`; там же их можно править вручную.

Размер окна, полноэкранный режим и внутреннее разрешение (540p / 720p / 1080p) —
**Настройки → Display**. Окно применяется сразу, внутреннее разрешение — после перезапуска.

Там же есть готовые профили (`Default` / `TV` / `Handheld`) — они выставляют все три
параметра разом, чтобы не собирать вручную заведомо неверную комбинацию. Если поменять
любое поле руками, экран честно показывает `Custom`.

| Профиль | Окно | Режим | Внутреннее |
|---|---|---|---|
| `Default` | 1280×720 | полный экран | 540p |
| `TV` | 1920×1080 | полный экран | 720p |
| `Handheld` | 1280×720 | в окне | 540p |

Там же — счётчик FPS, VSync, ограничение кадров и **язык** (Auto / English / Deutsch /
Italiano / Français / Español). Язык применяется сразу: переключение перезаполняет все
строковые таблицы, поэтому меняется и само меню — это же и есть проверка, что оно работает.

Ограничение кадров сильнее VSync: с явным лимитом игра идёт фиксированным шагом,
а VSync отключается, иначе два разных лимита дают рывки. На Anbernic лимит 30–60
заметно снижает нагрев.

**Настройки → HUD** — зум камеры (1.00x…2.00x, применяется сразу), сброс зума, три
виджета: часы, глубина, компас — «всегда включены», без соответствующего аксессуара,
и предупреждение о переходе в хардмод. Зум в игре по-прежнему меняется на `+` / `-`
(или триггерами на паузе), и это то же самое значение, что и в меню.

Список серверов обновляется сам раз в 20 секунд, пока открыт
(`[Network] AutoRefreshSeconds`, `0` выключает).

Сеть настраивается в игре — **Настройки → Network**: имя игрока (то, что видят другие),
порт, пароль хоста, публикация в списке серверов, адрес мастер-сервера и интервал
автообновления. Порт и пароль применяются к следующему хостингу; всё это пишется в
`[Network]` (и `[Game] Gamertag` для имени) в `Settings.ini`.

Мышь и геймпад работают одновременно: пока вы двигаете мышь, курсор абсолютный,
через ~3 секунды простоя управление возвращается стику.

## Настройки

`Settings.ini` создаётся при первом запуске в `Storage/Config/` (рядом с exe можно
положить шаблон — он будет скопирован туда) и дополняется новыми ключами:

```ini
[Game]
Gamertag=Terrarian
TrialActive=False
PSMode=False
UnlockAllRecipes=False
CollectorsEdition=Auto   ; Auto = спросить реестр Windows, True/False = решить здесь

[Display]
ScreenHeight=0          ; внутреннее разрешение: 0 = 540p, 1 = 720p, 2 = 1080p
Language=0              ; 0 = как в системе, 1 English, 2 Deutsch, 3 Italiano, 4 Français, 5 Español
Width=1280              ; размер окна
Height=720
ShowFPS=False
VSync=True              ; вертикальная синхронизация
FpsLimit=0              ; лимит кадров: 0 = без лимита, иначе 30/60/120/144/240
StartFullscreen=True
ZoomLevel=0             ; zoom: 0 = default, 1 = closest
AlwaysOnWatch=False   ; clock without a watch
AlwaysOnDepth=False     ; depth without a depth meter
AlwaysOnCompass=False   ; position without a compass

[Additions]
HardmodeAlert=False

[Input]
KeyboardMouse=True      ; выключить, чтобы получить оригинальное поведение

[Cheats]
Enabled=True            ; чит-меню доступно только в сингле

[Network]
Port=7777
Password=               ; пусто = пускать всех
JoinAddress=            ; "host:port" для быстрого подключения
Motd=                  ; приветствие, которое видят подключившиеся
Rules=                 ; правила, которые видят подключившиеся
ProtectSpawnRadius=16  ; тайлов вокруг спавна, которые нельзя менять удалённым игрокам
AntiCheat=Observe       ; проверка движения: Off / Observe (только лог) / Enforce (отказывать)
DisableBuild=False     ; True = мир меняет только хост
MasterServer=play.dartpower.xyz:17777   ; через запятую можно резервные
PublishToMaster=False   ; публиковать свой мир в списке серверов
PublicAddress=          ; пусто = мастер берёт адрес из соединения
AutoRefreshSeconds=20   ; автообновление списка серверов (0 = выключить)

[Mods]
Enabled=True
RequireMatchingMods=True

[Backups]
Enabled=True            ; датированные копии мира в Storage/Backups
Keep=10                 ; сколько копий хранить на мир (0 = выключить)
MinMinutes=15           ; интервал между копиями (0 = при каждом сохранении)
```

Избранные серверы лежат в `Storage/Cache/favorites.txt` (по одному `host:port` в строке)
и показываются в общем списке с пометкой `*`.

### Переводы

В игре пять языков, и правятся они без пересборки: файл `Storage/Lang/<code>.txt` читается
поверх встроенных строк.

```
TerrariaXDK.exe --lang-export de     # создать Storage/Lang/de.txt с текущими строками
```

Дальше правите нужные строки и запускаете игру; удалённая строка означает «взять
встроенный текст», так что файл может быть частичным. Повторный экспорт уже переведённое
не стирает — он только добавляет новые ключи.

В файле две части: строки самой игры (ключи — индексы, например `[MenuText] 6 = …`) и
**строки наших фич** — экраны и меню, ответы читов и команд хоста, модерация (`[Texts]`,
ключи по имени, например `chat.host.kick.done = …`). Формат, подстановки `{0}`, правило про
пробел после `=` и разбор ошибок — в [`docs/LOCALIZATION.md`](docs/LOCALIZATION.md).

### Текстуры

Заменить текстуру можно без пересборки контента: PNG-файл в `Storage/Textures/`, путь
повторяет дерево контента.

```
Content/Images/_sheetTiles.xnb   ->   Storage/Textures/Images/_sheetTiles.png
Content/UI/ProgressBar.xnb       ->   Storage/Textures/UI/ProgressBar.png
```

Поддержаны все типы цвета PNG (1/2/4/8/16 бит, палитра, `tRNS`), но **не** Adam7-интерлейсинг.
Если файл битый, интерлейсенный или не PNG — игра пишет причину в лог и берёт встроенную
текстуру, а не падает. Подробности, включая премультипликацию альфы, —
в [`docs/TEXTURES.md`](docs/TEXTURES.md).

Один спрайт внутри атласа заменяется отдельно, без вырезания всего листа:

```
Storage/Textures/Atlases/_sheetTiles/TILES_0.png
Storage/Textures/Atlases/_sheetSprites/ARM_BONE.png
```

Имя файла — имя спрайта из `_sheetTiles.ID` / `_sheetSprites.ID`. Размер может отличаться от
слота: картинка масштабируется и это отмечается в логе.

### Debug-сборка

В Debug рядом с игрой есть инструменты разработчика, которых **нет** в Release (весь код под
`#if DEBUG`, проверено поиском по exe):

- **`F12`** — консоль: живой лог плюс строка команд. Команды выполняются на игровом потоке,
  поэтому из окна можно спокойно звать `!help`, `!anticheat`, `!debugkit`.
- **`!debugkit`** — тестовый персонаж: 500 HP, 200 маны, кирка/топор/молот, факелы, блоки,
  зеркало, крюк, зелья.
- **`!allitems <page>`** — 44 id предметов за раз, 15 страниц на все 632 id.

Собирать: `dotnet build TerrariaXDK.csproj` (по умолчанию Debug) или
`tools\build.ps1 -Configuration Debug`.

## Headless self-test
```powershell
.\TerrariaXDK.exe --selftest
```

Проверяет без графики (62 проверки в Release, 64 в Debug):
1. **пути** — что всё пишется в `Storage/` рядом с exe, а не в профиль пользователя;
2. **манифест контента** — что каждый `Content.Load(...)` путь реально существует;
3. **осиротевшие файлы** — что в `Content/` нет ничего, что игра не грузит;
4. **framing** — сериализация кадров протокола;
5. **tcp loopback** — реальное TCP-соединение с handshake и обменом данными;
6. **хост + два клиента** — две настоящие сессии через хост: roster с реальными
   gamertag'ами, relay пакетов в обе стороны, уведомление о выходе;
7. **конфиг сети** — парсинг `host:port`, `[::1]`, отказ на некорректных портах;
8. **моды** — загрузка, детерминированность подписи, отказ чужой подписи, порядок
   загрузки, пакеты модов и события мира (`OnTilePlaced`/`OnTileKilled`/`OnNpcHurt`);
9. **читы** — что они включены в сингле и недоступны в мультиплеере;
10. **мастер-сервер** — запросы к локальному HTTP-стабу, кэш, backoff, отказ битым и
    огромным ответам, разбор списка адресов;
11. **список серверов** — разбор LAN-ответов, пометки пароля/модов, избранные адреса,
    логика автообновления;
12. **настройки** — чтение и **запись** (это был баг: сохранение ничего не меняло),
    профили экрана, зум и виджеты HUD, валидация значений;
13. **ввод** — виртуальная клавиатура и правила имён персонажа/мира: длина, пустое имя,
    управляющие символы, сохранение текста при отказе, отмена; имя игрока в сети;
14. **колесо и индексы** — шаги колеса (включая дробные дельты) и перенос индекса через
    край для хотбара и рецептов;
15. **логи** — что прошлый запуск сохраняется как `.prev`, а пустой лог не трогается;
16. **бэкапы миров** — датированные копии, их ротация и восстановление: отказ для
    файла, который не является миром, и `.prerestore` перед перезаписью;
17. **команды хоста** — разбор `!kick`/`!ban`/… (что считается командой, а что обычным
    сообщением) и отказ не-хосту;
18. **бан-лист** — точное совпадение по имени/IP, отказ подстрочным, переживание reload;
19. **модерация** — мут на сеанс, MOTD/правила и совместимость пакета чата с игрой;
20. **права** — группы, хост-владелец из кода, невозможность получить его права по имени, репорт об опечатках в файле;
21. **защита мира** — границы квадрата спавна, приоритет хоста, троттлинг отказов;
22. **регионы** — нормализация прямоугольника, запрет пересечений, закрытость по умолчанию, и то, что гейт правок их действительно спрашивает;
23. **запрет предметов** — разбор id, отказ именам без таблицы, round-trip файла и живой отказ синхронизации;
24. **профиль хостинга** — приоритет над `Settings.ini`, частичный файл, пустой пароль,
    мусор в значениях;
25. **пинг серверов** — живой сервер отвечает, отказ считается живым, мёртвый порт даёт
    `timeout`, а неизмеренный — ничего;
26. **звук** — `PlaySound` ничего не делает при выключенном звуке и молчит, а не падает,
    когда аудио не загрузилось (пулы `null`);
27. **формат миров** — `WorldFileInspector` разбирает настоящий `tutorial.wld` ровно до
    последнего байта, отличает обрезанный сейв от ПК-мира и от мусора;
28. **язык** — каждый из пяти переводов реально заполняет строковые таблицы, тексты
    отличаются, `Auto` разрешается в конкретный язык, а мусор в файле даёт `Auto`;
29. **правки перевода** — файл из `Storage/Lang/` применяется поверх встроенных строк:
    индекс вне диапазона не сдвигает соседние строки, пустое значение не стирает метку,
    неизвестная секция попадает в список проблем, ведущий пробел сохраняется, а
    сгенерированный шаблон читается обратно без потерь;
30. **текст наших фич** — экраны, ответы читов и команд хоста из `[Texts]`: подстановки
    `{0}` заполняются, пропущенная остаётся видимой (иначе выходит «Kicked .»), посторонние
    фигурные скобки не ломают строку, опечатка в ключе называется в логе по имени, при
    смене языка переводы не остаются с прошлого, повторный экспорт сохраняет уже
    переведённое, а у каждого переназначаемого действия есть название;
31. **причины отказа** — `OpReject` несёт код и поля: все коды round-trip'ятся, каждый
    имеет текст, причина кика не теряется, старый текстовый отказ читается как «неизвестно»
    и не путается с кодом, обрезанный и пустой payload не роняют сетевой поток, а
    **настоящий** хост на живой сокет отвечает кодом «неверный пароль»;
32. **переносимость путей** — конверсия в обе стороны, `RelativeTo` с разными разделителями,
    защита от ложного префикса (`Content` ≠ `Contents`), настоящий каталог с настоящими
    файлами: здоровое дерево даёт ноль замечаний, посторонний `.dds` — ровно одно, а
    манифест с обратными слэшами продолжает совпадать;
33. **PNG** — все пять фильтров против посчитанных вручную байт, типы цвета (RGBA, палитра
    с `tRNS`, 1-битная палитра, серый+альфа, 16 бит), семь отказов с названной причиной,
    премультипликация альфы; плюс декодирование настоящих PNG из `_RemovedContent/`;
34. **замена текстур** — PNG в `Storage/Textures/` побеждает `.xnb`, отсутствующий файл это
    не ошибка, битый не бросает исключение и объясняет, что взята встроенная текстура,
    а `.dds` назван по имени;
35. **настоящие PNG** — 39 файлов из `_RemovedContent/` декодируются без ошибок и без шума
    (тысячи разных цветов там, где в арте десятки, означали бы сломанный Paeth или порядок
    битов). Единственная проверка против настоящего кодировщика; без `_RemovedContent/`
    пишет `skip`;
36. **атласы** — имена и прямоугольники совпадают по длине (219 и 1489), имена уникальны,
    лист помещается в 4096; заплатка ложится точно в свой слот и не задевает соседние,
    масштабируется по ближайшему соседу, премультиплицирует альфу, а заплатка за пределами
    листа и пустой план ничего не пишут;
37. **анти-чит** — сначала честные случаи (спринт, падение на терминальной скорости,
    подвисание на 500 мс, возрождение, крюк) проходят в обоих режимах, потом нечестные:
    телепорт 5000 px, полёт на 1200 px/с ловится за ~1 с, на 812 px/с — за ~4.7 с не позже
    заданного числа пакетов; `NaN` и позиция за миром отклоняются даже в `Observe`, край мира
    с допуском разрешён, `Off` действительно ничего не делает.

Код возврата 0 — всё хорошо.

### Он же без Content и без нативных DLL

Для CI и для чистого клона: `--selftest` намеренно **не трогает `FNAPlatform`**, поэтому
ему не нужны ни `SDL2.dll`, ни `Content/` (277 МБ, вне git). Проверки, которые без
ассетов не имеют смысла (`content manifest`, `content orphans`, `world file inspector`,
`png corpus`), пишут `skip` с причиной, а не `FAIL`:

```
Passed: 58  Skipped: 4  Failed: 0
```

Пропуск — это **не** «пройдено»: он виден в итоговой строке и в списке. Как только
`Content/` появится рядом с exe, три из них начинают работать сами; `png corpus` нужен
`_RemovedContent/` с настоящими PNG.

В чистом клоне Release-сборка даёт 58 пройденных и 4 пропуска; Debug добавляет ещё две
свои проверки (`debug kit`, `debug console`) и только их.

### CI

`.github/workflows/build.yml` — на каждый push и pull request: сборка Release с
`-warnaserror` (предупреждение — это ошибка; проект собирается чисто, и новое
предупреждение почти всегда означает дефект) плюс `--selftest`, лог которого уходит
артефактом.

## Документация

Вся документация лежит рядом с кодом, в корне репозитория:

- `AGENTS.md` — правила работы над кодом (для людей и агентов).
- `CHANGELOG.md` — что уже работает и какие баги были исправлены.
- `IDEAS.md` — идеи, планы, отклонённые решения.
- `ROADMAP.md` — порядок работ и критерии готовности.
- `PROMPT.md` — исходное задание по проекту.
- `docs/MULTIPLAYER.md` — как устроен встроенный сетевой стек.
- `docs/MODDING.md` — как писать моды.
- `docs/CONTENT_AUDIT.md` — что и почему вычищено из `Content/`.
- `docs/XNB.md` — `tools/XnbToPng`: как достать PNG из `.xnb` и почему декодер устроен
  именно так.
- `docs/WORLD_FORMAT.md` — формат `.wld`: оба варианта раскладки, почему миры ПК-версии
  опознаются, но не открываются.
- `docs/REFS_DIFF.md` — сравнение архитектур TerrariaXDK и сборок из `refs/`.
  Там же — какой функционал стоит перенести из `TShock` (`refs/TShock`).
- `docs/PERFORMANCE.md` — аудит загрузки и ОЗУ: почему старт бывал нестабильным,
  куда уходит память и что осталось оптимизировать.
- `docs/INPUT.md` — построчное сравнение управления с ПК-версией (`refs/`):
  что расходится и что уже исправлено.
- `docs/LOCALIZATION.md` — выбор языка и правки переводов из `Storage/Lang/`:
  формат файла, правило пробела после `=`, что делать при ошибке, чего механизм не умеет.
- `docs/PORTABILITY.md` — что уже не зависит от Windows, что мешает сборке вне Windows
  и почему непроверенное не выдаётся за сделанное.
- `docs/TEXTURES.md` — замена текстур PNG-файлами: какие форматы поддержаны, почему RGB
  умножается на альфу и что происходит со сломанным файлом.
- `docs/ANTICHEAT.md` — проверка движения в мультиплеере: режимы, почему по умолчанию
  только наблюдение, что освобождается от проверки и как быстро ловится читерство.

## Лицензия и правовой статус

Код происходит из декомпилированной клиентской сборки Terraria (Xbox 360) и
переиспользует открытые части FNA. Terraria и связанные ассеты — собственность
Re-Logic. Репозиторий существует для исследования совместимости и сохранения
архивных сборок; коммерческое использование ассетов не подразумевается.
