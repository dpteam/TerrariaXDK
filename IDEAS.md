## Уже сделано

- [x] **Переименование TerrariaOGC → TerrariaXDK.** Имя сборки, csproj, exe/config,
      версия в главном меню (`Main.OGCVersion`), заголовок лога.
- [x] **Клавиатура + мышь.** `Terraria/Input/KeyboardMouseInput.cs`. Не переписывает игру,
      а собирает синтетический `GamePadState` и подмешивает его к физическому геймпаду.
      WASD — движение, Space/Enter — A, Shift — двойной прыжок, E/Tab — инвентарь,
      R — бросок, C — smart cursor, Esc — пауза, Q/M — карта. ЛКМ/ПКМ — использование/граппл,
      колесо — хотбар, в меню ЛКМ = подтвердить.
      Абсолютный курсор: пока мышь двигается, `Player.UpdateMouse`/`UpdateMouseSmart` берут
      позицию прямо из десктопного указателя; через 3 с простоя управление возвращается стику.
- [x] **Чит-меню (только сингл).** `Terraria/Cheats/`. Открывается пунктом «Cheats» в паузе
      или клавишей **F1**. Реализовано в стиле консольных команд из `refs/T1061C` (ModClass),
      но через UI-меню: god mode, no clip, бесконечная мана, бесконечные баффы, без урона от
      падения, хил/мана, капы, время суток, кровавая луна, спавн боссов, kill all, метеор,
      разблокировка рецептов, сохранение. Всё закрыто `CheatState.IsAvailable` (`NetMode == 0`).
- [x] **Мультиплеер без отдельного серверного EXE.** `Terraria/Net/TcpPeer.cs` — TCP-хост
      внутри игрового процесса. Реализует новый интерфейс `IPeerTransport`, который
      `NetworkSession` использует вместо Lidgren. Есть handshake с версией протокола и
      подписью модов, roster, join/leave, relay трафика через хоста, LAN-дискавери по UDP.
      Старый Lidgren-путь остаётся как fallback (`NetworkConfig.UseTcpTransport = false`).
- [x] **Моды (сингл + онлайн).** `Terraria/Mods/`. Мод = папка в `Mods/` с .NET-сборкой;
      класс-наследник `Mod` с хуками `Load/Unload/OnGameUpdate/OnPlayerUpdate/OnWorldLoaded/
      OnWorldSaving`. `ModContext` даёт загрузку текстур/звуков из папки мода.
      Для онлайна считается подпись набора модов (FNV-1a), которая проверяется в handshake —
      клиент с другим набором не пускается в игру.
- [x] **Чистка Content.** Проверен каждый файл по коду. Удалено 147 файлов (~11 МБ):
      все `.dds`/`.png` (сырьё, игра грузит только `.xnb`), `FontsOld/`, XACT-банки
      (`Sound Bank.xsb`, `Wave Bank.xwb`, `TerrariaMusic.xgs`), `SoundsOld.zip`, `ACB.tga`,
      `UI/Controller_Layout01.xnb`, `Button_Abort/Confirm/Random`, `Gender_Selector`,
      `Sounds/Jump.xnb`, `Fonts/HD/small_sc_PS3.xnb`. Всё лежит в `_RemovedContent/`
      (можно вернуть), см. `docs/CONTENT_AUDIT.md`.
- [x] **Git-репозиторий.** Инициализирован, `.gitignore`, автор — `Terraria Agent`.
- [x] **Портативная папка `Storage/`.** Всё изменяемое — сохранения, логи, моды,
      конфиг, бэкапы, кэш — лежит в `Storage/` рядом с exe, а не в профиле пользователя
      (`%USERPROFILE%\SavedGames\...`). Копирование папки переносит игру целиком.
      Единая точка правды — `Terraria/Storage/AppPaths.cs`; `StorageDevice.RootOverride`
      перенаправляет XNA-контейнеры в `Storage/Saves`. `Settings.ini` рядом с exe работает
      как шаблон и засевается в `Storage/Config` при первом запуске.
      Проверяется тестом `--selftest` («app paths»).
- [x] **Headless self-test.** `TerrariaXDK.exe --selftest`: пути, манифест контента,
      поиск осиротевших файлов, framing, реальный TCP-loopback, парсинг адресов,
      загрузка модов, гейтинг читов. Не требует GPU — именно то, что нужно для CI
      и для ручных проверок.

      который игра не подписывает. Глобального `<NoWarn>` нет намеренно: он бы спрятал
      реальные проблемы в игровом коде.

## Из `refs/TShock` — серверный функционал

TShock в `refs/` — это серверный мод для **ПК**-версии, поэтому код несовместим
(другие packet id, другой `Netplay`). Берём **модель**, а не реализацию.
Тем не менее это самый полный источник идей для «админки», какой у нас есть.
`refs/NATUPNPLib` — его зависимость для проброса портов, тоже пригодится.

### Администрирование и права

- [ ] **Система прав.** У TShock всё висит на строковых permission-ах
      (`canbuild`, `kick`, `ban`, `tp`, `give`, `manageregion`, …), команда объявляется
      парой «право + делегат». У нас пока роль одна — «игрок». Нужен свой минимальный
      аналог: `Permission`, `Group` (набор прав), `User` (группа + хэш пароля),
      проверка в одном месте перед обработкой команды.
- [ ] **Группы и пользователи.** `addgroup/modgroup/delgroup/group`, `user`,
      `userinfo`. Пароли — не в открытом виде: у TShock `BCrypt`/SHA; нам хватит
      PBKDF2 из `System.Security.Cryptography`.
- [ ] **Логин/регистрация.** `login`, `register`, `password`, опция `RequireLogin`,
      `DisableLoginBeforeJoin`. Для нашего встроенного хоста это защита от того,
      что кто-то подключится под чужим ником.
- [ ] **Баны и вайтлист.** `ban/banip/unban/unbanip/clearbans`, `whitelist`,
      `EnableWhitelist`, `EnableBanOnUsernames`, `immunetoban`, `immunetokick`.
      У нас уже есть заготовка `banlist.txt` в старом `refs/T104C` — сделать нормально:
      IP + ник + причина + кто забанил + когда.
- [ ] **Мут и модерация чата.** `mute/unmute`, `whisper/reply`, `me`, `broadcast`,
      `motd`, `rules`. Плюс `DisplayIPToAdmins`.
- [ ] **Кик и «наказания».** `kick`, `kill`, `slap`, `annoy`, `butcher`,
      `tphere`, `tpallow` (разрешение телепортировать к себе).
- [ ] **Логи в игре.** `displaylogs` — окно с последними действиями админов
      и подозрительными событиями, а не только `terraria-debug.log`.

### Защита мира

- [ ] **Регионы.** `region` (define/delete/info/list), `RegionManager`,
      `RegionProtectChests`, `editspawn`, `protectspawn`, `antibuild`.
      Самое ценное для публичного хоста: запрет ломать чужие постройки.
- [ ] **Запрет строительства глобально.** `DisableBuild` + право `canbuild`.
- [ ] **Запрет предметов.** `additem/delitem/listitems`, `additemgroup`,
      `usebanneditem`. Позволяет выключить, например, бомбы на PvP-сервере.
- [ ] **Точки возврата.** `setwarp/delwarp/warp/sendwarp`, `home`, `spawn`,
      `RememberLeavePos` (заходить туда, где вышел).

### Анти-чит

У TShock это набор детекторов в `GetDataHandlers` с отдельными правами
«игнорировать проверку». У нас `spamCheck` уже размечен в `ServerSock`
(`spamProjectile`, `spamAddBlock`, `spamDelBlock`, `spamWater`), но не подключён
к нашему транспорту.

- [ ] **Детект no-clip** (`IgnoreNoClip`, `ignorenoclipdetection`).
- [ ] **Детект абуза тайлов** — слишком много kill/place за тик
      (`ignorekilltiledetection`, `ignoreplacetiledetection`), с откатом.
- [ ] **Детект абуза жидкости** и **снарядов** (`ignoreliquidsetdetection`,
      `ignoreprojectiledetection`).
- [ ] **Детект stack hack / stat hack** — проверка стека предметов и статов игрока
      на сервере (`ignorestackhackdetection`, `ignorestathackdetection`).
- [ ] **Кап урона** (`ignoredamagecap`) — отклонять невозможный урон.
- [ ] **Серверный инвентарь** (`ServerSideInventory`) — авторитетный инвентарь
      на хосте, а не на клиенте. Дорого, но убивает половину читов.

### Эксплуатация сервера

- [ ] **UPnP-проброс порта.** `refs/NATUPNPLib` (`UPnPNAT`, `IStaticPortMapping`)
      позволяет хосту самому открыть порт на роутере. Ровно то, чего не хватает
      для «просто нажми Host».
- [ ] **RCON.** `RconHandler` — админ-консоль по сети, удобно для управления
      headless-хостом (см. Mid term).
- [ ] **REST API.** `RestManager`, `SecureRest`, токен-аутентификация,
      `EnableTokenEndpointAuthentication` — статус сервера, список игроков,
      выполнение команд снаружи.
- [ ] **Автобэкапы.** `BackupInterval` — сохранять мир по таймеру в `Backups/`.
- [ ] **Конфиг сервера.** `ConfigFile` — у TShock это отдельный файл с десятками
      опций (`InfiniteInvasion`, `DisableHardmode`, `DisableDungeonGuardian`,
      `DisableClownBombs`, `DisableSnowBalls`, `DisableInvisPvP`, `AllowIce`,
      `HardcoreOnly`, `MediumcoreOnly`, `KickOnMediumcoreDeath`, …). Нам нужен
      свой `ServerConfig.ini` с подмножеством.
- [ ] **Статистика и статус.** `stats`, `world`, `playing/who`,
      `DisablePlayerCountReporting`.
- [ ] **GeoIP.** `MaxMind`/`GeoIPCountry` — показывать страну игрока, опционально
      банить по региону. Низкий приоритет.
- [ ] **PacketBufferer.** Буферизация пакетов перед рассылкой — сглаживает пики
      при массовой застройке. Полезно и нашему `TcpPeer`.
- [ ] **Обновления.** `checkupdates` — у нас не нужно, но идея «проверка версии
      клиента при коннекте» уже реализована через `ProtocolVersion`.

> Порядок внедрения и критерии — в `ROADMAP.md`, этап 7.

## Средний срок (Mid term)

- [ ] **Сервер без окна (dedicated).** Тот же `TcpPeer`, но без `Main`/графики:
      консольный хост, который грузит мир и крутит только симуляцию. Даст возможность
      держать мир 24/7 и тестировать сеть в CI.
- [ ] **Разделение `Main`.** 100 КБ в одном файле, десятки статических полей — вынести
      ввод, рендер, сеть и звук в отдельные сервисы. Делать постепенно, без «большого взрыва».
- [ ] **Сохранения вне реестра/песочницы.** Пути сохранений сейчас определяются
      `StorageDeviceManager`; на десктопе логичнее обычная папка `Saves/` рядом с exe.
- [ ] **Полноценные выделенные слоты игроков.** В консольной версии было до 8 игроков на
      одной консоли (split-screen) и до 8 в сети; сейчас `MaxSessions`/`PlayerSlotsTaken`
      размечены, но онлайн-путь использует только 8 слотов без разделения private/public.
- [ ] **Поддержка геймпадов разных вендоров.** `GamePad.GetState` идёт через SDL;
      нужны нормальные маппинги для Anbernic/Retroid/8BitDo и хотплаг.

## Долгий срок (Long term)

- [ ] **Динамическая поддержка ресурсов ПК-версии.** *(запрошено)*
      Сейчас игра грузит `.xnb` в консольной раскладке (`_sheetSprites`, `_sheetTiles`,
      `Fonts/HD`, `ExtMusic/*.wav`). В `refs/` лежат исходники ПК-версии, где контент
      организован иначе: отдельные текстуры предметов/NPC/тайлов, `Content/Images/*.png`,
      музыка в `.ogg`/`.mp3`, другие имена ассетов.
      Цель: слой ресурсов, который **динамически** определяет, что за набор контента лежит
      перед ним, и подхватывает подходящий, не падая при отсутствии части файлов:
      - определение по манифесту (`Content/manifest.json`) и/или по фактическому набору файлов;
      - конвертация/чтение ПК-текстур на лету (PNG → атлас), сборка атласов из россыпи;
      - аудио: WAV/OGG/MP3 через существующий `SoundEffect.FromStream`/`libtheorafile`;
      - фолбэк-цепочка «консольный ассет → ПК-ассет → заглушка» с логом, чтобы игра
        стартовала даже на неполном наборе;
      - кэш собранных атласов, чтобы второй запуск был быстрым;
      - всё это переиспользует манифест из `--selftest`, чтобы проверять целостность
        любого набора без запуска игры.
      Отказоустойчивость важнее полноты: неподдерживаемый ассет — это warning, а не краш.
- [ ] **Кроссплатформенность.** Сборка под Linux/ARM (Anbernic) — FNA уже умеет,
      мешают `Microsoft.Win32.Registry` в `Main.SpecialCheck` и пути `StorageDevice`.
- [ ] **Совместимость форматов миров с ПК.** Чтение/запись `.wld` версий ПК-ветки,
      чтобы можно было открывать миры из `refs/` и обмениваться ими.
- [ ] **Мод-API версии 2.** События мира (постановка/удаление тайла, спавн NPC, урон),
      сетевые пакеты модов с регистрацией id, изоляция падений в отдельный AppDomain.
- [ ] **Полноценные достижения и лидерборды без Xbox Live.** Сейчас
      `AchievementSystem`/`LeaderboardInfo` завязаны на `SignedInGamer`; заменить на
      локальное хранилище + собственный сервер статистики (опционально).

## Отклонено

- [-] **Тянуть `T111M`/`T1061M` целиком как tConfig.** Это отдельный мод-лоадер с
  компиляцией C# на лету (`CSharpCodeProvider`) и двоичными форматами `.tconfig`.
  Взяты только идеи (def-хендлеры, хуки), реализация — своя, чтобы не тащить
  и компилятор, и несовместимый формат сохранений.
- [-] **Отдельный серверный EXE как в `T111M`.** Прямое требование — встроить в игру.
  `TcpPeer` покрывает этот сценарий; dedicated-режим (см. Mid term) будет тем же кодом.
