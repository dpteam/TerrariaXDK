# ROADMAP

Порядок работ по TerrariaXDK. Критерий готовности каждого пункта — «можно проверить»,
а не «написано». Идеи и обоснования — в `IDEAS.md`.

Легенда: `[x]` готово, `[~]` в работе, `[ ]` не начато.

---

## Этап 3 — Мультиплеер без серверного EXE

- [x] `IPeerTransport` + `TcpPeer`: хост внутри процесса, фрейминг, handshake с версией
      протокола и подписью модов, roster, join/leave, relay, LAN-дискавери (UDP).
- [x] `NetworkSession` переведён на транспорт; локальные (split-screen) игроки
      замыкаются в процессе, удалённые идут по сети.
- [x] Подключение по адресу из `[Network] JoinAddress`.
- [x] Клиентское подключение: `NetworkSession.EndJoin` → `StartClientPeer` открывает TCP
      (раньше `EndJoin` не создавал транспорт вовсе — соединения не было).
- [x] Таймаут подключения (5 с), чтобы недоступный хост не вешал игру.
- [x] Отказоустойчивость: битый пакет от клиента не роняет хост/клиент (try/catch вокруг
      `CheckBytesServer`/`CheckBytesClient` и `Session.Update`).
- [x] Legacy Lidgren оставлен как fallback (`UseTcpTransport = false`).
- [x] Исправлен `AvailableNetworkSession`: свойства читали сами себя, из-за чего любой
      настоящий сервер в списке (LAN или из мастера) убивал процесс `StackOverflowException`.
- [x] Пароль хоста: проверяется до регистрации пира, клиенту приходит причина отказа.
- [x] Диагностика в игре: пинг (RTT), входящий/исходящий трафик, счётчики пакетов
      (`Terraria/Net/NetworkStats.cs`, показ в HUD при `NetMode != 0`).
- [x] Мастер-сервер: клиент публичного списка (`Terraria/Net/MasterServerClient.cs`)
      с HTTP/JSON-протоколом `GET /v1/servers`, `POST /v1/announce`, `POST /v1/remove`,
      кэшем в `Storage/Cache/servers.json`, таймаутом, backoff и жёсткой валидацией
      ответа. Публикация своего мира — `[Network] PublishToMaster` (по умолчанию off),
      объявления шлёт фоновый поток (`MasterPublisher`). Публичные серверы попадают
      в общий список вместе с LAN.
      **Сам сервис**: `tools/MasterServer` — консольный, без зависимостей, с журналом каждого
      запроса и каждого изменения списка, страницей `/` и `/health`, и своим `--selftest`
      (31 проверка). Порт мастера 17777 против игрового 7777 закреплён проверками с обеих
      сторон. Проверено вживую: игра видит список с локального мастера.
- [x] **Статистика достижений и таблицы рекордов без Xbox Live**: `POST /v1/stats` (клиент
      присылает достижения и счётчики), `GET /v1/achievements` (сколько игроков получили
      каждое), `GET /v1/leaderboard?stats=A,B` (рейтинг по сумме колонок доски — та же
      метрика, что консольная версия отправляла в Live). `Terraria/Net/StatSync.cs` на
      клиенте, `Terraria.Leaderboards/LeaderboardData.cs` читает доску с мастера фоном.
      В достижениях — «Reported by N of M players», потому что числа присланные, а не
      проверенные. Таблицы больше не берут данные из заглушки Live: та придумывала имена.
      Покрыто проверками `achievement stats` (игра) и 12 проверками `--selftest` мастера.
- [x] Свой минимальный JSON-парсер (`Terraria/Net/Json.cs`) — в net40 нет `System.Text.Json`.
- [x] Список серверов: LAN и мастер в одном месте, пометки `[pw]` (пароль) и
      `[mods]` (другая подпись модов, подключение всё равно откажет handshake),
      реальное число игроков/слотов.
- [x] Обновление по кнопке (`F5` / `LB`) и сохранение серверов в избранное (`F`,
      `Storage/Cache/favorites.txt`; такие видны даже когда мастер и LAN недоступны).
- [x] Автообновление списка по таймеру (20 с, `[Network] AutoRefreshSeconds`,
      выбранная строка сохраняется). Покрыто тестом `auto refresh`.
- [x] **Пинг в списке серверов**: `ServerPing` шлёт тот же `Hello` отдельным сокетом и
      мерит ответ. Отказ (пароль/моды/версия) считается живым сервером, мёртвый порт —
      «timeout», неизмеренный — пусто. Покрыто тестом `server ping`.
- [ ] Карточки серверов: версия и моды отдельной строкой (сейчас это пометки в строке).
- [x] Прямое подключение по адресу: `D` или `Right Shoulder` на экране выбора мира
      открывает ввод `host[:port]`, разрешает имя и подключается. Работает и с

- [x] Тест «хост + два клиента» в `--selftest` на реальных сокетах: roster, relay в обе
      стороны, уведомление о выходе. Покрыто тестом `host and two clients`.
- [x] Починена LAN-дискавери: хост слушал произвольный UDP-порт вместо
      `DiscoveryPort`, поэтому хосты в локальной сети были невидимы вообще.
- [x] `NetworkConfig.Port = 0` теперь означает «свободный порт от ОС», а

- [ ] Dedicated-хост без окна (тот же транспорт, без `Main`).

      глазами на Dxt1/Dxt5/Color. См. `docs/XNB.md`. Шрифты не трогаем:

- [ ] Кастомные TrueType-шрифты и вынос `Lang.cs` в файлы целиком. Правки перевода уже

- [x] Нормальная система настроек: экран `Display` (размер окна, полноэкранный режим,
      внутреннее разрешение 540p/720p/1080p). Значения реально применяются и пишутся

- [x] Профили настроек: `Default` / `TV` / `Handheld` — один пункт выставляет окно,
      полноэкранный режим и внутреннее разрешение разом. Определение профиля идёт по
      значениям, поэтому ручная правка честно даёт `Custom`. Покрыто тестом
      `display profiles`. Заодно в Display перенесён счётчик FPS.
- [x] Автообновление списка серверов раз в 20 с (`[Network] AutoRefreshSeconds`), с
      сохранением выбранной строки и без перезапуска уже идущего поиска.
- [x] Перенос сетевых опций в UI: экран **Настройки → Network** — имя игрока, порт,
      пароль, публикация в мастере, адрес мастер-сервера, интервал автообновления списка.
      Ввод через клавиатуру или виртуальную клавиатуру; значения пишутся в `[Network]`.
- [x] Имя игрока: по умолчанию берётся из учётной записи ОС (раньше у всех было
      `Terrarian`, то есть в LAN-списке все выглядели одинаково), меняется в игре и
      применяется сразу. Покрыто тестом `player identity`.
- [x] VSync и ограничение кадров (0/30/60/120/144/240) в экране `Display`, применяются
      сразу. Явный лимит отключает VSync, чтобы два разных периода не давали рывки.
      Значения валидируются, мусор в файле → «без лимита». Покрыто тестом
      `display settings`.
- [x] **Мышь и геометрия экрана при любом пресете.** Три отдельные причины одного симптома
      («мышь думает, что она ещё в 540p»): указатель приходил в пикселях окна, а игра живёт во
      внутреннем разрешении (`KeyboardMouseInput.SetViewport`, пересчёт каждый кадр); хит-тест
      меню не умножал на `ScreenMultiplier` там, где умножала отрисовка; границы прокрутки
      мини-карты тоже не умножали. Плюс «область, которую видит игрок» в семи местах игровой
      логики была зашита как `1920x1080` — сведена к `Main.ScreenAreaAround`.
      Покрыто тестами `pointer scaling` и `screen geometry` (последний печатает
      `screen area at 540p: 1028x788`, бывшее `1920x1080`).
      **Осознанно не тронуто:** расстояния спавна в `NPC.cs`, радиус подбора в `Item.cs`, зона
      Стены Плоти в `Player.cs` — это игровые дистанции, а не размер экрана, и в оригинале они
      фиксированы. Правило различения записано в `AGENTS.md`.
- [x] **Защёлка модальных окон.** Пока клавиша, которой закрыли виртуальную клавиатуру,
      не отпущена, игровой ввод выключен (`KeyboardMouseInput.HoldUntilRelease`). Раньше
      подавление длилось один кадр, а экран под клавиатурой видел в ещё нажатом Enter
      свежее нажатие «Start» — создание персонажа снова открывало запрос имени. Покрыто
      тестом `modal input latch`.
- [x] **Меню режима мира**: панель и хит-тест строк выводятся из одного прямоугольника
      (раньше строки были на 90 px правее панели и уже её, поэтому левая часть не
      нажималась), клик вне строки не активирует последнюю выбранную, `Start Game`
      привязан к нижней кромке панели. Меню читов — мелким шрифтом, как настройки.
      Колесо в хотбаре инвертировано под ПК (`refs/T12`: `selectedItem -= delta/120`).
- [ ] **Смена внутреннего разрешения без перезапуска.** Сейчас `Display` честно пишет
      «применяется при следующем запуске»: 1080p использует другой атлас шрифтов
      (`Fonts/HD/`), поэтому на лету нужно перезагружать шрифты вместе с render target.
      Всё остальное (окно, полноэкранный режим, VSync, лимит кадров) применяется сразу.
      Делать только на стенде с GPU: без него нечем проверить, что шрифты перезагрузились.
- [x] **Выбор языка**: `Настройки → Display → Language` — Auto (как в системе), English,
      Deutsch, Italiano, Français, Español. Пять переводов лежали в `Lang.cs` всегда, но
      выбирать их было нечем: язык брался только из культуры ОС, и поменять его без смены
      системных настроек было невозможно. Применяется сразу (перезаполнение всех строковых
      таблиц — это же и есть видимое доказательство, что работает), сохраняется в
      `[Display] Language`. Покрыто тестом `language`.
- [x] Зум камеры и виджеты HUD в экране **Настройки → HUD**: зум 1.00x–2.00x
      (применяется сразу, шаг 0.05, значения клампятся), сброс, часы/глубина/компас
      «всегда». Раньше `ZoomLevel` парсился через `Convert.ToSingle` (падало на мусоре)
      и нигде не применялся, а `Zoom(1f)` при каждом переходе в полноэкранный вид сбрасывал
      зум. Там же — предупреждение о хардмоде. Покрыто тестом `hud settings`.
- [x] **Правки перевода без пересборки**: `Storage/Lang/<code>.txt` читается поверх
      встроенных строк, генерируется командой `--lang-export de` (работает без окна и без
      GPU). Файл может быть частичным — удалённая строка значит «встроенный текст»;
      повторный экспорт сохраняет уже переведённое. Индекс вне диапазона, нечисловой ключ
      и неизвестная секция попадают в лог с объяснением, а пустое значение не стирает
      метку. Покрыто тестом `language overrides`. Подробности — `docs/LOCALIZATION.md`.
- [x] **Текст наших фич в переводе**: ответы читов, всех 22 команд хоста, модерации и
      `!serverconfig` собраны в `Terraria/Texts.cs` под ключами `chat.*` и переводятся через
      секцию `[Texts]` того же файла. Подстановки `{0}`-стиля (свой мини-форматтер, не
      `string.Format`: перевод — это файл, который правит игрок, и лишняя скобка не должна
      ронять игру). Покрыто тестом `feature text`. См. `docs/LOCALIZATION.md`.
- [x] **Экраны в переводе**: `Display`, `HUD`, `Mods`, `Network`, `Cheats`, бэкапы,
      переназначение клавиш, строки меню настроек, статусы, подсказки и заголовки окон
      ошибок. Названия клавиш строятся из имени действия (`MoveLeft` → `ui.key.moveleft`),
      поэтому забытое название не спрячется: оно попадёт в тест по имени действия.
      Комментарии `Settings.ini` намеренно оставлены английскими — файл читают при разборе
      проблем, и он не должен меняться от смены языка.
- [x] **Причины отказа — кодом, а не фразой.** `OpReject` несёт код причины и поля
      (`Terraria/Net/RejectReasons.cs`), клиент подбирает фразу на своём языке. Раньше
      сервер присылал английское предложение, и немецкий клиент читал причину по-английски —
      единственное место, где язык нельзя было исправить на стороне клиента. Собирать фразу
      из переведённых кусков не стали: в немецком глагол уходит в конец. Поля — отдельные
      `BinaryWriter.Write(string)`, потому что одно из них (причина кика) набирает хост.
      `ProtocolVersion` 2 → 3; старый текстовый `Reject` клиент по-прежнему понимает
      (первый байт предложения — печатный символ, все коды ≤ 6). Покрыто тестом
      `reject reasons`, включая живой сокет: настоящий хост отвечает кодом «неверный пароль».
- [ ] Вынос строк `Lang.cs` в файлы целиком (сейчас всё в коде, 17 000 строк) и
      TrueType-шрифты. Оверрайды закрывают правку перевода, но **не** добавление нового
      языка: `Lang` знает ровно пять вариантов через ветвления `LangOption == N`, и глифы
      запечены в атлас `Fonts/HD`, так что кириллица туда не поместится. Это отдельная
      работа по `Lang.cs` и контенту.
- [ ] Постепенное разделение `Main.cs` (ввод, рендер, сеть, звук) без «большого взрыва».
      **Сделано:** звук вынесен в `Terraria/Audio/SoundPlayer.cs` (тело перенесено
      дословно, в `Main` однострочные врапперы — ~300 вызовов не менялись), туда же
      переехали `SfxInstancePool`, `SoundManager`, `MusicEntry`. `Main.cs`: 3996 → 3771
      строк. Покрыто тестом `sound routing`.
      **Осталось:** рендер, ввод и сеть — там нужен `GraphicsDevice` или статический
      `Main`, и проверить перенос без GPU нельзя. Берём, когда появится стенд с OpenGL.
- [x] `Storage/Backups/`: датированные копии мира после сохранения, с лимитом на мир
      и минимальным интервалом (`[Backups] Keep/MinMinutes`). Включены по умолчанию.
- [x] **Восстановление из бэкапа в игре**: экран `B` на выборе мира — список копий
      выбранного мира (дата/время/размер), подтверждение перед перезаписью, текущий сейв
      сохраняется как `.prerestore`. Покрыто тестом `backup restore`.
- [x] `Storage/Cache/` используется: `servers.json` (кэш списка серверов), `favorites.txt`,
      `banlist`-соседи, скретч `--selftest`.
- [x] **Кэш собранных атласов — не нужен, проверено.** Атласы (`_sheetTiles`,
      `_sheetSprites`) не собираются в рантайме: это уже готовые одиночные `.xnb`
      (1.27 МБ и 1.16 МБ), которые `ContentManager` читает напрямую. Собирать нечего,
      поэтому кэшировать нечего; единственная теоретическая экономия — распаковка LZX,
      но это доли секунды против риска рассинхронизировать кэш с контентом. Пункт закрыт
      как неприменимый, а не сделанный.
- [x] Один скрипт на всю сборку: `tools/build.ps1` (build + `--selftest` + `-Pack/-Zip`
      для портативной папки).
- [x] CI: `.github/workflows/build.yml` — сборка Release с `-warnaserror` + `--selftest`
      на каждый push/PR. `--selftest` больше не требует ни `Content/`, ни нативных DLL
      (не инициализирует `FNAPlatform`), а контентные проверки без ассетов пишут `skip`
      с причиной вместо `FAIL`. Проверено на копии exe без Content и без SDL2:
      `Passed: 56  Skipped: 4  Failed: 0`. Третьим пропуском стал `world file inspector`, четвёртым — `png corpus` (настоящие PNG лежат
      в `_RemovedContent/`, вне git):
      без `tutorial.wld` ему нечего разбирать, а его собственный `catch (Exception)`
      раньше превращал `skip` в `FAIL` — то есть CI краснел на чистом клоне.

## Этап 6 — Долгосрочно

- [x] **Замена текстур PNG-файлами.** `Storage/Textures/` зеркалит дерево контента;
      `TextureContentManager` перехватывает `Content.Load<Texture2D>` (все 26 вызовов, включая
      собранные из кусков имена), поэтому регистрировать текстуры вручную не нужно. Свой
      декодер PNG (`Terraria/Textures/PngDecoder.cs`): все типы цвета, битности 1–16, пять
      фильтров, `tRNS`; Adam7 честно отвергается с причиной. Битый файл не роняет игру —
      грузится `.xnb` и в лог пишется причина. Покрыто тестами `png decoder` и
      `texture overrides`, включая 39 настоящих PNG. См. `docs/TEXTURES.md`.
- [x] **Замена одного спрайта внутри атласа.** `Storage/Textures/Atlases/<атлас>/<SPRITE>.png`,
      имя — из enum атласа (`_sheetTiles.ID`), второго списка имён нет. Заплатка накладывается
      на уже загруженный лист (чтение в память → наложение → загрузка обратно), поэтому не нужен
      ни render target, ни возня с `SpriteBatch` во время загрузки. Размер может отличаться —
      масштабируется по ближайшему соседу с замечанием в лог. Наложение (`Apply`) — чистый CPU,
      проверяется без видеокарты; тест `atlas overrides` дополнительно сверяет, что имена enum и
      массив `Source` не разошлись (219 и 1489), иначе каждая замена после разрыва попадала бы
      в чужой слот.
- [ ] Динамическая поддержка ресурсов ПК-версии из `refs/`, **остальное**: автоопределение
      набора контента, звук (OGG/MP3 уже стримится, но не поверх консольного), фолбэк-цепочка
      «консольный → ПК → заглушка», кэш. Сборка атласов на лету из россыпи PNG не нужна:
      атласы уже запечены, а замена по спрайту закрыта отдельным пунктом выше.
      Отказоустойчивость важнее полноты.
- [x] **Кроссплатформенность, часть кода**: `Microsoft.Win32.Registry` больше не тянется из
      игровой логики (флаг Collectors Edition читается из `[Game] CollectorsEdition`, реестр —
      только на Windows под `Portability.IsWindows`); пути, которые сравниваются или
      показываются, приводятся к переносимому виду (`Terraria/Portability.cs`). Исправлена
      настоящая ошибка: аудит контента сравнивал манифест с `\`, а листинг каталога отдаёт
      разделитель ОС — на Linux вся игра считалась бы мусором. Покрыто тестом
      `portable paths`, см. `docs/PORTABILITY.md`.
- [ ] **Кроссплатформенность, сборка и запуск** (Linux/ARM, Anbernic): `.so`-имена нативных
      библиотек, `build.sh`, `WinExe`/WinForms. **Рантайм не меняем** — остаёмся на `net40`,
      чтобы сохранить Windows XP+ и старые Mono на Linux (см. `IDEAS.md`, раздел про отказ от
      нативных `.dll`). Не сделано намеренно: проверить нечем (нет ни Linux, ни OpenGL), а
      непроверенное за сделанное не выдаём. Полный список препятствий — в `docs/PORTABILITY.md`.
- [x] **Диагностика миров**: `WorldFileInspector` разбирает `.wld` без загрузки и говорит,
      почему мир не открылся — обрезан (с указанием байта), повреждён, слишком короткий или
      это мир ПК-версии. Экран `LOAD_FAILED` теперь показывает причину. Покрыто тестом
      `world file inspector` на настоящем `Content/Worlds/tutorial.wld`.
      См. `docs/WORLD_FORMAT.md`.
- [ ] **Конвертация миров ПК-версии.** Нужны образцы ПК-миров (минимум две версии):
      раскладка ПК гейтится по версиям полей, а без образцов реализация проверялась бы

## Этап 7 — Серверная админка (по мотивам `refs/TShock`)

Порядок важен: каждый пункт опирается на предыдущий. Идеи и обоснования —
в `IDEAS.md`, раздел «Из `refs/TShock`».

- [x] **7.1 Права и команды (частично).** Группы в `Storage/Config/permissions.ini`,
      права флагами, единая точка проверки `Permissions.Allows`. Хост — владелец из кода;
      удалённый игрок не может получить его права под чужим именем. Команды клиентов
      исполняются на хосте с их правами. Покрыто тестом `permissions`.
      Осталось: единый разбор `/команда аргументы` для не-хостов без чата, `help` по правам.
- [x] **7.2 (частично) Баны.** `Storage/Config/banlist.txt`, точное сравнение по имени
      или IP, проверка в handshake до регистрации пира. Пароль хоста сделан в этапе 3.
      Осталось: логин/вайтлист.
- [x] **7.3 (частично) Модерация.** Команды хоста в чате: `!kick`, `!who`, `!say`,
      `!mute`/`!unmute`, `!whisper`, `!motd`, `!rules`, `!bans`, `!unban`, `!help`.
      Мут проверяется в relay-цикле, MOTD/правила уходят при подключении. Покрыто
      тестами `host commands`, `moderation`, `ban list` и живым мут+кик в
      `host and two clients`. Осталось: `displaylogs`, единая система прав.
- [x] **7.4 Защита мира.** Право `build`, защита квадрата вокруг спавна
      (`ProtectSpawnRadius`), аварийный `DisableBuild` и **именованные регионы**
      (`Storage/Config/regions.txt`, `!region`). Проверка в приёмнике пакетов 17/20/34 до
      применения и пересылки. Покрыто тестами `world protection`, `regions` и живой
      проверкой в `host and two clients`.
- [x] **7.4 (запрет предметов).** `!additem`/`!delitem`/`!items`, `items.txt`; хост
      отклоняет синхронизацию инвентаря с запрещённым id и не пересылает её. Покрыто
      тестом `item restrictions` и живой проверкой в `host and two clients`.
- [x] **7.6 (частично) Информация.** `!stats` (игроки, трафик, аптайм) и `!world`
      (имя, размер, спавн, боссы).
- [x] **7.6 (частично) Эксплуатация.** `Storage/Config/ServerConfig.ini` — отдельный
      профиль хостинга (порт, пароль, лимит игроков, MOTD, правила, защита, публикация).
      Ключи профиля побеждают `Settings.ini`, пропущенные берутся из него; файл не
      создаётся сам, меню пишет в активный файл. Покрыто тестом `server config`.
- [ ] **7.6 (остаток) UPnP-проброс.** `refs/NATUPNPLib`, автопроброс порта при хостинге.
      Без реального роутера не проверяется.
- [x] **7.5 Анти-чит, движение.** `Terraria/Net/AntiCheat.cs`: бюджет перемещения вместо
      лимита на пакет (пакеты приходят неравномерно, клиент сам выбирает момент, при
      подвисании несколько тиков едут одним пакетом). Ёмкость 512 px, пополнение 700 px/с —
      выше терминальной скорости падения (600 px/с), ниже чего-либо подозрительного.
      Проверка стоит в обработчике пакета 13 **до** применения и до пересылки, иначе отказ
      косметический. Режимы `Off` / `Observe` (по умолчанию) / `Enforce`; `Observe` пишет
      доказательства, но ничего не блокирует, потому что одно ложное срабатывание замораживает
      честного игрока для всех. Освобождены от проверки возрождение и крюк; `NaN`, `∞` и
      позиция за миром отклоняются даже в `Observe` — такое значение не бывает настоящим и
      портит мир хоста. `!anticheat off|observe|enforce`, покрыто тестом `anti-cheat`
      (в первую очередь честными случаями). См. `docs/ANTICHEAT.md`.
- [ ] **7.5 (остаток) Анти-чит.** No-clip (проход сквозь тайлы), абуз тайлов/жидкостей и
      снарядов, кап урона, право «игнорировать проверку». No-clip требует доступа к миру в
      момент приёма пакета и живой сверки — отложено до GPU-стенда. Подключить существующий

- [ ] **7.6 Эксплуатация.** UPnP-проброс (`refs/NATUPNPLib`), `ServerConfig.ini`,
      автобэкапы, `stats`/`world`, `PacketBufferer`.
- [ ] **7.7 Внешнее управление.** RCON для headless-хоста, затем REST API с токеном.

**DoD этапа:** можно поднять публичный хост, выдать кому-то права модератора,
забанить нарушителя, защитить спавн и увидеть это в логе — без правки кода.

## Этап 8 — Ноль поставляемых нативных библиотек (самый последний)

Цель: **не поставлять с игрой ни одного нативного файла** — ни `SDL2.dll`, ни `FNA3D.dll`,
ни `FAudio.dll`, ни `libtheorafile.dll`. Вместо них системные API: `user32`/`gdi32`, `d3d9`,
`dsound` на Windows; `libX11`/`libGL`/`libasound` на Linux. Системные `.so` — часть ОС, а не
сторонние библиотеки, поэтому это и есть «ноль зависимостей».

Побочный эффект — **совместимость с Windows XP+**, ради которой рантайм остаётся `net40`
(миграция на .NET 8 отменена: современные рантаймы XP не поддерживают вовсе).

Обоснование, замеры, таблица «что на что менять» и честная оценка стоимости — в `IDEAS.md`,
раздел «Полный отказ от сторонних нативных библиотек».

Порядок — от дешёвого к дорогому:

- [ ] **8.0. Предусловие:** игра запускается на стенде с OpenGL 2.1+. Всё, что связано с
      рендером, без этого не проверить, а писать вслепую проект не будет.
- [ ] **8.1. Убрать `libtheorafile`.** Видео игра не использует
      (`Content.Load<Video>` не вызывается), библиотека нужна только `Video.cs`.
      Минус одна зависимость и 370 КБ. Делается при любом варианте.
- [ ] **8.2. Инвентаризация API XNA** — какие типы и методы реально вызываются игрой.
      Результат в `docs/NATIVE_BACKEND.md`; это и есть объём работы, без него оценка — гадание.
- [ ] **8.3. Свой ввод** (`user32` + XInput/DirectInput) поверх существующего
      `KeyboardMouseInput`. Проверяется логированием, GPU не нужен.
- [ ] **8.4. Свой звук** (`DirectSound`/`WaveOut` / ALSA) для `SoundEffect` и музыки.
- [ ] **8.5. Свой рендер** (D3D9 / OpenGL через системный `libGL`) — только на стенде,
      со сверкой кадров с текущей версией. Самая большая часть.
- [ ] **8.6. Linux-бэкенд** (X11 + GL) — после того, как картинка совпала на Windows.

**Отменено:** упаковка чужих `.dll` в embedded resource и слияние FNA3D+FAudio+SDL2 в одну
библиотеку как *цель*. Это оставляет файлы нативных библиотек в комплекте — то, чего просили
избежать. Может пригодиться разве что как временная мера.

**DoD этапа:** папка с игрой состоит из exe, `Content/` и `Storage/` — и больше
ничего. Запускается на чистой Windows XP и новее, и на Anbernic без доустановки библиотек.

## Definition of Done

**Аудит роадмапа — самый последний шаг.** Когда все остальные пункты закрыты, `ROADMAP.md`
перечитывается построчно с одним вопросом к каждому: *какое доказательство, что это точно
сделано?* Пункт без доказательства возвращается в `[ ]` с пометкой, чего не хватает. Пункт,
закрытый «в основном», получает отдельный `[ ]` на остаток. Это записано и в `IDEAS.md`,
раздел «Самое последнее: аудит роадмапа» — чтобы список остатков был виден, а не размазан
по формулировкам «сделано, но…».

Пункт считается закрытым, когда одновременно:

1. `dotnet build` без ошибок;
2. `TerrariaXDK.exe --selftest` — 0 failed;
3. поведение описано в `README.md` или `docs/`;
4. изменение покрыто хотя бы одной проверкой в `Headless/SelfTest.cs`
   (если оно проверяемо без GPU);
5. коммит с осмысленным сообщением, автор — `Terraria Agent`.
