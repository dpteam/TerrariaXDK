# ROADMAP

Порядок работ по TerrariaXDK. Критерий готовности каждого пункта — «можно проверить»,
а не «написано». Идеи и обоснования — в `IDEAS.md`.

Легенда: `[x]` готово, `[~]` в работе, `[ ]` не начато.

---

## Этап 0 — База (готово)

- [x] Переименование TerrariaOGC → TerrariaXDK (сборка, exe, config, версия в меню).
- [x] Сборка одним `dotnet build`, net40/x64.
- [x] Git-репозиторий, `.gitignore`, автор `Terraria Agent`.
- [x] Чистка `Content/` с проверкой каждого файла по коду (147 файлов → `_RemovedContent/`).
- [x] Портативная `Storage/` рядом с exe: сохранения, логи, моды, конфиг (вместо профиля).
- [x] Headless self-test без GPU (`--selftest`).

## Этап 1 — Ввод (готово, кроме виртуальной клавиатуры)

- [x] Клавиатура + мышь: синтетический `GamePadState`, абсолютный курсор, приоритет
      мыши/стика, ввод в меню.
- [x] Все клавиши задокументированы в `README.md`.
- [x] Отключается одним флагом `[Input] KeyboardMouse=False`.
- [x] Виртуальная клавиатура для геймпада (`Terraria/Input/VirtualKeyboard.cs`):
      имена, чат, IP; буквы/цифры/символы, D-Pad и стики, `Y` — символы,
      `Start` — подтвердить. Открывается по `A` в чате и в поле адреса сервера.
- [x] **Имена персонажа и мира вводятся, а не генерируются.** Раньше нажатие Start
      сразу сохраняло персонажа со сгенерированным именем. Теперь `NamePrompt` открывает
      клавиатуру с этим именем в поле, проверяет длину и вычищает управляющие символы
      (`NameRules`), `Esc` отменяет создание. Покрыто тестом `name prompt`.
- [x] Переназначение клавиш: экран `Keyboard bindings` в настройках, значения хранятся
      в `Settings.ini` (`[Keys]`), повторное назначение занятой клавиши запрещено,
      `R` сбрасывает всё на умолчания.
- [x] Мышь в создании персонажа, выборе мира и выборе режима игры (наведение + клик).
- [x] Esc = «назад» в меню (раньше активировал пункт), курсор в меню не исчезает,
      клик не дублируется как `A`, хотбар цифрами 1..0, прямой прицел без smart cursor.
- [x] Колесо мыши листает то, что в фокусе: хотбар в игре, рецепты в крафте. Раньше оно
      было замаплено на бамперы и в инвентаре переключало раздел. Покрыто тестом
      `wheel scrolling`.
- [x] **Shift-клик «быстрый перенос»** в инвентаре: весь стек уходит в открытый контейнер
      (сундук, копилка, сейф) и обратно, с дозаполнением стеков и остатком в источнике.
      Логика — `Terraria/InventoryTransfer.cs`, проверка `inventory transfer`.
- [x] Остаток «как на ПК»: семантика `mouseLeftRelease`. Разобрано по `refs/T12`:
      в ПК-версии `mouseLeftRelease` — это **не** «отпустил», а «кнопка была поднята на конце
      прошлого кадра», то есть `mouseLeft && mouseLeftRelease` = «нажал в этом кадре». У нас
      это `LeftClicked`, и оно таким было. Чего действительно не хватало — того, ради чего в
      ПК-версии стоит `delayUseItem`: кнопка, которая уже была зажата, не должна начать
      действовать, как только игра снова обратила на неё внимание. Два случая — возврат
      фокуса в окно (клик, которым игрок переключился обратно, бил мечом) и закрытие меню с
      зажатой кнопкой (клик по «Resume» продолжал копать). Оба теперь ждут отпускания:
      `KeyboardMouseInput.AnyMouseButtonDown` / `EffectiveMouseButtons`, проверка в
      `input mapping`. `mouseInterface`, перетаскивание, переназначение клавиш и Shift-клик
      уже есть. Разбор — в `IDEAS.md`, раздел «Клавиатура и мышь „как на ПК“».

## Этап 2 — Читы и удобство (сингл)

- [x] Чит-меню: god, no clip, мана, баффы, fall damage, хил, капы, время, луна,
      спавн боссов, kill all, метеор, рецепты, сохранение.
- [x] Открытие: пункт «Cheats» в паузе + `F1`.
- [x] Жёсткий гейт: в мультиплеере недоступно (проверяется тестом).
- [x] Настройка «Enable Cheats» в игре: пункт в меню настроек, применяется сразу и
      сохраняется в `Settings.ini`; при выключении сбрасывает активные читы.
- [x] Плашка «CHEATS ACTIVE» в HUD и запрет отправки в лидерборды при читах.
- [x] **Отладочная консоль на хосте (Debug only).** `CheatConsole.CanRunHere` =
      `CheatState.IsAvailable || DebugHostConsole`, где второй — `NetMode == 2` под
      `#if DEBUG`; сам `CheatState.IsAvailable` не тронут, поэтому Release не содержит ни
      команд, ни флага (проверено поиском строк в Release-`exe`). Новые команды:
      `!spawnnpc <id|имя> [count]` (через `Terraria/NpcLookup.cs`) и `!invasion <goblins|snow>`.
      Читы-флаги (`god`/`noclip`/`infmana`/`infbuff`) на хосте отказывают с причиной, потому
      что их эффект гейтится на одиночную игру. Покрыто тестами `npc names` и
      `debug host console`; меню поверх команд — `IDEAS.md`, «Меню Debug вместо меню Cheats».
- [x] Виртуальная клавиатура для геймпада (`Terraria/Input/VirtualKeyboard.cs`):
      открывается из чата по `A`, полная сетка символов + страница знаков.
- [x] Меню модов в игре: список `Storage/Mods`, вкл/выкл через `disabled.txt`, `R` —
      пересканировать, показ подписи и ошибок. Изменения применяются после перезапуска
      (выгрузка уже загруженной сборки в .NET невозможна).

## Этап 3 — Мультиплеер без серверного EXE

- [x] `IPeerTransport` + `TcpPeer`: хост внутри процесса, фрейминг, handshake с версией
      протокола и подписью модов, roster, join/leave, relay, LAN-дискавери (UDP).
- [x] `NetworkSession` переведён на транспорт; локальные (split-screen) игроки
      замыкаются в процессе, удалённые идут по сети.
- [x] Подключение по адресу из `[Network] JoinAddress`.
- [x] Клиентское подключение: `NetworkSession.EndJoin` → `StartClientPeer` открывает TCP
      (раньше `EndJoin` не создавал транспорт вовсе — соединения не было).
- [x] Таймаут подключения (5 с), чтобы недоступный хост не вешал игру.
- [x] Отказоустойчивость: битый пакет от клиента не роняет хост/клиент (try/catch вокруг
      `CheckBytesServer`/`CheckBytesClient` и `Session.Update`).
- [x] Legacy Lidgren оставлен как fallback (`UseTcpTransport = false`).
- [x] Исправлен `AvailableNetworkSession`: свойства читали сами себя, из-за чего любой
      настоящий сервер в списке (LAN или из мастера) убивал процесс `StackOverflowException`.
- [x] Пароль хоста: проверяется до регистрации пира, клиенту приходит причина отказа.
- [x] Диагностика в игре: пинг (RTT), входящий/исходящий трафик, счётчики пакетов
      (`Terraria/Net/NetworkStats.cs`, показ в HUD при `NetMode != 0`).
- [x] Мастер-сервер: клиент публичного списка (`Terraria/Net/MasterServerClient.cs`)
      с HTTP/JSON-протоколом `GET /v1/servers`, `POST /v1/announce`, `POST /v1/remove`,
      кэшем в `Storage/Cache/servers.json`, таймаутом, backoff и жёсткой валидацией
      ответа. Публикация своего мира — `[Network] PublishToMaster` (по умолчанию off),
      объявления шлёт фоновый поток (`MasterPublisher`). Публичные серверы попадают
      в общий список вместе с LAN.
      **Сам сервис**: `tools/MasterServer` — консольный, без зависимостей, с журналом каждого
      запроса и каждого изменения списка, страницей `/` и `/health`, и своим `--selftest`
      (31 проверка). Порт мастера 17777 против игрового 7777 закреплён проверками с обеих
      сторон. Проверено вживую: игра видит список с локального мастера.
- [x] **Статистика достижений и таблицы рекордов без Xbox Live**: `POST /v1/stats` (клиент
      присылает достижения и счётчики), `GET /v1/achievements` (сколько игроков получили
      каждое), `GET /v1/leaderboard?stats=A,B` (рейтинг по сумме колонок доски — та же
      метрика, что консольная версия отправляла в Live). `Terraria/Net/StatSync.cs` на
      клиенте, `Terraria.Leaderboards/LeaderboardData.cs` читает доску с мастера фоном.
      В достижениях — «Reported by N of M players», потому что числа присланные, а не
      проверенные. Таблицы больше не берут данные из заглушки Live: та придумывала имена.
      Покрыто проверками `achievement stats` (игра) и 12 проверками `--selftest` мастера.
- [x] Свой минимальный JSON-парсер (`Terraria/Net/Json.cs`) — в net40 нет `System.Text.Json`.
- [x] Список серверов: LAN и мастер в одном месте, пометки `[pw]` (пароль) и
      `[mods]` (другая подпись модов, подключение всё равно откажет handshake),
      реальное число игроков/слотов.
- [x] Обновление по кнопке (`F5` / `LB`) и сохранение серверов в избранное (`F`,
      `Storage/Cache/favorites.txt`; такие видны даже когда мастер и LAN недоступны).
- [x] Автообновление списка по таймеру (20 с, `[Network] AutoRefreshSeconds`,
      выбранная строка сохраняется). Покрыто тестом `auto refresh`.
- [x] **Пинг в списке серверов**: `ServerPing` шлёт тот же `Hello` отдельным сокетом и
      мерит ответ. Отказ (пароль/моды/версия) считается живым сервером, мёртвый порт —
      «timeout», неизмеренный — пусто. Покрыто тестом `server ping`.
- [x] Карточки серверов: версия и моды отдельной строкой. Строка списка была одной, и
      пометки приклеивались к имени: `Bob [pw] [mods] [v3] [relay]`. При двух причинах сразу
      это упиралось в счётчик игроков справа, и читаемым оставалось только имя. Теперь
      **две строки** (`Terraria/ServerCard.cs`, чистая функция): сверху номер, звёздочка
      избранного и имя, справа пинг и заполненность; снизу адрес и пометки — пароль,
      «моды отличаются», «protocol 4, yours 3», «via relay». У релейного сервера вместо
      адреса честно написано `via relay`: прямого адреса у него нет.
      Высота карточки вдвое больше строки мира, поэтому в панель входит вдвое меньше
      серверов; `MouseSessionRowHeight` — **отдельное** число, а не общее с миром, и обе
      раскладки идут через одну `WorldSelect.RowAt`. Прокрутка серверов теперь тоже есть
      (колесом и стрелками), а видимое число берётся из высоты панели, а не из
      захардкоженных 16. Покрыто тестом `server cards`.
- [x] Прямое подключение по адресу: `D` или `Right Shoulder` на экране выбора мира
      открывает ввод `host[:port]`, разрешает имя и подключается. Работает и с
      виртуальной клавиатурой.
- [x] Тест «хост + два клиента» в `--selftest` на реальных сокетах: roster, relay в обе
      стороны, уведомление о выходе. Покрыто тестом `host and two clients`.
- [x] Починена LAN-дискавери: хост слушал произвольный UDP-порт вместо
      `DiscoveryPort`, поэтому хосты в локальной сети были невидимы вообще.
- [x] `NetworkConfig.Port = 0` теперь означает «свободный порт от ОС», а
      `ActivePort` сообщает реально занятый.
- [ ] Dedicated-хост без окна (тот же транспорт, без `Main`).

## Этап 4 — Моды

- [x] Загрузчик: папки `Mods/<Mod>/<Assembly>.dll`, атрибут `ModInfo`, класс `Mod`.
- [x] Хуки: `Load`, `Unload`, `OnGameUpdate`, `OnPlayerUpdate`, `OnWorldLoaded`,
      `OnWorldSaving`.
- [x] `ModContext`: файлы, текстуры (PNG/DDS), звуки (WAV), лог.
- [x] Изоляция падений: упавший мод отключается, игра продолжается.
- [x] Подпись набора модов и проверка при подключении (сингл + онлайн).
- [x] Сетевые пакеты модов: свой opcode транспорта (`OpMod`), id мода внутри кадра,
      регистрация не нужна, лимит 64 КиБ, хост ретранслирует как обычные данные.
      `Context.SendPacket` / `Mod.OnPacket`, покрыто тестом `mod packets`.
- [x] События мира: `OnTilePlaced` / `OnTileKilled` / `OnNpcHurt`. Один вызов на точку
      входа в `WorldGen.PlaceTile` / `KillTile` / `NPC.StrikeNPC`, гейт
      `ModEvents.IsActive` (нет модов / идёт генерация / открыто меню → ноль работы).
      Покрыто тестом `mod world events`, включая «упавший мод не ломает остальные».
- [x] События мира, остаток: `OnNpcSpawn` (`NPC.NewNPC`), `OnNpcDeath` (`NPC.CheckDead` —
      ровно один раз на смерть, в отличие от `OnNpcHurt`), `OnPlayerHurt` (`Player.Hurt`,
      урон после защиты), `OnLiquidChanged` (только ведро, не симуляция течения).
      Все под тем же гейтом и с проверкой на `null`; покрыто тем же тестом `mod world events`
      (включая «во время генерации молчат»). Разбор «что где менять» — `docs/MODDING.md`.
- [x] Пример мода в `Examples/ExampleMod` + инструкция (собирается отдельным проектом,
      проверено: загрузчик видит его и подпись перестаёт быть `vanilla`).
- [x] Совместимость с tConfig: чтение `Storage/tConfig/*/Item/*.ini` и правка
      существующих предметов по имени (новые id не создаются — ломают сохранения и сеть).
      Неподдерживаемые поля пишутся в лог. Покрыто тестом `tconfig import`.
- [x] Конвертор tConfig → наш формат мода: `--tconfig-convert <пак>` пишет проект
      (`<Имя>.csproj`, `<Имя>.cs`, `README.md`) в `Storage/ModSources/<Имя>/`, который
      собирается обычным `dotnet build` и кладётся в `Storage/Mods/`. Числа переносятся
      вызовами `Context.Item(...)`, а не текстом INI, поэтому результат участвует в подписи
      набора — этого папка в `Storage/tConfig/` не даёт. Всё непереносимое (неизвестные имена,
      поля без эквивалента) перечисляется в `README.md`, а не выбрасывается молча. Покрыто
      тестом `tconfig convert`, включая сверку «каждому полю — существующее свойство
      `ItemOverride`»; проверено и вживую: сгенерированный проект собирается, `--selftest`
      видит мод и меняет подпись набора.
      **Осталось:** декомпилятор поведения — у tConfig-модов с кодом переносится только
      описание предметов, а логику нужно писать заново под наш API. Это уже не конвертация,
      а реверс-инжиниринг конкретных паков, и делать его вслепую, без самих паков, нечестно.
- [x] **Новые предметы из модов.** `Context.DefineItem(name, sprite)` создаёт предмет, которого
      в игре не было: id выше ванильных, спрайт из папки мода, статы как у `ItemOverride`.
      Проверено на живом паке: `Omnirs Weapons` (114 предметов с `type=-1`) конвертируется,
      проект собирается, игра регистрирует все 114.
      **Как решены три трудные части:**
      1. **Id.** Выделяются **после** загрузки всех модов, в порядке `(мод, предмет)`. Не в
         порядке регистрации: id едет по проводу, и два игрока с одинаковыми модами,
         загруженными в разном порядке, иначе разъехались бы — выглядело бы как «предмет
         превратился в другой». Диапазон с 20000: `Item.Type` — `short`, он уже в сохранениях
         и в протоколе.
      2. **Спрайты.** Одна упакованная текстура **на мод**, с кэшем в `Storage/Cache/ModSheets/`.
         Одна — потому что `SpriteBatch` сбрасывает пачку при смене текстуры, и отдельные PNG
         на предмет стоили бы по сбросу на каждый предмет в сундуке. Кэш — потому что распаковка
         сотни PNG на каждом запуске заметна; ключ включает имена, размеры и время правки.
      3. **Потерянный мод.** Id из сохранения без мода становится **пустым слотом** с записью в
         лог. И отрисовка это учитывает: три места (`UI.DrawInventoryItem`,
         `WorldView.DrawItems`, `Player` — предмет в руке) проверяют диапазон, иначе ванильная
         ветка проиндексировала бы атлас id вроде 20043 и упала.
      **Покрыто** тестом `mod items` (id, статы, имя, пустой слот, формат кэша спрайтов).
      **Осталось:** поведение из tConfig-кода (`OnUse`, `PreDraw`) — это декомпилятор,
      отдельная работа; предмет пока только данные. И упаковка текстуры требует GPU, поэтому
      в headless-тест не входит — проверена вживую.
- [x] **Рецепты модов.** `Context.AddRecipe` + `AddIngredient`/`AddStation` по имени. Массив
      рецептов был фиксированным (`new Recipe[342]`) и **все** циклы говорили `342`, поэтому
      мод-рецепт не мог попасть в игру вообще; теперь `Recipe.Capacity` и циклы до
      `Recipe.NumRecipes`, а «открытые рецепты» расширяются на чтении сейва.
      **Найденный по дороге баг, который был хуже самого пункта:** `Item.SetDefaults(string)` —
      не поиск, а `switch` на две дюжины старых консольных предметов. Через него шли
      `Context.Item`, импортёр tConfig, ингредиенты рецептов и конвертер — то есть все они
      работали только для этих двух дюжин, и тесты этого не видели, потому что использовали
      «Copper Shortsword» из списка. Добавлен `Terraria/ItemLookup.cs`: обратная таблица от
      `Lang.ItemName`, включая legacy-предметы с отрицательными id, построенная на английском
      (файлы модов английские) и спрашивающая реестр мод-предметов первой.
      Конвертер теперь разбирает секции `[Items]`/`[Tiles]`/`[Amount]`/`[needWater]` — раньше
      секция отбрасывалась, и каждый ингредиент попадал в отчёт как «поле без эквивалента»
      (450 предупреждений на одном паке, прятавших настоящие). Проверено вживую:
      `Omnirs Weapons` — **114 предметов и 114 рецептов**, проект собирается. Покрыто тестами
      `mod recipes` и `mod items`.
      **Осталось:** поведение из tConfig-кода (`OnUse`, `PreDraw`) — декомпилятор, отдельная
      работа; предмет и рецепт пока данные.
- [x] Менеджер модов в игре: список, вкл/выкл (`disabled.txt`), ошибки загрузки,
      приоритет загрузки (`Mods/loadorder.txt`, Left/Right в меню, покрыто тестом
      `mod load order`). В списке видны и tConfig-паки (`[tConfig]`) — они не загружаются, но
      конвертируются из меню по `C`, с вопросом «удалить оригинал?». Покрыто тестом
      `mod menu kinds`.
- [x] **Raw Mod: мод без компиляции.** Папка `Storage/Mods/<Имя>/` без `.dll`, но с
      `Item/*.ini` (+ необязательный `mod.ini`), — это мод. Формат совпадает с tConfig-паком,
      поэтому пак кладётся в `Mods/` как есть. `Terraria/Mods/RawMod.cs` регистрирует новые
      предметы (`type=-1` или неизвестное имя + PNG), правки существующих и рецепты в тех же
      реестрах, что и скомпилированный мод, — игра их не различает.
      **Подпись по содержимому:** `имя|версия|raw:<хеш папки>`, `disabled.txt` в хеш не входит;
      у скомпилированных модов подпись не изменилась.
      **Меню:** пометка `[Raw]`, число предметов и версия; вкл/выкл и порядок загрузки — как у
      обычного мода. **Пример:** `Examples/ExampleRawMod`.
      Проверено вживую: `SonnyMod` прямо из `Storage/tConfig/` даёт **111 новых предметов и
      84 рецепта** — те же числа, что давала конвертация в проект. Пять паков сразу (`HPack`,
      `Omnirs Weapons`, `The Arsenal`, `Portal Mod`, `SonnyMod`) дают 468 предметов и
      427 рецептов, и `--selftest` проходит с ними.
      **Найдено по дороге:** в реальных паках два написания рецепта. Кроме по-секционного
      (`[Items] Copper Bar=6`) есть строчный (`[Recipe] Items=6 Copper Bar, 2 Wood`), который
      пишут `SonnyMod` и `Suggestions`. Он молча пропускался как «не поле предмета», и такие
      предметы нельзя было скрафтить. Теперь понимаются оба — и в Raw-загрузчике, и в
      конвертере (80 → 84 рецепта у `SonnyMod`).
      **Конвертация пака в Raw-мод** тоже сделана: `C` в меню модов (и `--tconfig-raw`)
      пишет `Storage/Mods/<Имя>/` с `mod.ini` и переписанными `Item/*.ini`; `P`
      (`--tconfig-convert`) по-прежнему пишет проект с C#. Проверено вживую на `SonnyMod`:
      111 предметов и 84 рецепта, и результат загружается как мод без правок.
      **Неподдерживаемый контент теперь называется.** У реальных паков есть `NPC/` (146 файлов у
      `Omnir's Creatures`), `Tiles/` (88 у `SonnyMod`), `Walls/`, `Buffs/`, `Projectiles/` — и
      раньше они молча не читались, из-за чего «111 предметов загружено» читалось как «и NPC
      тоже». Теперь загрузчик их считает и пишет строку в лог, меню показывает
      `N file(s) unusable`, а `README.md` конвертированного проекта получает раздел «what this
      build cannot load». Это граница сборки, а не ошибка пака.
      Покрыто тестами `raw mod`, `mod menu kinds` и `tconfig convert`.
- [x] **Сетевая игра требует одинаковый набор модов.** Раньше клиент **без модов**
      принимался любым хостом: «у меня ничего нет» читалось как «мне всё равно». Чистая
      установка заходила на модифицированный сервер, видела другие характеристики предметов,
      и никто ничего не говорил. Теперь сравнение симметричное, а отказ **называет моды**
      (в handshake едет список имён и версий): «не хватает: CoolMod v1.2.0», «лишние:
      Sneaky v0.1», «версии разошлись: CoolMod (host 1.2.0, you 1.0.0)». Покрыто тестом
      `mod set requirement`, включая живой хост: настоящий handshake от модифицированного
      хоста отказывает ванильному клиенту и **пропускает** совпадающего.
      **Скачивание с сервера — сделано.** Хост может раздать свои моды клиенту с другим
      набором (`[Mods] AllowDownload`), клиент может их принять (`[Mods] DownloadFromHost`),
      обе выключены по умолчанию. Список в handshake несёт размер и хеш содержимого; отказ
      `ModMismatch` называет моды и предлагает скачивание; файлы идут по отдельному opcode
      `OpModFile` на втором соединении (которое никогда не становится игроком), проверяются по
      пути, манифесту и хешу на диске и только потом переезжают в `Storage/Mods/<Имя>/`.
      Покрыто проверками `mod download` и `mod set requirement`. Подробности — `IDEAS.md`,
      раздел 1b.

- [x] **Причины отказа — кодом, а не фразой.** `OpReject` несёт код причины и поля

      сервер присылал английское предложение, и немецкий клиент читал причину по-английски —
      единственное место, где язык нельзя было исправить на стороне клиента. Собирать фразу
      из переведённых кусков не стали: в немецком глагол уходит в конец. Поля — отдельные
      `BinaryWriter.Write(string)`, потому что одно из них (причина кика) набирает хост.
      `ProtocolVersion` 2 → 3; старый текстовый `Reject` клиент по-прежнему понимает
      (первый байт предложения — печатный символ, все коды ≤ 6). Покрыто тестом
      `reject reasons`, включая живой сокет: настоящий хост отвечает кодом «неверный пароль».
- [x] **TrueType-шрифты и новый язык без пересборки.** Было два барьера, и сняты оба:
      `Lang` знал ровно пять вариантов, прошитых ветвлениями `LangOption == N`, а глифы были
      запечены в `Content/Fonts/HD`, поэтому кириллица туда не помещалась.
      **Язык:** шестой вариант `Custom` (`Language.Custom`), у которого нет скомпилированных
      таблиц — он стартует с английского (он же фолбэк) и берёт текст из
      `Storage/Lang/<code>.txt`. Код языка — из `[Display] CustomLanguage`, **фильтруется как
      имя файла** (`../../etc/passwd` → `etcpasswd`), иначе настройка указывала бы на любой
      файл на диске. `Lang.SetLang` для этого варианта наливает английские таблицы и
      возвращает опцию: без этого ни одна ветка `LangOption == N` не совпала бы и интерфейс
      остался бы **пустым** — это проверяет тест `custom language`.
      **Шрифт:** формат атласа — PNG + текстовые метрики (`Terraria/Fonts/FontAtlas.cs`,
      чтение/запись/обратимость, восемь способов испортить файл отвергаются с причиной).
      Соглашение ячейки — как у встроенных атласов (`cropping = (0,0,w,h)`,
      `kerning = (0,w,0)`), а не плотная обрезка конвейера XNA: иначе каждый глиф рисуется не
      на своём месте. Загрузка — «все три набора или ни одного» (`GeneratedFonts`), иначе
      меню рисовалось бы, а HUD остался пустым. При любой проблеме остаётся встроенный атлас.

## Этап 7 — Серверная админка (по мотивам `refs/TShock`)

Порядок важен: каждый пункт опирается на предыдущий. Идеи и обоснования —
в `IDEAS.md`, раздел «Из `refs/TShock`».

- [x] **7.1 Права и команды (частично).** Группы в `Storage/Config/permissions.ini`,
      права флагами, единая точка проверки `Permissions.Allows`. Хост — владелец из кода;
      удалённый игрок не может получить его права под чужим именем. Команды клиентов
      исполняются на хосте с их правами. Покрыто тестом `permissions`.
      Осталось: единый разбор `/команда аргументы` для не-хостов без чата, `help` по правам.
- [x] **7.2 Баны и вайтлист.** `Storage/Config/banlist.txt`, точное сравнение по имени
      или IP, проверка в handshake до регистрации пира. Пароль хоста сделан в этапе 3.
      Вайтлист: `Storage/Config/whitelist.txt`, `[Network] Whitelist`, `!whitelist
      on|off|add|remove|list`, проверка в handshake после пароля и до регистрации; пустой

- [x] **7.3 (частично) Модерация.** Команды хоста в чате: `!kick`, `!who`, `!say`,

- [x] **7.6 (остаток) UPnP-проброс.** Порт открывается через роутер, если тот умеет.
      Реализовано **не** через COM (`refs/NATUPNPLib`, `HNetCfg.NATUPnP` — только Windows), а
      своими сокетами: SSDP-поиск шлюза, чтение его описания, SOAP `AddPortMapping` /
      `DeletePortMapping` / `GetExternalIPAddress` / `GetSpecificPortMappingEntry`.
      `Terraria/Net/UPnP.cs` (протокол; всё, что можно решить без сети, — чистые функции),
      `PortForwarder.cs` (фон, чтобы хостинг не ждал роутер). Включено по умолчанию
      (`[Network] UPnP=True`), трогает только порт игры и снимает правило при выходе.
      **Три вещи важнее самого проброса:**
      1. **Чужое правило не удаляется.** `DeletePortMapping` снимает запись, кто бы её ни
         сделал, поэтому `Map` сообщает, создали ли правило мы: найденный (ручной) проброс
         остаётся на месте — иначе выход из игры ломал бы настроенный вручную хостинг.
      2. **718 (порт занят) — не «успех».** Запись читается обратно: если порт ведёт на эту
         машину, всё хорошо; если на другую — внятная ошибка «порт уже проброшен на
         192.168.1.9, а не на 192.168.1.5». Молчаливый успех здесь — это и есть ответ на
         «почему меня никто не видит».
      3. **Ответ роутера не парсится как XML.** У них бывают недекларированные префиксы и
         мусорные байты; «роутер сказал 718» не должно превращаться в «роутер ничего не
         сказал».
      Проверка `upnp` в `--selftest` гоняет весь обмен против **заглушки шлюза** (SSDP,
      описание, SOAP, включая отказы и конфликт 718). Есть и диагностика
      `TerrariaXDK.exe --upnp [порт]` — только читает, ничего не меняет.
      **Честно:** на этой машине роутер на SSDP не отвечает вообще (проверено независимо,
      сырым сокетом: 0 ответов на `ssdp:all`), поэтому живой проброс здесь не проверен —
      проверены протокол и вся логика вокруг него. Релей остаётся рабочим путём.
- [x] **7.6 (альтернатива UPnP) Релей через мастер-сервер.** Для CGNAT и роутеров без
      UPnP, где наружу не пробиться вообще: хост и клиенты приходят на мастер

      разрешение строить. Теперь два ведра на игрока: одиночные правки — 200 в запасе,
      60/с (быстрейшая кирка — 20/с, взрыв — ~150 сразу), записи секций (пакет 20) — 8 в
      запасе, 0.5/с. Отказ пишется в лог и говорится игроку не чаще раза в 5 с, чтобы отказ не
      превратился в флуд чата; бюджет сбрасывается при выходе игрока и при завершении сессии.
      Двери (пакет 19) тоже расходуют бюджет — они обходили защиту мира полностью, потому что
      `WorldProtection` их вообще не проверял; гейт по правам им намеренно **не** добавлен
      (иначе в защищённом доме нельзя открыть дверь, в которую надо войти), но флуд закрыт.
      Порядок важен и закреплён: права спрашиваются **первыми**, поэтому игрок без права
      строить не тратит бюджет на выяснение этого. Покрыто тестом `edit budget`.
      **Осталось (честно):** no-clip (проход сквозь тайлы) требует доступа к миру в момент
      приёма пакета и живой сверки — отложено до GPU-стенда; кап урона и право «игнорировать
      проверку» не сделаны; `spamCheck` в этой кодовой базе отсутствует (искал — нет), так что
      подключать было нечего, лимит написан с нуля.
- [x] **7.6 Эксплуатация.** UPnP-проброс (`Terraria/Net/UPnP.cs`, см. пункт выше),
      `ServerConfig.ini`, автобэкапы, `stats`/`world` — сделано.
      **`PacketBufferer`** — тоже: `Terraria/Net/PacketBufferer.cs`. Каждый пакет раньше
      уходил отдельным `Write` при `NoDelay=true`, то есть отдельным TCP-сегментом с 40 байтами
      заголовка. Теперь игровые данные (`OpData`) копятся и уходят **одной записью на
      соединение за тик**, в `TcpPeer.Drain` (игровой поток, тот же тик, в котором данные
      появились — задержка не растёт). Остальное (handshake, roster, reject, ping) уходит
      сразу: это кадры, которых кто-то ждёт, и reject, оставшийся в буфере при закрытии
      соединения, — баг без выгоды. `Close` сначала сбрасывает буфер.
      Покрыто тестом `packet batching` (20 кадров → одна запись, все читаются в том же
      порядке; в буфер попадает только `OpData`; предел 32 КиБ; пустой flush не пишет
      ничего) и живой проверкой в `host and two clients`: 12 пакетов одним тиком доходят до
      второго клиента по порядку.
- [ ] **7.7 Внешнее управление.** RCON для headless-хоста, затем REST API с токеном.

**DoD этапа:** можно поднять публичный хост, выдать кому-то права модератора,
забанить нарушителя, защитить спавн и увидеть это в логе — без правки кода.

## Этап 8 — Ноль поставляемых нативных библиотек (самый последний)

Цель: **не поставлять с игрой ни одного нативного файла** — ни `SDL2.dll`, ни `FNA3D.dll`,
ни `FAudio.dll`, ни `libtheorafile.dll`. Вместо них системные API: `user32`/`gdi32`, `d3d9`,
`dsound` на Windows; `libX11`/`libGL`/`libasound` на Linux. Системные `.so` — часть ОС, а не
сторонние библиотеки, поэтому это и есть «ноль зависимостей».

Побочный эффект — **совместимость с Windows XP+**, ради которой рантайм остаётся `net40`
(миграция на .NET 8 отменена: современные рантаймы XP не поддерживают вовсе).

Обоснование, замеры, таблица «что на что менять» и честная оценка стоимости — в `IDEAS.md`,
раздел «Полный отказ от сторонних нативных библиотек».

Порядок — от дешёвого к дорогому:

- [ ] **8.0. Предусловие:** игра запускается на стенде с OpenGL 2.1+. Всё, что связано с
      рендером, без этого не проверить, а писать вслепую проект не будет.
- [ ] **8.1. Убрать `libtheorafile`.** Видео игра не использует
      (`Content.Load<Video>` не вызывается), библиотека нужна только `Video.cs`.
      Минус одна зависимость и 370 КБ. Делается при любом варианте.
- [ ] **8.2. Инвентаризация API XNA** — какие типы и методы реально вызываются игрой.
      Результат в `docs/NATIVE_BACKEND.md`; это и есть объём работы, без него оценка — гадание.
- [ ] **8.3. Свой ввод** (`user32` + XInput/DirectInput) поверх существующего
      `KeyboardMouseInput`. Проверяется логированием, GPU не нужен.
- [ ] **8.4. Свой звук** (`DirectSound`/`WaveOut` / ALSA) для `SoundEffect` и музыки.
- [ ] **8.5. Свой рендер** (D3D9 / OpenGL через системный `libGL`) — только на стенде,
      со сверкой кадров с текущей версией. Самая большая часть.
- [ ] **8.6. Linux-бэкенд** (X11 + GL) — после того, как картинка совпала на Windows.

**Отменено:** упаковка чужих `.dll` в embedded resource и слияние FNA3D+FAudio+SDL2 в одну
библиотеку как *цель*. Это оставляет файлы нативных библиотек в комплекте — то, чего просили
избежать. Может пригодиться разве что как временная мера.

**DoD этапа:** папка с игрой состоит из exe, `Content/` и `Storage/` — и больше
ничего. Запускается на чистой Windows XP и новее, и на Anbernic без доустановки библиотек.

## Definition of Done

**Аудит роадмапа — самый последний шаг.** Когда все остальные пункты закрыты, `ROADMAP.md`
перечитывается построчно с одним вопросом к каждому: *какое доказательство, что это точно
сделано?* Пункт без доказательства возвращается в `[ ]` с пометкой, чего не хватает. Пункт,
закрытый «в основном», получает отдельный `[ ]` на остаток. Это записано и в `IDEAS.md`,
раздел «Самое последнее: аудит роадмапа» — чтобы список остатков был виден, а не размазан
по формулировкам «сделано, но…».

Пункт считается закрытым, когда одновременно:

1. `dotnet build` без ошибок;
2. `TerrariaXDK.exe --selftest` — 0 failed;
3. поведение описано в `README.md` или `docs/`;
4. изменение покрыто хотя бы одной проверкой в `Headless/SelfTest.cs`
   (если оно проверяемо без GPU);
5. коммит с осмысленным сообщением, автор — `Terraria Agent`.
