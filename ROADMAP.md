# ROADMAP

Порядок работ по TerrariaXDK. Критерий готовности каждого пункта — «можно проверить»,
а не «написано». Идеи и обоснования — в `IDEAS.md`.

Легенда: `[x]` готово, `[~]` в работе, `[ ]` не начато.

---

## Этап 3 — Мультиплеер без серверного EXE

- [x] `IPeerTransport` + `TcpPeer`: хост внутри процесса, фрейминг, handshake с версией
      протокола и подписью модов, roster, join/leave, relay, LAN-дискавери (UDP).
- [x] `NetworkSession` переведён на транспорт; локальные (split-screen) игроки
      замыкаются в процессе, удалённые идут по сети.
- [x] Подключение по адресу из `[Network] JoinAddress`.
- [x] Клиентское подключение: `NetworkSession.EndJoin` → `StartClientPeer` открывает TCP
      (раньше `EndJoin` не создавал транспорт вовсе — соединения не было).
- [x] Таймаут подключения (5 с), чтобы недоступный хост не вешал игру.
- [x] Отказоустойчивость: битый пакет от клиента не роняет хост/клиент (try/catch вокруг
      `CheckBytesServer`/`CheckBytesClient` и `Session.Update`).
- [x] Legacy Lidgren оставлен как fallback (`UseTcpTransport = false`).
- [x] Исправлен `AvailableNetworkSession`: свойства читали сами себя, из-за чего любой
      настоящий сервер в списке (LAN или из мастера) убивал процесс `StackOverflowException`.
- [x] Пароль хоста: проверяется до регистрации пира, клиенту приходит причина отказа.
- [x] Диагностика в игре: пинг (RTT), входящий/исходящий трафик, счётчики пакетов
      (`Terraria/Net/NetworkStats.cs`, показ в HUD при `NetMode != 0`).
- [x] Мастер-сервер: клиент публичного списка (`Terraria/Net/MasterServerClient.cs`)
      с HTTP/JSON-протоколом `GET /v1/servers`, `POST /v1/announce`, `POST /v1/remove`,
      кэшем в `Storage/Cache/servers.json`, таймаутом, backoff и жёсткой валидацией
      ответа. Публикация своего мира — `[Network] PublishToMaster` (по умолчанию off),
      объявления шлёт фоновый поток (`MasterPublisher`). Публичные серверы попадают
      в общий список вместе с LAN.
- [x] Свой минимальный JSON-парсер (`Terraria/Net/Json.cs`) — в net40 нет `System.Text.Json`.
- [x] Список серверов: LAN и мастер в одном месте, пометки `[pw]` (пароль) и
      `[mods]` (другая подпись модов, подключение всё равно откажет handshake),
      реальное число игроков/слотов.
- [x] Обновление по кнопке (`F5` / `LB`) и сохранение серверов в избранное (`F`,
      `Storage/Cache/favorites.txt`; такие видны даже когда мастер и LAN недоступны).
- [x] Автообновление списка по таймеру (20 с, `[Network] AutoRefreshSeconds`,
      выбранная строка сохраняется). Покрыто тестом `auto refresh`.
- [x] **Пинг в списке серверов**: `ServerPing` шлёт тот же `Hello` отдельным сокетом и
      мерит ответ. Отказ (пароль/моды/версия) считается живым сервером, мёртвый порт —
      «timeout», неизмеренный — пусто. Покрыто тестом `server ping`.
- [ ] Карточки серверов: версия и моды отдельной строкой (сейчас это пометки в строке).
- [x] Прямое подключение по адресу: `D` или `Right Shoulder` на экране выбора мира
      открывает ввод `host[:port]`, разрешает имя и подключается. Работает и с
      виртуальной клавиатурой.
- [x] Тест «хост + два клиента» в `--selftest` на реальных сокетах: roster, relay в обе
      стороны, уведомление о выходе. Покрыто тестом `host and two clients`.
- [x] Починена LAN-дискавери: хост слушал произвольный UDP-порт вместо
      `DiscoveryPort`, поэтому хосты в локальной сети были невидимы вообще.
- [x] `NetworkConfig.Port = 0` теперь означает «свободный порт от ОС», а
      `ActivePort` сообщает реально занятый.
- [ ] Dedicated-хост без окна (тот же транспорт, без `Main`).

      Deutsch, Italiano, Français, Español. Пять переводов лежали в `Lang.cs` всегда, но

      системных настроек было невозможно. Применяется сразу (перезаполнение всех строковых
      таблиц — это же и есть видимое доказательство, что работает), сохраняется в
      `[Display] Language`. Покрыто тестом `language`.
- [x] Зум камеры и виджеты HUD в экране **Настройки → HUD**: зум 1.00x–2.00x
      (применяется сразу, шаг 0.05, значения клампятся), сброс, часы/глубина/компас
      «всегда». Раньше `ZoomLevel` парсился через `Convert.ToSingle` (падало на мусоре)
      и нигде не применялся, а `Zoom(1f)` при каждом переходе в полноэкранный вид сбрасывал
      зум. Там же — предупреждение о хардмоде. Покрыто тестом `hud settings`.
- [x] **Правки перевода без пересборки**: `Storage/Lang/<code>.txt` читается поверх
      встроенных строк, генерируется командой `--lang-export de` (работает без окна и без
      GPU). Файл может быть частичным — удалённая строка значит «встроенный текст»;
      повторный экспорт сохраняет уже переведённое. Индекс вне диапазона, нечисловой ключ
      и неизвестная секция попадают в лог с объяснением, а пустое значение не стирает
      метку. Покрыто тестом `language overrides`. Подробности — `docs/LOCALIZATION.md`.
- [x] **Текст наших фич в переводе**: ответы читов, всех 22 команд хоста, модерации и
      `!serverconfig` собраны в `Terraria/Texts.cs` под ключами `chat.*` и переводятся через
      секцию `[Texts]` того же файла. Подстановки `{0}`-стиля (свой мини-форматтер, не
      `string.Format`: перевод — это файл, который правит игрок, и лишняя скобка не должна
      ронять игру). Покрыто тестом `feature text`. См. `docs/LOCALIZATION.md`.
- [x] **Экраны в переводе**: `Display`, `HUD`, `Mods`, `Network`, `Cheats`, бэкапы,
      переназначение клавиш, строки меню настроек, статусы, подсказки и заголовки окон
      ошибок. Названия клавиш строятся из имени действия (`MoveLeft` → `ui.key.moveleft`),
      поэтому забытое название не спрячется: оно попадёт в тест по имени действия.
      Комментарии `Settings.ini` намеренно оставлены английскими — файл читают при разборе
      проблем, и он не должен меняться от смены языка.
- [ ] Причины отказа в handshake (`Wrong password.`, `Server is full.`). Они уходят по сети
      как текст, поэтому сначала нужен код причины в протоколе: иначе клиент покажет
      строку, которую прислал сервер, на чужом языке.
- [ ] Вынос строк `Lang.cs` в файлы целиком (сейчас всё в коде, 17 000 строк) и
      TrueType-шрифты. Оверрайды закрывают правку перевода, но **не** добавление нового
      языка: `Lang` знает ровно пять вариантов через ветвления `LangOption == N`, и глифы
      запечены в атлас `Fonts/HD`, так что кириллица туда не поместится. Это отдельная
      работа по `Lang.cs` и контенту.
- [ ] Постепенное разделение `Main.cs` (ввод, рендер, сеть, звук) без «большого взрыва».
      **Сделано:** звук вынесен в `Terraria/Audio/SoundPlayer.cs` (тело перенесено
      дословно, в `Main` однострочные врапперы — ~300 вызовов не менялись), туда же
      переехали `SfxInstancePool`, `SoundManager`, `MusicEntry`. `Main.cs`: 3996 → 3771
      строк. Покрыто тестом `sound routing`.
      **Осталось:** рендер, ввод и сеть — там нужен `GraphicsDevice` или статический
      `Main`, и проверить перенос без GPU нельзя. Берём, когда появится стенд с OpenGL.
- [x] `Storage/Backups/`: датированные копии мира после сохранения, с лимитом на мир
      и минимальным интервалом (`[Backups] Keep/MinMinutes`). Включены по умолчанию.
- [x] **Восстановление из бэкапа в игре**: экран `B` на выборе мира — список копий
      выбранного мира (дата/время/размер), подтверждение перед перезаписью, текущий сейв
      сохраняется как `.prerestore`. Покрыто тестом `backup restore`.
- [x] `Storage/Cache/` используется: `servers.json` (кэш списка серверов), `favorites.txt`,

- [x] **Кэш собранных атласов — не нужен, проверено.** Атласы (`_sheetTiles`,
      `_sheetSprites`) не собираются в рантайме: это уже готовые одиночные `.xnb`
      (1.27 МБ и 1.16 МБ), которые `ContentManager` читает напрямую. Собирать нечего,
      поэтому кэшировать нечего; единственная теоретическая экономия — распаковка LZX,
      но это доли секунды против риска рассинхронизировать кэш с контентом. Пункт закрыт
      как неприменимый, а не сделанный.
- [x] Один скрипт на всю сборку: `tools/build.ps1` (build + `--selftest` + `-Pack/-Zip`
      для портативной папки).
- [x] CI: `.github/workflows/build.yml` — сборка Release с `-warnaserror` + `--selftest`
      на каждый push/PR. `--selftest` больше не требует ни `Content/`, ни нативных DLL
      (не инициализирует `FNAPlatform`), а контентные проверки без ассетов пишут `skip`
      с причиной вместо `FAIL`. Проверено на копии exe без Content и без SDL2:
      `Passed: 50  Skipped: 3  Failed: 0`. Третьим пропуском стал `world file inspector`:
      без `tutorial.wld` ему нечего разбирать, а его собственный `catch (Exception)`
      раньше превращал `skip` в `FAIL` — то есть CI краснел на чистом клоне.

- [ ] Кроссплатформенность (Linux/ARM, Anbernic): убрать `Microsoft.Win32.Registry`
      и привязки к путям Windows.
- [x] **Диагностика миров**: `WorldFileInspector` разбирает `.wld` без загрузки и говорит,
      почему мир не открылся — обрезан (с указанием байта), повреждён, слишком короткий или
      это мир ПК-версии. Экран `LOAD_FAILED` теперь показывает причину. Покрыто тестом
      `world file inspector` на настоящем `Content/Worlds/tutorial.wld`.
      См. `docs/WORLD_FORMAT.md`.
- [ ] **Конвертация миров ПК-версии.** Нужны образцы ПК-миров (минимум две версии):
      раскладка ПК гейтится по версиям полей, а без образцов реализация проверялась бы
      только против собственных представлений о формате.

## Этап 7 — Серверная админка (по мотивам `refs/TShock`)

Порядок важен: каждый пункт опирается на предыдущий. Идеи и обоснования —
в `IDEAS.md`, раздел «Из `refs/TShock`».

- [x] **7.1 Права и команды (частично).** Группы в `Storage/Config/permissions.ini`,
      права флагами, единая точка проверки `Permissions.Allows`. Хост — владелец из кода;
      удалённый игрок не может получить его права под чужим именем. Команды клиентов
      исполняются на хосте с их правами. Покрыто тестом `permissions`.
      Осталось: единый разбор `/команда аргументы` для не-хостов без чата, `help` по правам.
- [x] **7.2 (частично) Баны.** `Storage/Config/banlist.txt`, точное сравнение по имени
      или IP, проверка в handshake до регистрации пира. Пароль хоста сделан в этапе 3.
      Осталось: логин/вайтлист.
- [x] **7.3 (частично) Модерация.** Команды хоста в чате: `!kick`, `!who`, `!say`,
      `!mute`/`!unmute`, `!whisper`, `!motd`, `!rules`, `!bans`, `!unban`, `!help`.
      Мут проверяется в relay-цикле, MOTD/правила уходят при подключении. Покрыто
      тестами `host commands`, `moderation`, `ban list` и живым мут+кик в
      `host and two clients`. Осталось: `displaylogs`, единая система прав.
- [x] **7.4 Защита мира.** Право `build`, защита квадрата вокруг спавна
      (`ProtectSpawnRadius`), аварийный `DisableBuild` и **именованные регионы**
      (`Storage/Config/regions.txt`, `!region`). Проверка в приёмнике пакетов 17/20/34 до
      применения и пересылки. Покрыто тестами `world protection`, `regions` и живой
      проверкой в `host and two clients`.
- [x] **7.4 (запрет предметов).** `!additem`/`!delitem`/`!items`, `items.txt`; хост
      отклоняет синхронизацию инвентаря с запрещённым id и не пересылает её. Покрыто
      тестом `item restrictions` и живой проверкой в `host and two clients`.
- [x] **7.6 (частично) Информация.** `!stats` (игроки, трафик, аптайм) и `!world`
      (имя, размер, спавн, боссы).
- [x] **7.6 (частично) Эксплуатация.** `Storage/Config/ServerConfig.ini` — отдельный
      профиль хостинга (порт, пароль, лимит игроков, MOTD, правила, защита, публикация).
      Ключи профиля побеждают `Settings.ini`, пропущенные берутся из него; файл не
      создаётся сам, меню пишет в активный файл. Покрыто тестом `server config`.
- [ ] **7.6 (остаток) UPnP-проброс.** `refs/NATUPNPLib`, автопроброс порта при хостинге.
      Без реального роутера не проверяется.
- [ ] **7.5 Анти-чит.** Детект no-clip, абуза тайлов/жидкостей, кап урона — требует
      запущенной игры для сверки позиций, отложено до появления GPU-стенда.
- [ ] **7.5 Анти-чит.** Подключить существующий `spamCheck`, добавить детект no-clip,
      абуза тайлов/жидкости/снарядов, кап урона; права «игнорировать проверку».
- [ ] **7.6 Эксплуатация.** UPnP-проброс (`refs/NATUPNPLib`), `ServerConfig.ini`,
      автобэкапы, `stats`/`world`, `PacketBufferer`.
- [ ] **7.7 Внешнее управление.** RCON для headless-хоста, затем REST API с токеном.

**DoD этапа:** можно поднять публичный хост, выдать кому-то права модератора,
забанить нарушителя, защитить спавн и увидеть это в логе — без правки кода.

## Этап 8 — Без нативных `.dll` (самый последний)

Цель: рядом с игрой не остаётся ни `SDL2.dll`, ни `FNA3D.dll`, ни `FAudio.dll`,
ни `libtheorafile.dll`. Кастомная FNA-сборка тянет зависимости сама, одинаково на
Windows и Linux/ARM. Обоснование, замеры и варианты — в `IDEAS.md`,
раздел «Полный отказ от нативных `.dll`».

Порядок — от дешёвого к дорогому:

- [ ] **8.1. Убрать `libtheorafile`.** Видео игра не использует
      (`Content.Load<Video>` не вызывается), библиотека нужна только `Video.cs`.
      Минус одна зависимость и 370 КБ.
- [ ] **8.2. Упаковать нативные либы в embedded resource** + распаковка в
      `Storage/Cache/native/` и загрузка по полному пути до первого P/Invoke.
      Работает на текущем net40, «рядом с exe чисто».
- [ ] **8.3. Слить FNA3D + FAudio + SDL2 в одну библиотеку** под Windows.
- [ ] **8.4. Повторить для Linux/ARM** (Anbernic): `.so`, `SONAME`, `rpath $ORIGIN`.
      Здесь статическая сборка особенно важна — на прошивках handheld'ов половины
      системных библиотек нет.
- [ ] **8.5. Полный static link / NativeAOT.** Требует миграции с net40 на
      современный .NET — отдельный большой проект, делать только после 8.1–8.4.

**DoD этапа:** папка с игрой состоит из exe, `Content/` и `Storage/` — и больше
ничего. Запускается на чистой Windows и на Anbernic без доустановки библиотек.

## Definition of Done

Пункт считается закрытым, когда одновременно:

1. `dotnet build` без ошибок;
2. `TerrariaXDK.exe --selftest` — 0 failed;
3. поведение описано в `README.md` или `docs/`;
4. изменение покрыто хотя бы одной проверкой в `Headless/SelfTest.cs`
   (если оно проверяемо без GPU);
5. коммит с осмысленным сообщением, автор — `Terraria Agent`.
