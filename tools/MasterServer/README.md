# MasterServer

Мастер-сервер для TerrariaXDK: список миров, которые хостят игроки.

Нужен потому, что клиент игры (`Terraria/Net/MasterServerClient.cs`) обращается к сервису по
HTTP/JSON, а в репозитории никакого сервиса не было — адрес `play.dartpower.xyz:17777`
работал только если кто-то его поднимал. Это он.

## Запуск

```powershell
dotnet build tools\MasterServer\MasterServer.csproj
.\tools\MasterServer\bin\Debug\net40\MasterServer.exe
```

По умолчанию слушает **0.0.0.0:17777** и печатает в консоль всё, что делает:

```
TerrariaXDK master server
=========================
[12:20:46] listening on 0.0.0.0:17777
[12:20:46] ttl 120s, data master-servers.json
[12:20:47] listed   203.0.113.7:7777  'DartPower world'  2/8
[12:20:47] 203.0.113.7  POST /v1/announce  -> 200
[12:20:47] 203.0.113.7  GET /v1/servers  -> 200
[12:22:50] expired  203.0.113.7:7777  'DartPower world'  (no announce for 120s)
```

Остановка — `Ctrl+C` (сохраняет список и печатает, сколько миров было).

## Параметры

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `--port N` | `17777` | TCP-порт. `0` — взять свободный (для тестов). |
| `--ttl SECONDS` | `120` | Через сколько без announce запись выбрасывается. Хост повторяет announce каждые 45 с. |
| `--data FILE` | `master-servers.json` рядом с exe | Куда сохранять список. |
| `--selftest` | — | Проверить протокол на временном экземпляре и выйти. |

## Проверка, что работает

```powershell
# в браузере: живая страница со списком, обновляется раз в 5 секунд
start http://localhost:17777/

# или из консоли
curl http://localhost:17777/health
# {"ok":true,"servers":0,"ttlSeconds":120,"announces":0,"uptimeSeconds":12}
```

`--selftest` проверяет контракт целиком: пустой список, announce, повторный announce обновляет
запись (а не дублирует), пустой `host` подменяется адресом соединения, `remove`, отказы
(`port 0`, битый JSON, неверный метод, неизвестный путь), `/health`, html-страница и
истечение по TTL. Сейчас: **16 проверок**.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/servers` | `{"servers":[{...}]}` — то, что читает игра |
| `POST` | `/v1/announce` | добавить/обновить мир по `host:port` |
| `POST` | `/v1/remove` | убрать мир (`{"host":..,"port":..}`) |
| `GET` | `/health` | счётчики для мониторинга |
| `GET` | `/` | страница для человека |

Формат полей — `Terraria/Net/MasterServerClient.cs` и `docs/MULTIPLAYER.md`, раздел 7.

## Две вещи, которые легко сломать

**Порт.** Игра хостит на **7777**, мастер слушает на **17777**. Перепутать их — самый частый
способ получить пустой список при живом сервере; оба значения закреплены проверками
(`master endpoints` в self-test игры и `--selftest` здесь).

**Пустой `host`.** Хост за NAT не знает своего публичного адреса, поэтому присылает пустую
строку, а мастер подставляет адрес, с которого пришёл запрос. Если это сломать, все миры
окажутся с адресом `:0` и в игре будут недоступны.

## Чего он не делает

- не проверяет, что мир действительно доступен по указанному адресу (это делал бы пинг, но
  пинг уже есть у клиента и он честнее: видит то же, что увидит игрок);
- не хранит историю, баны и статистику — это список миров на две минуты;
- не умеет HTTPS: клиент ходит по HTTP/1.1, и добавлять TLS ради локального сервиса
  значило бы тащить зависимость.

## Файрвол

Для приёма соединений из интернета нужно открыть TCP 17777 (от администратора):

```powershell
New-NetFirewallRule -DisplayName "TerrariaXDK master server (TCP 17777)" `
  -Direction Inbound -Protocol TCP -LocalPort 17777 -Action Allow -Profile Any
```
