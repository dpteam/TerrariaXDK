# MasterServer

Мастер-сервер для TerrariaXDK: список миров, которые хостят игроки.

Нужен потому, что клиент игры (`Terraria/Net/MasterServerClient.cs`) обращается к сервису по
HTTP/JSON, а в репозитории никакого сервиса не было — адрес `play.dartpower.xyz:17777`
работал только если кто-то его поднимал. Это он.

## Запуск

```powershell
dotnet build tools\MasterServer\MasterServer.csproj
.\tools\MasterServer\bin\Debug\net40\MasterServer.exe
```

По умолчанию слушает **0.0.0.0:17777** и печатает в консоль всё, что делает:

```
TerrariaXDK master server
=========================
[12:20:46] listening on 0.0.0.0:17777
[12:20:46] ttl 120s, data master-servers.json
[12:20:46] relay listening on 0.0.0.0:17778 (max 64 room(s), 512 KiB/s each)
[12:20:47] relay    room 9f2c41ab7d0e5a13 opened (1 of 64)
[12:20:47] listed   203.0.113.7:7777  'DartPower world'  2/8
[12:20:47] 203.0.113.7  POST /v1/announce  -> 200
[12:20:47] 203.0.113.7  GET /v1/servers  -> 200
[12:22:50] expired  203.0.113.7:7777  'DartPower world'  (no announce for 120s)
```

Остановка — `Ctrl+C` (сохраняет список и печатает, сколько миров было).

## Параметры

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `--port N` | `17777` | TCP-порт. `0` — взять свободный (для тестов). |
| `--relay-port N` | `17778` | TCP-порт релея. `0` — взять свободный. |
| `--no-relay` | — | Не запускать релей: мастер только перечисляет миры. |
| `--ttl SECONDS` | `120` | Через сколько без announce запись выбрасывается. Хост повторяет announce каждые 45 с. |
| `--data FILE` | `master-servers.json` рядом с exe | Куда сохранять список. |
| `--selftest` | — | Проверить протокол на временном экземпляре и выйти. |

## Проверка, что работает

```powershell
# в браузере: живая страница со списком, обновляется раз в 5 секунд
start http://localhost:17777/

# или из консоли
curl http://localhost:17777/health
# {"ok":true,"servers":0,"ttlSeconds":120,"announces":0,"uptimeSeconds":12}
```

`--selftest` проверяет контракт целиком: пустой список, announce, повторный announce обновляет
запись (а не дублирует), пустой `host` подменяется адресом соединения, `remove`, отказы
(`port 0`, битый JSON, неверный метод, неизвестный путь), `/health`, html-страница,
истечение по TTL, статистику достижений, рейтинги и релей. Сейчас: **45 проверок**.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/servers` | `{"servers":[{...}]}` — то, что читает игра |
| `POST` | `/v1/announce` | добавить/обновить мир по `host:port` |
| `POST` | `/v1/remove` | убрать мир (`{"host":..,"port":..}`) |
| `POST` | `/v1/stats` | присланный игроком прогресс: достижения и счётчики |
| `GET` | `/v1/achievements` | `{"totalPlayers":N,"counts":[..]}` — сколько игроков получили каждое |
| `GET` | `/v1/leaderboard` | `?stats=A,B&limit=50` → рейтинг по сумме колонок |
| `GET` | `/health` | счётчики для мониторинга |
| `GET` | `/` | страница для человека |

Плюс **релей** на отдельном порту (по умолчанию 17778): `HOST`, `JOIN`, `POLL`, `ACCEPT` —
см. раздел «Релей» ниже.

Формат полей — `Terraria/Net/MasterServerClient.cs` и `docs/MULTIPLAYER.md`, раздел 7.

## Релей (порт 17778)

Нужен тем, кого нельзя достать снаружи: CGNAT, мобильный интернет, гостевой Wi-Fi. И хост, и
клиент подключаются к релею исходящими соединениями, релей перекачивает байты и не разбирает
их — handshake игры остаётся сквозным.

```
HOST <token>      -> OK <roomId>      сокет становится «присутствием» комнаты
JOIN <roomId>     -> WAIT             сокет ждёт хоста
POLL <token>      -> JOIN <ticket>... END
ACCEPT <ticket>   -> (релей склеивает сокет с ожидающим клиентом)
```

Лимиты: 64 комнаты, 16 ожидающих на комнату, 30 секунд на тикет, 512 КиБ/с на комнату.
Токен — 128 бит, тикет одноразовый: иначе это открытый прокси.

Выключить: `--no-relay` или `--relay-port 0` не подходит (0 = свободный порт), поэтому именно
`--no-relay`. Свой порт: `--relay-port 18000`.

`--selftest` проверяет и его: комната открывается и закрывается вместе с хостом, клиент
паркуется, тикет выдаётся один раз, чужой токен не пускается, байты идут в обе стороны.

## Статистика: что именно хранится

`POST /v1/stats` принимает `{"gamertag","achievements":[индексы],"stats":{"Имя":число}}`.
Достижения складываются объединением (полученное не отбирается), счётчики берутся
**максимумом** — счётчик не убывает, поэтому меньшее значение означает устаревший отчёт,
а не исправление. Данные лежат в `*.stats.json` рядом с файлом списка миров: список живёт
две минуты, статистика — всегда.

Рейтинг — по сумме запрошенных колонок, ровно как консольная версия считала `Rating`
записи в Xbox Live. Имена статистик (`AirTravel`), а не индексы: индекс — позиция в enum,
который в порте уже менялся, и колонка не должна съезжать.

Числа **присланные**, а не проверенные: модифицированный клиент может соврать, и отличить
это без серверного геймплея нельзя. Поэтому в игре написано «Reported by N of M players».

## Две вещи, которые легко сломать

**Порт.** Игра хостит на **7777**, мастер слушает на **17777**. Перепутать их — самый частый
способ получить пустой список при живом сервере; оба значения закреплены проверками
(`master endpoints` в self-test игры и `--selftest` здесь).

**Пустой `host`.** Хост за NAT не знает своего публичного адреса, поэтому присылает пустую
строку, а мастер подставляет адрес, с которого пришёл запрос. Если это сломать, все миры
окажутся с адресом `:0` и в игре будут недоступны.

## Чего он не делает

- не проверяет, что мир действительно доступен по указанному адресу (это делал бы пинг, но
  пинг уже есть у клиента и он честнее: видит то же, что увидит игрок);
- не проверяет присланную статистику: это числа от клиента, а не измеренные сервером;
- не хранит баны и историю — список миров живёт две минуты;
- не умеет HTTPS: клиент ходит по HTTP/1.1, и добавлять TLS ради локального сервиса
  значило бы тащить зависимость.

## Файрвол

Для приёма соединений из интернета нужно открыть **оба** порта — список миров и релей. Одной
командой из повышенной PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File ..\firewall.ps1
```

Или вручную:

```powershell
New-NetFirewallRule -DisplayName "TerrariaXDK master server (TCP 17777)" `
  -Direction Inbound -Protocol TCP -LocalPort 17777 -Action Allow -Profile Any
New-NetFirewallRule -DisplayName "TerrariaXDK relay (TCP 17778)" `
  -Direction Inbound -Protocol TCP -LocalPort 17778 -Action Allow -Profile Any
```

Забыть второй порт легко, и это выглядит обманчиво: список миров работает, а вход в игру через
релей даёт `timeout`. Windows по умолчанию блокирует входящие на всех профилях, поэтому
«порт не отвечает» — это чаще правило фаервола, чем проброс.

Проверять надо **снаружи** (не с этой же машины): изнутри проброс виден только если роутер
умеет hairpin. Быстрая проверка — любой внешний чекер TCP, например
`https://check-host.net/check-tcp?host=play.dartpower.xyz:17778`.
