# Текстуры без пересборки

Игра грузит только `.xnb` — скомпилированные файлы контент-пайплайна. Чтобы заменить
текстуру, раньше нужно было пересобрать её инструментами MonoGame на Windows-машине.
Теперь достаточно положить PNG в `Storage/Textures/`.

---

## Как заменить текстуру

Путь зеркалит дерево контента, расширение `.xnb` меняется на `.png`:

| В игре | Файл-замена |
|---|---|
| `Content/Images/_sheetTiles.xnb` | `Storage/Textures/Images/_sheetTiles.png` |
| `Content/UI/ProgressBar.xnb` | `Storage/Textures/UI/ProgressBar.png` |
| `Content/Images/Background_5.xnb` | `Storage/Textures/Images/Background_5.png` |

Папку `Content/` трогать нельзя: игра считает её только для чтения, и обновление игры
затрёт правку. `Storage/Textures/` — ваша, там же лежит `readme.txt` с этим правилом.

Перезапуск игры подхватывает изменения. В лог пишется строка на каждый загруженный оверрайд:

```
INFO  | Textures | override Images/_sheetTiles.png (2048x2048 RGBA)
```

## Что поддерживается

| Свойство PNG | Поддержка |
|---|---|
| Типы цвета: серый, RGB, палитра, серый+альфа, RGBA | да |
| Битность: 1, 2, 4, 8, 16 | да (всё приводится к 8-битному RGBA) |
| Прозрачность `tRNS` (включая палитровую и «этот цвет прозрачный») | да |
| Все пять фильтров строк (None/Sub/Up/Average/Paeth) | да |
| Несколько `IDAT` | да |
| **Adam7 interlacing** | **нет** — отказ с явной ошибкой |
| `.dds`, `.jpg` | нет — сообщение в лог с предложением сохранить в PNG |

Интерлейсинг не поддержан осознанно: ни одна текстура Terraria его не использует, а
молчаливое «декодировали в шум» выглядело бы как испорченный арт, а не как неподдерживаемый
формат. Поэтому файл с интерлейсингом **не** загружается, а в лог пишется причина.

---

## Что будет при ошибке

Правило одно: **сломанная текстура не должна превращаться в сломанную игру**.

| Проблема | Поведение |
|---|---|
| Файла нет | штатное поведение: грузится `.xnb`, в лог ничего не пишется |
| Файл не читается | предупреждение, грузится `.xnb` |
| Файл не PNG / битый / обрезанный | предупреждение с причиной, грузится `.xnb` |
| Файл интерлейсенный | предупреждение «Adam7 interlacing is not supported», грузится `.xnb` |
| Лежит `.dds` вместо `.png` | предупреждение «save it as .png», грузится `.xnb` |
| Файл огромный (больше 16 Мп) | предупреждение, грузится `.xnb` |
| Текстура не загрузилась в GPU | предупреждение, грузится `.xnb` |

Пример строки в `Storage/Logs/terraria-debug.log`:

```
WARN  | Textures | _sheetTiles.png: compressed image data is corrupt or truncated:
        expected 16777216 bytes, got 1048576 - using the built-in texture
```

## Альфа-канал: почему RGB умножается на альфу

PNG хранит **прямую** альфу: цвет пикселя не зависит от его прозрачности. Контент-пайплайн
XNA (и `SpriteBatch` с его блендингом по умолчанию) работает с **премультиплицированной**:
`RGB * A`. Если отдать прямую альфу, все мягкие края и полупрозрачные пиксели становятся
светлее — это выглядит как ошибка цветового пространства, а не как ошибка загрузки.

Поэтому при конверсии RGB умножается на альфу (с округлением). Полностью прозрачный пиксель
обнуляется целиком, чтобы билинейная фильтрация не вытаскивала цвет из «ничего».

## Как это устроено

| Файл | Что делает |
|---|---|
| `Terraria/Textures/PngDecoder.cs` | чтение PNG: чанки, zlib, фильтры, типы цвета |
| `Terraria/Textures/ImageData.cs` | результат: 8-битный RGBA, один формат для всех источников |
| `Terraria/Textures/TextureOverrides.cs` | какой файл заменяет какой ассет, ошибки, список установленных |
| `Terraria/Textures/TextureContentManager.cs` | `ContentManager`, который вклинивается в `Load<Texture2D>` |

`TextureContentManager` подменяет `Game.Content` в конструкторе `Main`, поэтому **все**
вызовы `Content.Load<Texture2D>(...)` проходят через него — включая те, что собирают имя из
кусков (`"Images/Background_" + index`). Их 26, и добавлять ещё один список «какие текстуры
поддерживают замену» не нужно.

Всё, кроме `Texture2D`, идёт в базовый `ContentManager` без изменений: это один хук перед
пайплайном, а не его переписывание.

### Почему свой декодер, а не `System.Drawing`

`System.Drawing` — это GDI+, то есть Windows-only (см. `docs/PORTABILITY.md`), и вызвать его
из headless-теста без рабочего стола нельзя. Свой декодер — примерно 450 строк, зато
работает везде и проверяется без видеокарты.

## Проверки

Тест `png decoder` сверяет **написанные руками байты** с ожидаемыми пикселями:

- все пять фильтров на картинке 3x2 с посчитанными вручную значениями. Например, для
  `Up` вторая строка `30,40` кодируется как `20,20` (`30-10`, `40-20`) — при ошибке в знаке
  получилось бы `-10`;
- типы цвета: RGBA (каналы не перепутаны), палитра с `tRNS`, **1-битная палитра** (первый
  пиксель — в старшем бите), серый+альфа, 16-битные сэмплы (старший байт);
- отказы называют причину: неизвестный фильтр, битые данные, нет `IEND`, обрезанный чанк,
  интерлейсинг, несуществующий тип цвета, недопустимая битность, превышение размера;
- премультипликация: `200,100,50,128` → `100,50,25,128`, полностью прозрачный пиксель → `0`.

Тест `texture overrides`: отсутствующий файл — не ошибка; настоящий оверрайд побеждает и
попадает в список установленных; битый файл **не** бросает исключение и объясняет, что
используется встроенная текстура; `.dds` назван по имени.

Дополнительно оба теста прогоняют декодер по **39 настоящим PNG** из `_RemovedContent/`
(они вне git, поэтому в чистом клоне проверка пишет `skip`). Это единственная доступная
«земля»: файлы писали настоящие кодировщики, и ошибка в Paeth или в порядке битов даёт шум —
тысячи разных цветов там, где в арте десятки. Тест это ловит.
