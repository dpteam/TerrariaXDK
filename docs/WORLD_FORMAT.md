# Формат миров `.wld`

Мир — один бинарный файл. Этот документ описывает **точно тот формат, который читает
игра**, и заодно объясняет, почему миры из ПК-версии не открываются.

Источник истины — код: `WorldGen.loadWorld` → `loadOldWorld` (версии ≤46) или
`loadNewWorld` (47–49). Проверка соответствия — `tools`-уровня: `WorldFileInspector`
(`Terraria/World/WorldFileInspector.cs`) проходит файл тем же порядком полей и сверяется с
настоящим миром `Content/Worlds/tutorial.wld` в `--selftest`.

---

## Две версии формата

| Версия | Кто пишет | Чем отличается |
|---|---|---|
| ≤ 46 | старые сборки, `Content/Worlds/tutorial.wld` (у него 39) | `int32` в заголовке, булевы флаги «есть стена / есть жидкость», `int16` счётчик повторов, тип NPC строкой, футер с именем мира |
| 47–49 | текущая сборка (`NewWorldDataVersion = 49`) | CRC32, `int16` в заголовке, плотная байтовая раскладка тайла, RLE с продолжением |

Футер старого формата — это ещё и проверка целостности: он повторяет имя мира и его id, и
загрузчик падает, если они не совпали. Именно поэтому обрезанный старый сейв почти всегда
диагностируется как «повреждён», а не как «загрузился наполовину».

## Заголовок (версии 47–49)

```
int32   version            // 47..49
uint32  crc32              // по байтам с 8-го до конца
string  name               // 7-битная длина + UTF-8
int32   worldID
int32   worldTimestamp     // только при version >= 48
int32   rightWorld         // в пикселях
int16   bottomWorld
int16   maxTilesY
int16   maxTilesX
int16   spawnTileX
int16   spawnTileY
int16   worldSurface
int16   rockLayer
single  worldTime
bool    dayTime
byte    moonPhase
bool    isBloodMoon
int16   dungeonX
int16   dungeonY
bool x11                   // боссы, спасённые NPC, метеор
byte    shadowOrbCount
int32   altarCount
bool    inHardMode
byte    invasionDelay
int16   invasionSize
byte    invasionType
single  invasionX
```

## Секция тайлов (47–49)

Идёт **по колонкам**: для каждого `x` от 0 до `maxTilesX-1` читаются тайлы сверху вниз,
пока счётчик строк не достигнет `maxTilesY`.

Одна запись:

```
byte  isActive
      если != 0:
        byte  type            // 127 = «неактивен», тайл остаётся пустым
        если type — frame-important (см. ниже):
          int16 frameX
          int16 frameY
byte  wallType
byte  liquid
      если liquid > 0:
        bool isLava
byte  flags
byte  repeat               // RLE
      если (repeat & 0x80) != 0:
        repeat = (repeat & 0x7F) | (nextByte << 7)
```

Запись покрывает **`repeat + 1`** тайлов: базовый плюс повторы. Это самая частая ошибка
при разборе — забыть `+1` даёт сдвиг на один тайл на каждую RLE-запись, файл «читается», но
структура уезжает, и на настоящем мире разбор доходит до мусора ближе к концу.

«Frame-important» — это `Main.TileFrameImportant[type]`, заполняемый из
`EntityID.FrameImportantTiles` (81 тип: факелы, деревья, сундуки, двери и т.п.). Для таких
тайлов в файле лежат ещё 4 байта кадров; для остальных — нет. Таблица обязательна: без неё
длину записи не определить.

## После тайлов (47–49)

```
1000 x bool hasChest
        int16 x, int16 y
        20 x (int16 stack; если > 0: int16 itemId, byte prefix)
1000 x bool hasSign
        // для version >= 49:
        int16 x, int16 y, UserString text
        // для version <= 48:
        string text, int16 x, int16 y
bool hasNpc                             // и далее, пока true:
        byte type, single x, single y, bool homeless, int16 homeX, int16 homeY
10 x string                             // имена NPC (гид, торговец, ...)
```

`UserString` — не обычная строка: сначала байт флагов (бит 0 — проверено, бит 1 —
цензурировано), и только если цензуры нет, дальше идёт строка. Наивный читатель возьмёт
байт флагов за длину.

## Старый формат (≤46) — чем отличается

Набор данных тот же, раскладка другая:

- в заголовке `int32` вместо `int16` (и границы читаются парами: right, right, bottom,
  bottom — так в декомпиляте);
- уровень поверхности и скального слоя — `double`, время мира — `double`;
- у тайла: `bool hasWall` перед `wallType`, `bool hasLiquid` перед `liquid`, `bool isLava`
  только если жидкость есть;
- версия < 46 — вместо байта флагов отдельный `bool` для провода;
- RLE — `int16` без упаковки;
- сундуки — `int32` координаты и `int32` id предмета; знаки — строка + `int32` координаты;
- тип NPC — строка, а дома — `int32`;
- в конце — десять имён NPC и **футер**: `bool`, строка имени мира, `int32` id.

## ПК-версия: почему не открывается

Первое поле — тоже `int32 version`, но нумерация другая: у ПК-версий это 87, 194, 279 и
т.д. То есть файл легко **опознать**, и `WorldFileInspector` именно это и делает: говорит
«это мир ПК-версии N», а не «не удалось загрузить».

Дальше начинаются настоящие препятствия, из-за которых конвертация не сделана:

1. **Раскладка зависит от версии.** ПК-формат добавляет поля по мере выхода версий (режим
   игры, Drunk World, NPC-«bestiary», tile entities, зональные данные). Читать его — значит
   держать таблицу «с какой версии какое поле появилось», иначе поля съезжают.
2. **Другие системы.** У ПК-версии иная нумерация тайлов и стен, другие кадры (frame-important
   иначе), другая таблица предметов. Даже прочитав тайлы, нельзя один в один перенести id:
   консольная сборка — это отдельная линейка контента.
3. **Не на чем проверить.** В репозитории нет ни одного ПК-мира, а без образцов любая
   реализация проверяется только против собственных представлений о формате — то есть
   выглядит проверенной, не будучи ею.

Поэтому честный результат: **мир ПК-версии опознаётся и объясняется**, но не загружается.
Если появятся образцы (хотя бы один мир ПК 1.1.x и один 1.2.x), первым шагом будет
конвертер «ПК → консоль» с отчётом о том, что перенести нельзя, а не молчаливая подмена id.

## Что проверяется автоматически

`--selftest`, проверка `world file inspector`:

- настоящий мир `Content/Worlds/tutorial.wld` разбирается целиком и **ровно до последнего
  байта** (`StoppedAt == Length`) — это ловит любую ошибку в размерах полей;
- количество тайлов совпадает с `maxTilesX * maxTilesY`;
- обрезанная копия того же файла даёт «save is truncated» с указанием байта, а не тишину;
- файл с версией 279 опознаётся как ПК-мир, а не как повреждённый;
- пустой и шестибайтовый файлы — «не мир», а не «мир с ошибкой».

Без `Content/` проверка пропускается (`skip`), а не падает: см. `README.md`, раздел про
self-test без ассетов.
